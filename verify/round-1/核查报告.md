### P3【中】管理台登录凭据浏览器无法保存（bug 验证：真实 bug）
- **根因（主导）**：TLS 证书 SAN 仅 `IP:10.10.0.1`，日常入口 `https://127.0.0.1:8444` 永久证书不匹配（自签也未信任）→ 用户手动绕过证书错误 → Chromium 既定策略禁用密码保存气泡。10-02 只修了 DOM 层（Login.vue:61-70 要素齐全），未触及证书层。
- **修正（三方一致）**：① 光加 SAN 不够，必须**同时导入信任 CA**（Chromium 拦任意证书错误）；② TLS 由 **web/nginx 容器**终止（docker-compose.prod.yml:11、prod-nginx.conf:7），不是 api 容器（初稿写错）；③ 证书修好后**可能仍不弹**（fetch 提交无导航+两段式 TOTP 登录是第二瓶颈），终验口径=绿锁+实测弹保存，若不弹再做提交层改造（含 TOTP 框补 autocomplete="one-time-code"）。
- **修复步骤**：重签证书 SAN=`IP:127.0.0.1, IP:10.10.0.1, DNS:localhost` → **先把现网 127.0.0.1:8443 的端口映射固化进 compose（当前是宿主机手工漂移，直接重建 web 容器会丢掉 8444 隧道入口——10-03 出过同类事故）** → 替换 nginx 证书并重启 web 容器（管理台闪断 30-60s，agent 心跳自动重试不受影响）→ 给你 .crt 导入 Windows"受信任的根证书颁发机构"（一次性）→ 浏览器验收。
- 阻断：是（你本轮明确要求处理）。

### P6【中】路由器隧道密钥无 command= 限制（Codex 新发现，源码级）
`setup-mgmt-tunnel.sh:84` 生成的授权行只有 no-pty+转发白名单。**no-pty 不禁止无终端命令执行**——任一路由器被入侵、私钥（/etc/routermgmt/id_dropbear_mgmt）泄露，即等于拿到四台 VPS 的 root shell。修复需专项设计（command= wrapper 与 -N 转发的兼容性要灰度验证），本轮只登记不强推。

### P7【低-中】discovery/watchdog 把 HTTP 错误页当健康（Codex）
`mgmt-port-discovery.sh:16`、`tunnel-watchdog.sh:9` 的 curl 无 `--fail`——401/502 也算"活着"。修复一行加 `-f`。同类：hy2 客户端模板固定 `skip-cert-verify: true`（template.go:106，客户端不验证服务端身份）；旧 `setup-mgmt-tunnel.sh` 重跑会把配置降级覆盖回单端点 DO 默认值（键名 VPS_SSH_PORT 与 v3 的 VPS_PORT 不兼容）——建议给旧脚本加防呆头注释。
