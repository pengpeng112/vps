## 2. 目标模式（已隔离验证）

每台路由器在 DO 建**独立账户**（`rtr-ath` / `rtr-snr1`），authorized_keys 单行：
`restrict,port-forwarding,permitlisten="127.0.0.1:18222",permitopen="10.10.0.1:8443"`（SN-R1 对应 13222）
账户 `usermod -p '*'`（禁密码、不锁户）+ shell=/usr/sbin/nologin；sshd 无需改（AllowTcpForwarding 已允许）。

## 3. 隔离验证证据（`isolated_validate.py`，本地 Docker alpine openssh，非生产）

| 用例 | 结果 |
|---|---|
| -N -R 到 permitlisten 允许口 | ✓ 转发建立 |
| -N -R 到未授权监听口（13222） | ✓ sshd 拒绝，ExitOnForwardFailure 进程退出 |
| 请求 shell | ✓ 拒绝（restrict+nologin 双保险） |
| -L 穿透到 permitopen 允许口 | ✓ 成功 |
| -L 穿透到未授权口 | ✓ ConnectionReset（administratively prohibited） |

**实操教训（写入生产步骤）**：① alpine/ubuntu `adduser -D` 产生锁定账户（shadow `!`）会拒登，必须 `usermod -p '*'`；② `.ssh` 属主错误会被 StrictModes 静默拒绝；③ permitopen 在**连接期**拒绝（验收必须穿透测试，不能只看本地监听）；④ 隧道非正常断开会在服务端留孤儿监听口导致下次绑定失败（PC 跳板 09-26 历史与 DO repair 机制均与此有关）。
