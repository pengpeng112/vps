### 下午 ~13:20—14:10（吞吐深挖，定案"流级不稳定"）
| 测试项 | 结果 |
|---|---|
| 隧道(hy2)→CloudFront/CF 8MB | 35 / 38 / 46 / 13.7 KB/s（四轮全死） |
| 隧道(vless)→CF 8MB | 0B/5s、11KB/s（死亡） |
| 路由器直连 TX:80 明文 8MB | 21—26Mbps（好窗口）|
| **同秒三条直连流对照** | **11.5KB/s → 2.19MB/s → 4KB/s（决定性证据）** |
| 4 并发下载 | 一条流吃满（2MB/s），其余 0.5—26KB/s（互相饿死） |
| TX 机房本机出口 | →dl.google 166MB/s、→CF 110MB/s（53—74MB/s 复测，机房侧无瓶颈） |
| DNS/POP 排除 | 223.5.5.5 / 8.8.8.8 / 1.1.1.1 解析 CF 同 IP，排除"解析到差节点" |

结论：客户联通线对国际方向存在**流级策略性压制**（与协议 TCP/QUIC、端口、加密无关），新流随机获得"满速 17—26Mbps"或"死流 <50KB/s"。网页=多条短流多数成功（能开+偶卡）；视频=单条长流掷中死流即永久卡（用户"手机打不开"的机理）。**属线路物理品质，不可配置修复。**

## 四、当日结论与未决项

**结论**
1. 客户体验问题的根源=客户接入线品质（广电不可用→换联通家宽后"流级不稳"），与路由器配置、VPS、协议均无关（均有对照实验排除）。
2. hy2 上线是正确优化（小请求提速 4—6 倍，好窗口吞吐足够 4K），但救不了坏窗口。
3. 结构性出路：精品线路（回程三网优化，去程需买后实测）或客户更换上联运营商；公司线证明"好的联通路径"体验完全不同。

**未决/待观察**
- 客户联通线晚高峰表现未采样（今日全部为日间数据）
- 电信/移动/广电视角无观测点（R4 回归后可补广电解）
- 精品线路（搬瓦工/六六云）买后需跑 7 天 netprobe 曲线（流程已固化，见《精品线路选型论证-20260930》）
