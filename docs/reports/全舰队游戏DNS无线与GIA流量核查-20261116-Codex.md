# 全舰队游戏 DNS、无线与 GIA 流量核查

日期：2026-11-16；执行者：Codex；主体采样约 12:08—12:21，参考脚本只读检查随后补验，Asia/Shanghai。

本轮为只读核查与方案交付，未给其他设备改 DNS、无线、节点或限速，未部署后端、未重启服务。R9 先前修复单独记录且仍有效。

## 结论

1. **10 台在线设备均已远程实登并验证管理 health=200。除已修好的 R9，其他 9 台都存在相同配置缺陷：LOL 域名返回 fake-ip，透明代理没有对应 UDP 接管。** 这是配置风险的实证，不等于证明这九处现场当前都有用户在玩游戏或都正在报错。
2. **“全舰队已经弃用 GIA”不成立。** 8 台 SN 的普通 PROXY 为 BWG，但视频组 US-MEDIA 仍经 NODE-PICK 选 GIA。GL 普通代理和视频组都仍选 GIA，且实际出口回显为 GIA。雅典娜普通代理在 BWG，没有 US-MEDIA/AIRPORT 组。
3. 无线不能用累计 CRC 或整个接口的帧错误比例判定用户丢包；已关闭的无线也能有驱动接收统计增长。需要区分开启状态、关联客户端、实际信道与业务复现，不能批量换同一信道。
4. **现有限速字段没有任何设备启用；其实现也不足以覆盖当前出口栈。** 仅匹配 policy.vps_host 的 TCP 443，遗漏 BWG-HY2、GIA-HY2、CF2053、机场动态端点；任务 ok 也不能证明内核限速成功。
5. 流量交接混用了 GB/GiB、30 天/本月和服务器网卡/客户端负载口径。现有按活跃连接估算的数据不足以追溯谁耗掉了缺失流量，不能按连接次数或历史十月下载量给设备定责。

### 统计缺陷比交接描述更具体

`mgmt/agent/routermgmt-agent.sh:collect_metrics` 每次把 **当前仍活跃、chains[0] 非 DIRECT 的连接生命周期 download/upload 求和**。这不是进程自启动以来的持久累计计数。

因此同一 proxy_counter_epoch 内频繁下降是正常的连接关闭现象。11 月 R9 有 90863 对有效样本，其中 49751 对发生至少一个方向下降；R6 为 15744 / 8025。后台仅加正差值，会丢失采样间结束连接的流量，也会把连接关闭抵消的新流量漏掉；按重启 epoch 修补不能解决此问题。

源码默认心跳 60 秒、任务轮询 10 秒；不能把 metrics、connlog 两者一律写成 5 分钟采样。connlog 本身只记录下行、≥1MiB 增量、轮询间短连接仍丢失，且代码没有排除 DIRECT，**不能拿它直接执行国外配额封禁**。

`exit_node` 是一次出口探测对应的 PROXY 选择，不能代表同一时刻所有业务连接，尤其不能用它把仍经 US-MEDIA/GIA 的流量算成 BWG。

## GIA 服务器实测

12:12 读取 vnstat JSON，数据库最近更新时间 12:10：

- eth0 11 月：rx **423089084375** 字节，tx **425764849678** 字节。
- 合计 **848853934053 字节 = 848.854GB = 790.557GiB**。
- 11-04 单日 **135.908GiB**，是本月明显高峰；11-01—06 合计 **415.266GiB，占本月 52.53%**。交接只列 11-07 之后，会漏掉这一段主要消耗。
- vnstat 数据库建立于 **10-31**，不是交接所写 10-30；采集器建立时间不是供应商账单周期的证据。
- 原受控套餐档案写 **820GB**；交接写 **828GB**。本轮没有供应商面板证据确认额度单位、入站/出站计费方式或重置日期。
- 若供应商确实按网卡双向合计计费，代理负载通常在同一公网网卡进一次、出一次，服务器总量约为用户代理负载的两倍加开销。不能直接将“828÷30=27.6”当作用户负载日预算。
- vnstat 是网卡计量源，**不是供应商结算账单**；不能从它单独证明“95% 已触发某阈值”或保证 12-01 自动恢复。

服务器 s-box、s-box-ws、vnstat 运行中；HY2 UDP34568 也监听。当前 TCP443 的 sing-box 配置没有开启 clash_api；不是已有一个可直接查询的持久按用户计量接口。

## 现有限速/告警不能直接拿来执行

- 本轮 DB 所有设备 `vps_limit_kbps=0`。部分有 `traffic_alert_hourly_mb=2048`，R5/GL 等为 0。
- `traffic_analysis.go` 小时接口读 **WAN rx/tx**；小时告警读 **WAN 下行**，阈值比较乘 1e6；接口展示却除 1048576，单位也需统一。它不是国外专用告警。
- `apply_vps_qos*` 只匹配一个 vps_host 的 TCP443；policy 的 host 来自 current_node_id，可能还停留旧节点，与运行时钉选、视频组不一致。
- 该实现为丢包型限速，不是平滑排队；节点协议换 HY2/CF/机场会绕过，增加节点还可能放大总额。
- `apply_policy_fields` 没有严格检查 QoS 命令成功就继续写 policy.fp；任务会回 ok。不能把 UI 值/任务 ok 当作限速实测。
- 限速任务还会重新落其他 policy，包括重启计划、代理模式和访问控制，不能当作只有一条无副作用 tc 命令。
