## 对用户方案的结论

**方向可行，适合作为 UDP 协议备用；“纯增量、零风险、所有功能不受影响”不成立。**

Hysteria2 把 TCP/UDP 代理流量承载在 QUIC/UDP 上，因此若故障确实仅限目标 TCP 路径，它可能提供有效备援。端口 34567 没有特殊抗封能力，也不能由 ICMP 或其他 UDP 应用可用推断 HY2 能通过。

UDP/QUIC 也可能被识别、限速或阻断。Hysteria 官方支持在特定 QUIC/HTTP3 阻断情形下采用 Salamander 等混淆，但不承诺能穿过所有 UDP 阻断。2025 年公开研究已证实 QUIC/SNI 相关 UDP 阻断机制；该研究不证明本次事件的原因或当前全国范围。

独立端口能避免监听端口直接冲突，不能消除共享 CPU/内存/带宽、系统参数、防火墙、配置发布及证书错误的影响。向 mihomo 增加成员需要正确生成、下发、验签、加载；运行中已有连接也不保证跨协议自动无缝迁移。

## 建议的实施顺序（尚未执行）

1. 保持广州 SSH 与现有管理路径，先核对所有依赖和回退文件。先解决 R4 的媒体空组及后端旧模板覆盖问题，避免新节点绑定时把旧问题再次下发。
2. **优先在 BWG 试 UDP**：它的 TCP 出口已失效，先在这里验证第二运输协议，不首先改动当前唯一工作的 GIA 服务器。部署前仍须有独立可用的服务器管理入口。
3. BWG 使用独立实例/配置/UDP 端口；不要重启现有 VLESS 或 SSH，不执行会重置整体防火墙的安装脚本。明确云安全组及主机仅增加所需 UDP 规则，留存原规则。
4. 先在现场电脑或有资源余量的独立临时客户端试验 HY2，不改运行中的生产 mihomo。验证真实鉴权、TLS、HTTPS 出口、丢包/时延与持续小流量；UDP 端口扫描的 open|filtered 或一次 400 不是协议验收。
5. 客户端与服务端匹配 obfs 配置。优先正规证书/SNI 或受控证书固定，不把 `skip-cert-verify: true` 当成长期默认。是否启用 Salamander 由实测及客户端版本支持决定，不盲用最新文档才有的实验功能。
6. 先一台设备、预览配置差异、mihomo 离线检查，通过后热加载；读回 PROXY/AUTO/NODE-PICK/US-MEDIA，实际出网及主备 SSH 都验收。保留现有主用，不把新 HY2 直接置主。
7. 测试客户端范围内验证 TCP 不可用时的 HY2 选择与恢复；不能通过阻断全局 GIA TCP 或停 VLESS 来模拟，避免同时拆掉管理中继。已有生产会话可能需要重连，不承诺零断流。
8. BWG 试点稳定后，再评估 GIA 增加 HY2 和其他设备按站点灰度。带宽配置从保守值/默认拥塞控制开始，观察管理 RTT 与 CPU；不盲目填写很高 up/down 值。

## 其他可选路径

| 路径 | 可以改善 | 边界 |
| --- | --- | --- |
| VLESS/TCP + HY2/UDP，配不同运营商/地区节点 | 协议和节点故障的异构备援 | 同 IP、同主机的两个协议不抵御整机/整 IP 故障 |
| TUIC 等另一种 QUIC 客户端/服务端 | 增加实现或协议选择 | 仍基于 UDP，不能解决所有 UDP 被阻断；本项目需额外实现平台字段，当前不优先 |
| 第二个独立国内 SSH 救援入口 | 降低广州单点，并保留国内远程能力 | 不等于海外业务可上网；后端独立性另行设计，不直接开启冻结库双写 |
| 可用 IPv6/不同出口线路 | 可能避开某些 IPv4 或源运营商路径故障 | 须双方实测；不为此盲目打开全网 IPv6 或改现有路由 |
| 换 TCP 端口/仅更换同 IP 上的 TCP 协议 | 针对个别端口或部分协议识别可能有用 | 若前提是该源到该 IP 全 TCP 被阻断，则本身不能解决 |

近期优先级：保持国内管理入口 → 修复发布与媒体组 → BWG 单点 HY2 试验 → 通过后增加 GIA HY2。不是先向全舰队推两条新节点。
