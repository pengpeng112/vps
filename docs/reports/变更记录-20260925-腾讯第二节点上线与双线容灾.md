## 二、逐项明细

### C1 腾讯节点部署
- 实例：腾讯云轻量应用服务器，新加坡，Ubuntu 26.04，hostname `tx-sg-node`。
- 服务：sing-box 1.14.2，VLESS+Reality `:443`（SNI 伪装 www.microsoft.com，flow xtls-rprx-vision，fp chrome）；配置 `/etc/sing-box/config.json`（systemd 用 `-C /etc/sing-box`，**不是** /usr/local/etc）。
- **身份参数与 DO 节点完全独立**（uuid/pbk/sid 各自一套，互不通用）。
- 加固：ufw 仅 22/443、BBR+fq、unattended-upgrades、专用 SSH 密钥（`C:\Users\Administrator\.ssh\id_ed25519_tencent`，ubuntu 用户 sudo 提权）。
- **轻量平台防火墙与机内 ufw 是两层**：平台规则在控制台改（当前 22/80/443/ICMP 全放行）。

### C2 首 IP 路由黑洞 → 重置 IP
- 现象：办公网（联通 4837）→ 43.134.5.101 全端口 TCP+ICMP 100% 不通；DO 方向 1.5ms 秒通；traceroute 死在 Zayo 转接（64.86.161.4 后全星号）；节点 sing-box 日志零大陆入站。
- 结论：运营商级路由问题，非我方防火墙/服务问题。
- 处理：控制台「重置公网IP」→ **43.134.46.44**，443 秒连、ICMP 0% 丢包、延迟 ~213ms。
- **经验**：再遇「节点自身正常但大陆方向全灭」，直接重置 IP，别怀疑自己的配置。
- IP 变更联动同步项（均已做）：管理台节点 host（PATCH）、两台路由器 netprobe、仓库脚本（tx_node_diag.py / register_tx_node.py）、总表 §4b。

### C4 三层容灾策略（golden.yaml 改版）
- 新结构（两台路由器已生效，PROXY.now=AUTO）：
  ```
  PROXY(select) → AUTO(fallback, 探测 http://captive.apple.com/hotspot-detect.html, 300s)
                    ├─ NODE-PICK(url-test, gstatic generate_204, 300s, tolerance 80ms)  ← 平时：DO/腾讯按延迟择优
                    └─ DIRECT  ← 节点全部失活时自动回落（国外流量直连兜底，国内本就直连）
  ```
- 文件：`F:\vps\mgmt\backend\internal\clash\golden.yaml`（proxy-groups 重构）+ `template_test.go`（断言同步：AUTO 必须 fallback 且恰为 [NODE-PICK, DIRECT]）。
- 健康检查 URL 选 captive.apple.com 的原因：经节点（Apple 海外边缘）和直连（Apple 在华可达）两条路径都必须能通。
- 部署链：本地 `go test ./internal/clash/` 通过 → scp 到 VPS `/opt/mgmt/backend/internal/clash/` → api 重建 → assignments/batch 发布 → set_proxy_state 回 AUTO。
- **已知边界**：回落直连只在健康探测失败（彻底不通）时触发，轻度丢包抖动不会乱跳；节点间切换由 url-test 延迟逻辑处理（丢包严重通常表现为测速劣化，可触发）。
- **注意**：switch_node 任务会把 PROXY 钉到主用节点名，**每次发布/切换后需补一发 `set_proxy_state enabled=true`** 才回到 AUTO。

### C5 agent 验签 0x00 缺陷修复（重要）
- 病因：busybox awk `printf "%c", 0` 丢弃 0x00 字节。hex→二进制转换器用它，Ed25519 签名约 22% 概率含零字节 → **配置发布/agent 升级的验签随机失败**（当日实锤：同管线 v2/v4 成功、v3 失败）。
- 修复：改为 ash `printf "\xHH"` 逐对生成 + `>> 文件` 重定向（实测含 NUL 二进制安全）。位置：`handlers/switch_node.sh` 的 `verify_config_signature()`。
- 版本：升级包 **agent-2026092509**（含修复），两台路由器已通过 agent_update 管线升级（备份 agent-bak-20260925084042 / 084301），升级后 md5 与仓库一致：handler `709841e193716b71b5c96ec9f66ef685`。
- 服务器侧源码 `/opt/mgmt/agent/handlers/switch_node.sh`、`/opt/mgmt/agent/netprobe.sh` 已同步；升级包已重建（`/opt/mgmt/build-agent-bundle.sh 2026092509`）。
- 修复后连续 4 次验签（v4/v5 发布 + 2 次 agent_update）全部通过。

### C8 【code-review 核查】四项发现与修复（2026-09-25 下午）

**发现1（严重）：雅典娜 mihomo「换文件不换运行时」——三次发布全部静默失效**
- 症状：磁盘配置是新的三层结构，但运行时 API 里 AUTO 仍是旧的单节点 url-test（进程 PID 一整天未变）。
- 根因（两个叠加）：① 雅典娜核心以 `-d /etc/openclash` 启动，热加载接口拒绝主目录以外的路径（`PUT /configs` 对 `/etc/mihomo/run.yaml` 返回 400 "path is not subpath of home directory"）；② 回退路径 `/etc/init.d/openclash restart` 在 openclash 自身 `enable=0` 时返回成功但**不重启核心**（空操作）。
- 为何发布任务没发现：出口校验走 PROXY→旧 AUTO→DO，结果恰好等于期望值（DO 节点参数从未变过），旧配置照样能通过健康检查。
- 修复：① 手动 `/etc/init.d/mihomo restart` 恢复雅典娜运行时（PID 更新，三层组生效，透明代理规则由 init 脚本重装）；② agent `oc_reload()` 加固——新增 `reload_effective()`（新 yaml 里声明的全部 proxies/groups 必须已出现在运行时 API，不能只信 HTTP 204），回退顺序改为 mihomo 直跑脚本优先于 openclash 包装层；③ 升级包 **2026092510** 双机已升，handler md5 `050937023914ae799a3e844ea70258a7`。

**发现2（严重）：SN-R1 被管理台下发的旧版升级包降级**
- 症状：升级到 2026092510 一分钟后 handler 变回 `c5947c6a`（带 awk bug 的原始版）。
- 定位：审计日志显示 11:46:50 / 11:51:53 有两次 `agent_update version=2026092415`（created_by=admin，来自管理台入口，**非本次变更流程所发**；前端「升级」按钮发的是空版本=最新包，这两次是显式指定旧版本——疑似旧浏览器会话/手工调用）。SN-R1 那次发生在正常升级之后，故停留旧版。
- 修复：① SN-R1 重新升回 2026092510；② 后端加**防降级护栏**（configs.go agent_update 分支）：显式版本低于目录最新包时 422 拒绝，确需回滚须 `params.force=true`。已部署并实测：`2026092415 → 422 已拒绝`。
- **提醒：管理台页面上「升级 agent」请直接点（发最新包）；不要用旧标签页/手工指定旧版本号。**

**发现3（中）：netprobe 保留窗口数学错误**
- 原阈值按"432 行/天"计算，实际 3 目标×288 次/天=864 行/天，3100 行只够 3.6 天。已改为 6200/5900（真正 7 天），仓库/服务器/两台路由器四处同步（md5 `d12f46fc8fdff22da0766441b385472f`）。

**发现4（低）：migrate_tx_ip.py 轮询把 running 当终态**
- `status not in (pending, claimed)` 会把 running 提前当结果返回。已改为显式终态集合（ok/failed/rolled_back/expired/timeout）。

**核查通过项**：验签修复边界情况走查（奇数长度/非法字符/空签名 → 均产生错误字节 → 验证失败 → fail-closed，无需改）；golden.yaml 三层组在 SN-R1 的 fallback 健康检查实测有效（DIRECT=16ms / NODE-PICK=217ms）；重启后透明代理规则由 init 脚本自愈重装（雅典娜 nft / SN-R1 iptables 跳转链均确认）。

### C7 【事故记录】漏 prod overlay 重建 api
