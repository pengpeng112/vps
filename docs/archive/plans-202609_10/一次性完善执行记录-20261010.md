## 附录 A：P6 隧道密钥 command= 加固方案（待用户另批窗口执行，本轮未动现网）

### A.1 现状与威胁

路由器→VPS 的授权行（四台 VPS 各自的 authorized_keys，以 R2@DMIT 为例，密钥体略）：

```
no-agent-forwarding,no-X11-forwarding,no-pty,permitopen="10.10.0.1:8443",permitopen="127.0.0.1:8443",permitlisten="127.0.0.1:13223" ssh-rsa AAAA… rtr-mgmt-tunnel-snR2
```

缺口：`no-pty` 只是不分配终端，**不禁止无终端命令执行**。任一路由器被入侵、
`/etc/routermgmt/id_dropbear_mgmt` 私钥泄露，攻击者 `ssh -i key root@VPS '任意命令'`
即拿到对应 VPS 的 root 命令执行（四台全中）。

### A.2 关键事实：现网隧道客户端带 -N，与 command= 天然兼容

v3 init（`mgmt/agent/init/mgmt-tunnel-v3:99`）的实例命令：

```
/usr/bin/ssh -i "$KEY" -p "$_port" -N -K 30 -T -o ExitOnForwardFailure=yes … "root@$_vps"
```

`-N` 表示客户端**不请求任何会话通道**（无 exec/shell）。sshd 的 `command=` 强制命令是在
**会话通道建立时**替换客户端请求的命令——没有会话通道，强制命令根本不会被触发；
端口转发由 `permitopen`/`permitlisten`（+ AllowTcpForwarding）继续管控。
因此：**给这些行加一个"立即退出"的 command=，-N 隧道完全不受影响，而 exec 滥用会被掐断。**

### A.3 目标行格式（command= 与 permitopen/permitlisten 并存的写法）

```
command="/usr/local/sbin/mgmt-tunnel-gate",no-agent-forwarding,no-X11-forwarding,no-pty,permitopen="10.10.0.1:8443",permitopen="127.0.0.1:8443",permitlisten="127.0.0.1:13223" ssh-rsa AAAA… rtr-mgmt-tunnel-snR2
```

要点：
- `command=` 必须是**选项列表第一项**（放哪都合法，但放头部便于审计）；与 permitopen/
  permitlisten 之间用逗号分隔；**permitopen 仍必须重复选项格式**（沿用既有铁律，禁止逗号列表值）。
- 可选更现代化写法：`restrict,port-forwarding,command="…",permitopen=…`（OpenSSH≥7.8，
  `restrict` 一键关闭 pty/x11/agent/user-rc 等，`port-forwarding` 再放行转发）。四台 VPS 的
  sshd 版本需先核（DMIT/TX/BWG/DO 均 Ubuntu 24.04 系 OpenSSH 9.x，支持）。

### A.4 gate 脚本（四台 VPS 同一文件，root:root 755）

```sh
#!/bin/sh
# /usr/local/sbin/mgmt-tunnel-gate — 路由器隧道密钥 command= 闸门（P6）
# -N 转发会话不会触发本脚本；任何 exec/shell 会话会被替换为本脚本并立即退出=拒绝执行。
# 只记审计日志，不执行任何客户端请求。
logger -t mgmt-gate "rejected session client=${SSH_CLIENT:-?} orig=${SSH_ORIGINAL_COMMAND:-<none>}"
exit 0
```

说明：`exit 0` 让滥用会话干净结束（对攻击者表现为"连上即断"，无输出）。
`SSH_ORIGINAL_COMMAND`/`SSH_CLIENT` 落审计日志，攻击尝试可追溯。
**不要**用 sleep/wait 陪跑写法——那会让滥用会话挂着不断，也没有必要（-N 不触发本脚本）。

     无路由器侧条件时，以"心跳+双通道正常"为充分观察项。
