## 1. 全局铁律（历史事故教训，违反即停）

1. 远端写文件：写完必须 md5 比对与源一致才执行/生效；>8KB 分段传输+逐段校验；绝不复用出过错的中间产物。
2. `authorized_keys` 多目标必须重复选项（`permitopen="A",permitopen="B"`），严禁逗号列表；本轮**不改任何 permitopen/permitlisten 行**。
3. 服务器侧允许的动作：`docker compose restart/up -d`（指定容器）、`systemctl reload ssh`、文件替换。**reload/restart 后必须新开会话验证成功，才允许退出当前会话。**
4. 生产 compose 一律核对 base 与 prod overlay 的合并结果（`docker compose -f docker-compose.yml -f docker-compose.prod.yml config`），不照搬开发命令。
5. 改 sshd：改前备份 → `sshd -t` 语法检查 → reload（不是 restart）→ 新连接验证。失败立即还原备份再 reload。
6. 路由器上只允许：读命令、写 `/etc/routermgmt/` 与 `/etc/config/` 下文件（md5 闸门）、`crontab -l/-`（增 discovery 行）。**不执行 /etc/init.d/mgmt-tunnel restart、不 reboot、不 ifup/wifi。**
7. 敏感产物脱敏：报告/执行记录不贴口令、密钥、完整证书、token。
8. 任何一步的"验收"不过 → 回退 → 停，写《执行记录》说明停在哪。
