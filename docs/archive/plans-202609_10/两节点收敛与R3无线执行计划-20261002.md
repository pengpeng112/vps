## 2. 三十台能不能放在第一台美西

**可以按 30 台登记来用。** 不能按 30 台同时满速看视频来用。

依据和限制（执行时不要把这些写成新的实测）：

- 管理心跳很轻。2026-09-26 的隔离压测是 50 台虚构设备 × 20 轮心跳，P95 约 17ms。30 台真实心跳不是这台机器的上限。
- 每台路由器到主台一条常驻 SSH。30 条对 sshd 可接受。观察期内仍是四端点：DMIT 收主用，腾讯（`VPS2`）、东京（`VPS3`）、DO（`VPS4`）各收一条备用。
- 视频上限来自同一台 2GB 机器同时跑管理台和代理。2026-10-01 晚 R2 的一次样本：美西三路并发合计约 15.4 MB/s（约 120 Mbps）。这是单次传输，不是套餐标称带宽，档案里没有这台机器的月流量配额。
- 规划预算：**同时约 5 路 1080p（大约几十 Mbps），留一倍余量。** 4K 或更多路同时看，就触发第 9 节，加第二台美西，而不是把登记台数理解成带宽已经够。
- 东京是 1GB 内存、每月 1TB，重置日 2026-10-31，超额会停到重置日，不能单买流量包。30 台的网页交互可以放在东京；视频必须留在美西。没进海外媒体名单的大文件仍会走东京，阶段 B 要盯月流量。

执行 AI 在阶段 B 用面板和网卡计数补「套餐带宽 / 已用月流量」，补完之前沿用上面的预算，不要自行放宽。

## 5. 阶段 A — 远程修改 R3 无线（立即做）

目标 SSID：`SN-R3-AX3000`（2.4G）、`SN-R3-AX3000-5G`（5G）。
目标 PSK：凭证总览里的舰队 WiFi 政策值，与 R2 已经在用的值相同。root 口令不动。

现场影响：无线客户端约 1 分钟内断开，须改连新 SSID。WAN、反向 SSH、代理、有线 LAN 保持。回退不依赖人在现场。

### A0. 动手前

1. 向操作者发一行说明：即将把 R3 无线改为上述 SSID，口令沿用舰队 WiFi 政策，无线约断 1 分钟。用户本轮已授权，**不要为此再询问一次**。若操作者在动手前明确叫停，才中止。
2. 管理台确认 R3 心跳在刷新，且当前没有进行中的发布任务。
3. 经 DMIT `13227` 进入后确认设备 ID。

### A1. 只读摸底

在 R3 上记录（写入执行记录的是键名、SSID、RadioOff，**不是** PSK 原文）：

```sh
cd /etc/wireless/mediatek
for F in mt7981.dbdc.b0.dat mt7981.dbdc.b1.dat DBDC_card0.dat; do
  echo "== $F =="
  grep -E '^(SSID[0-9]*=|RadioOff=)' "$F"
  grep -oE '^WPAPSK[0-9]*=' "$F"
done
iwconfig ra0; iwconfig rax0
uci show wireless.ra0.ssid; uci show wireless.rax0.ssid
```

继续的条件：

- 三个 dat 都在。
- 当前广播的是出厂 `WIFI-7880`（或执行记录写明的实际 SSID）。若已经是 `SN-R3-AX3000`，改为只核对 PSK 哈希是否与政策值一致，一致则阶段 A 记为已完成，不再 `wifi up`。
- `RadioOff` 不是 1。若是 1 而接口仍在广播，停止并报告，不要猜。

### A2. 备份

```sh
TS=$(date +%Y%m%d-%H%M%S)
mkdir -p /root/wifi-bak-$TS
cp -a mt7981.dbdc.b0.dat mt7981.dbdc.b1.dat DBDC_card0.dat /root/wifi-bak-$TS/
cp -a /etc/config/wireless /root/wifi-bak-$TS/wireless.uci
md5sum mt7981.dbdc.b0.dat mt7981.dbdc.b1.dat DBDC_card0.dat /etc/config/wireless
```

把四个 md5 和备份目录名写入执行记录。

### A3. 写入

在操作者电脑上从凭证总览取出舰队 WiFi PSK，不要打印。写到 R3 的 `/tmp/wifi-psk`（单行、权限 600），用完即删。口令不要出现在 `sed`、`uci` 或执行记录里。

先拒绝会打破 shell 或 dat 行的值。现行舰队值是字母数字，会通过；不通过就停，不要自行加转义：

```sh
awk '{sub(/\r$/,""); if (NR==1) v=$0} END{
  if (NR!=1 || v=="" || v ~ /[^A-Za-z0-9]/) exit 1
}' /tmp/wifi-psk || { echo 'psk rejected'; exit 1; }
```

SSID 用单引号固定字符串。PSK 用 awk 从文件读入，等号左边的 `WPAPSK` 序号原样保留：

```sh
cd /etc/wireless/mediatek
sed -i 's/^SSID1=.*/SSID1=SN-R3-AX3000-5G/' mt7981.dbdc.b1.dat
sed -i 's/^SSID1=.*/SSID1=SN-R3-AX3000/' mt7981.dbdc.b0.dat
sed -i 's/^SSID1=.*/SSID1=SN-R3-AX3000/' DBDC_card0.dat
for F in mt7981.dbdc.b0.dat mt7981.dbdc.b1.dat DBDC_card0.dat; do
  awk 'BEGIN{getline p < "/tmp/wifi-psk"; sub(/\r$/,"",p); if (p=="" || p ~ /[^A-Za-z0-9]/) exit 1}
    /^WPAPSK[0-9]*=/{key=$0; sub(/=.*/,"",key); print key "=" p; next}
    {print}' "$F" > "$F.tmp" && mv "$F.tmp" "$F"
done
```

uci 只同步镜像，**不要**写 `disabled=1`，**不要**改 `RadioOff`。这里的值来自上一步已通过字母数字检查的文件：

```sh
PSK=$(cat /tmp/wifi-psk)
uci set wireless.ra0.ssid='SN-R3-AX3000'
uci set wireless.rax0.ssid='SN-R3-AX3000-5G'
uci set wireless.ra0.key="$PSK"
uci set wireless.rax0.key="$PSK"
unset PSK
uci commit wireless
rm -f /tmp/wifi-psk
```

写入后、重启无线前检查：

- `grep -c '12345678' mt7981.dbdc.b0.dat mt7981.dbdc.b1.dat DBDC_card0.dat` 为 0。
- `grep -c 'WIFI-7880'` 同样为 0。
- `grep -oE '^WPAPSK[0-9]*='` 的键名集合与 A1 相同。
- 在操作者电脑比较：`grep '^WPAPSK1=' b0.dat` 的 md5 等于本地 `WPAPSK1=<政策PSK>` 这一行的 md5。不相等则从 A2 备份拷回，不要 `wifi up`。

### A4. 生效

`wifi down` 会断开从无线侧连进来的 SSH。R3 的管理入口是 DMIT 上的反向口 `13227`，走 WAN，不走无线。动手前确认当前 shell 就是这条：

```sh
echo "$SSH_CONNECTION"
```

来源应是 `127.0.0.1` 或路由器本机地址（反向隧道落地）。来源若落在 `192.168.132.0/24` 的客户端地址，或 `SSH_CONNECTION` 为空，停止。改从 DMIT `13227` 重新进入后再执行。回退时的 `wifi down` 也必须在同一次 `13227` 会话里。

```sh
wifi down; wifi up
sleep 8
iwconfig ra0; iwconfig rax0
```

验收：`ra0` 的 ESSID 为 `SN-R3-AX3000`，`rax0` 为 `SN-R3-AX3000-5G`，两块射频不是关闭态。然后在同一会话再执行一次 `echo ok`。管理台看 R3 心跳仍刷新。

### A5. 回退

ESSID 不对、射频没起来、或操作者要求撤回：

```sh
cd /etc/wireless/mediatek
cp -a /root/wifi-bak-$TS/*.dat .
cp -a /root/wifi-bak-$TS/wireless.uci /etc/config/wireless
wifi down; wifi up
```

回读 ESSID，应回到 A1 的出厂名。备份目录留在路由器上，不拉回仓库。

- 当前状态顶部把「R3 WiFi 待时间窗」改成已改，并写 ESSID 与备份目录名，不写 PSK。
- 执行记录写明：备份 md5、键名是否保持、ESSID、心跳是否连续、有没有回退。

## 7. 阶段 C — 观察到 2026-11-02

每天不需要人工值守。执行 AI 只在用户开任务时抽查，或阶段 B 已经发现超预算时才加测。

观察期规则：

- 腾讯、DO 的虚拟机、sshd、代理进程保持运行。四端点隧道保持：不删 `VPS2`/`VPS3`/`VPS4`。
- 新设备可以上线，主用必须是东京，`US-MEDIA` 必须是美西。腾讯和 DO 只作为备用成员。
- R4 在观察期继续整机主用美西。这是接受的代价：交互大约停在 2026-10-02 实测的 159ms，而不是东京那档大约 80ms 的历史水平；这两个数不是同一小时的对照。阶段 D 才把它改成与 R2/R3 相同。观察期内不要为了「终态是东京交互」提前改 R4。阶段 B 的长流若出现「小探测成功但长流掉到几十 KB/s」，只记录，把 R4 调整提前列为阶段 D 的第一项业务变更。
- 可选、且单独一天做：仅当 B4 读到的那一台是腾讯 Hysteria2 排在腾讯 VLESS 前面。把该台 `failover_priority` 调成东京 VLESS、腾讯 VLESS、腾讯 Hysteria2。R4 在 2026-10-02 已是 hy2 在最后，不在此列，除非 B4 读到的顺序变了。改完预览再发布，发布后核对 NODE-PICK，并确认该台出口 IP 仍是改前的主用。不要顺手改 `US-MEDIA` 或别的规则。
- 东京 Hysteria2 的 UDP 重测若做，只做探测，不通就保持休眠。

每周在执行记录追加四行：美西可用内存、美西晚高峰出站、东京本月流量、有没有必须靠腾讯或 DO 才恢复的故障。一次都没有，才算阶段 D 的「一个月没问题」。

## 8. 阶段 D — 停用（最早 2026-11-02）

日期未到就停止。日期到了但闸门缺证据，也停止。顺序固定，前一步没验收不走下一步。每一步都先备份、写 md5、准备回退，再重启对应服务。

### 闸门（全部要有执行记录）

1. 阶段 A 已验收，或记录 R3 无线在动手前已经是目标 SSID。
2. 阶段 B 的依赖表每一行都有「仍在用 / 已无监听」结论，不能是空的。
3. 自 2026-10-02 至检查日，没有「只有腾讯或只有 DO 能通、东京和美西都不通」的故障。有过一次，就把保留期再延 30 天，不关机器。
4. 美西内存和晚高峰带宽仍低于 B2 的线，或者第二台美西已经在线并接走了视频（阶段 E）。超预算又没有第二台时，**仍然可以停腾讯的代理角色**，但不要把腾讯上的视频流量改回业务路径。
5. 异地备份至少两份。2026-10-02 已有腾讯和东京两份。关腾讯虚拟机前，接替腾讯的那一份必须已经在写（第二台美西），或者用户在本计划之后另书面接受只留东京一份。只剩东京一份时不关腾讯。

### D1. 出口收成两节点（先家用 R2）

在 DMIT 管理台：

1. 读 R2 当前绑定和 NODE-PICK 原文，写入执行记录。
2. 主用改为东京 VLESS。`US-MEDIA` 仍只指向 LAX，失活回落 NODE-PICK。
3. 从绑定里去掉腾讯 VLESS、腾讯 Hysteria2、DO。预览 diff，确认国内直连规则还在，再发布。
4. 验收：出口 IP 双验为 `74.82.203.175`；YouTube 走美西（出口 `179.255.137.64`）；百度直连。然后原样做 R3，最后做 R4。
5. R4 发布后再做一次晚高峰长流。交互应出东京，视频应出美西。
6. 回退：按该设备发布前的绑定重新 apply。每台发布间隔至少跨过一次心跳，不要三台并行发布。

雅典娜的出口不在 D1 改。管理隧道迁完并过了独立的一天，再做 D2b。D5 停腾讯代理之前，D2b 必须已经验收。

### D2. 雅典娜管理隧道迁到 DMIT

雅典娜是 AX6600，防火墙是 nftables。本步只动它的 `mgmt-tunnel` 与 `tunnel.conf`。

1. 先读出现网 init 和 conf，确认是 v1 单端点、目标在 DO。和仓库 `mgmt/agent/init/mgmt-tunnel-v3` 做差异。v3 若只是多段 SSH，可以套用；若夹带 iptables / mihomo 规则，停，不要套。
2. 在 DMIT `authorized_keys` 为雅典娜公钥增加 `permitlisten` 到一个未占用端口（不要复用 13223/13224/13227）。`permitopen` 用重复选项，指向 `127.0.0.1:8443`。语法检查 sshd 后再加载。**这一天不要再改路由器上的隧道脚本。**
3. 次日再写雅典娜 conf：`VPS_HOST` 为 DMIT，`VPS2_HOST` 为东京，不写腾讯和 DO。传输用 md5 闸门。灰度至少 45 分钟，确认新端口 200，再切主。
4. 验收：排障口在 DMIT 上能进、设备 ID 正确、心跳改写 DMIT、DO 上该设备心跳停止刷新。
5. 回退：恢复雅典娜本机 `tunnel.conf` 备份并重启隧道，心跳回到 DO。

### D2b. 雅典娜代理改离腾讯（D5 的前置）

D2 验收之后单独一天做。只通过管理台发布雅典娜自己的配置。发布前预览 diff：国内直连、公司与医院相关直连规则还在。不要把 SN-R 的 iptables 脚本或另一台的整份配置覆盖上去。雅典娜防火墙保持 nftables。

1. 读当天绑定。历史记录是腾讯主用、DO 备用，以这次读到的为准。
2. 主用改为东京 VLESS，`US-MEDIA` 指向 LAX，去掉腾讯和 DO 的绑定成员。
3. 验收：出口 IP 双验为 `74.82.203.175`；一条海外视频样本出口为 `179.255.137.64`；公司网直连目标仍通（至少包括既有的国内与医院依赖检查，不访问业务正文）。
4. 回退：按发布前绑定重新 apply，出口 IP 回到发布前的节点。
5. 这一步没验收，就停在这里，不执行 D5。

### D3. 医院跳板与 WireGuard

医院链路今天是：工位电脑计划任务连 DO，DO 回环 `18422`/`18322` 再回到工位，经雅典娜上的 `10.1.2.18` 进医院。`10.1.2.18` 不动。

1. 在 DMIT 上建与 DO 同权限边界的 jump 账户：只能到本机回环的医院口和已经迁完的路由器口，不能拿 shell。密钥用现有 jump 公钥，不新造密码。
2. 改工位计划任务的目标主机到 `179.255.137.64`，回环端口保持 `18322`/`18422`，避免改医院侧。
3. 复验两个医院地址的 SSH banner。失败则把计划任务指回 DO，本闸不通过，DO 不关。
4. WireGuard：列出 `docs/wg-peers/` 的每个 peer。管理台访问已经有 `管理台通道-DMIT.bat`。给仍要用手机 WG 的 peer 发指向 DMIT 的新配置，旧 DO 枢纽保持到对方确认连上。没有确认的 peer 就不停 DO 上的 `wg-quick@wg0`。

### D4. 备份改道

2026-10-02 的备份源已经是 DMIT，推送目标已经是腾讯和东京两份。本步不是把腾讯「设成第二份」，东京就是现成的第二份。

1. 读 DMIT `/opt/mgmt/backup.sh`，把实际目标写入执行记录。若不是这两台，停止并报告，不要按旧印象改。
2. 第二台美西就绪后，用它接替腾讯那一份：推到新机器的 `/opt/mgmt-standby/latest-backup.tar.gz`，东京那一份保持。手动跑一次，DMIT、东京、新机器三处 md5 一致，再留 cron。
3. 第二台还没有时，不改推送目标。D5 可以停腾讯的代理入站，腾讯虚拟机、sshd 和 `/opt/mgmt-standby` 继续收备份。
4. DO 的 `do-legacy-backup.tar.gz` 路径保持，直到 D6。

### D5. 腾讯退出代理

前置：D1 已验收，并且 D2b 已验收（雅典娜出口不再是腾讯）。缺一个就停。

1. 在腾讯 sing-box 配置里给 VLESS 和 Hysteria2 入站做停用备份（整文件副本，权限保持），再停用入站并重载。
2. 从 R2 和雅典娜各做一次连接测试。R2 交互出口应为东京，视频样本应为美西。雅典娜同样双验，并且公司网直连检查仍通。
3. sshd、备份目录、`/opt/mgmt-standby` 保留。管理隧道里的 `VPS2`（腾讯，本地 `18444`）也保留，直到接替备份的机器到位、并且下面的两段收口做完。
4. 回退：恢复 sing-box 配置副本并重载。

腾讯 `28722` 不再作为管理备用的那一天（不早于 D4 的接替备份已经在写），逐台把隧道收成两段，先 R2：

1. 备份 `tunnel.conf`。
2. 把现有 `VPS3_HOST`（东京）写到 `VPS2_HOST`，端口仍是 `28722`；删除 `VPS3_*`。`VPS4` 是否还在，以当时 D6 做到哪一步为准，不要在这一步顺便改 DO。
3. 重启隧道。`18443` 仍是 DMIT 且返回 200，`18444` 变为东京且返回 200。init 不会因为删了 `VPS3` 就自动改端口号；东京是被写进 `VPS2` 之后才落在 `18444`。
4. 心跳仍在 DMIT。然后隔一次心跳再做 R3、R4。雅典娜若 D2 已经是 DMIT+东京两段，跳过。
5. 回退：恢复该台 conf 备份并重启。

### D6. DO 退出

D2、D2b、D3 都验收之后。先拆路由器上的 DO 端点，再停 DO 上的服务。各台 conf 还写着 `VPS4` 时先关 DO 的 sshd，procd 会按 `respawn 3600 0 0` 一直重连。逐台删掉 `VPS4` 并确认 `18443` 仍通之后，再停 DO。

逐台去掉 `VPS4`，先 R2，灰度至少 45 分钟，再 R3、R4。雅典娜若 D2 没写 DO，跳过。

1. 备份该台 `tunnel.conf`。确认 `VPS_HOST` 仍是 DMIT，`VPS3_HOST` 仍是东京（若尚未按 D5 收成两段）。
2. 只删除 `VPS4_HOST` 和 `VPS4_PORT`。不要在同一步删除腾讯或东京。
3. 重启隧道。验收：`18443` 返回 200，心跳仍写 DMIT，本机不再监听 `18446`。`18444`/`18445` 按还留着的 `VPS2`/`VPS3` 继续 200。
4. 回退：恢复 conf 备份并重启，`18446` 重新指向 DO。

四台里仍依赖 DO 的都拆完之后：

1. 再确认 DO 上没有刷新中的设备心跳，`18222` 无新建连，`18322`/`18422` 已无业务（或已明确改到 DMIT 且 banner 复验通过）。
2. 做最终库导出到 DMIT `/opt/mgmt/backups/do-final-YYYYMMDD.sql.gz`（含设备、任务、告警、流量、审计相关表），记录大小和 sha256。这是归档，不导回 DMIT 生产库，避免和现网库合并。
3. 停 DO 上的管理容器、sing-box、WireGuard。sshd 再留 7 天。
4. 7 天后没有回退需求，才在厂商侧关机。退订由用户自己在面板操作，执行 AI 不代点销毁。

### D7. 文档

停机验收后更新：`docs/current/当前状态.md` 顶部、`docs/INDEX.md` 进行中列表、`AGENTS.md` 态势速览里的「四节点」句子。旧报告不改写。`mgmt-tunnel-v3` 文件头注释仍描述 DO 主用和 socat，与现网不符；阶段 D 若改脚本，一并改注释，并用 R2 灰度，不和无线或 sshd 同一天。

## 9. 阶段 E — 第二台美西（触发才做）

本计划不购买。出现下面任一条，执行 AI 写一份单独的接入提纲给用户，自己不注册机器：

- 连续 3 个晚高峰，第一台出站超过 80 Mbps 且持续 10 分钟以上。
- 可用内存低于 300MB。
- 视频长流多次低于 1 MB/s，而小探测仍成功。
- 登记设备已到 30，并且同时视频明显多于 5 路。

第二台的角色预先定死，避免又做成管理单点：

- 只做第二视频出口和备份接收。
- 管理主台、主备份源、路由器 `-R` 排障口仍在第一台。
- 接入时按现有节点流程：独立 REALITY 凭据、防火墙只开 22 和 443、先绑一台家用设备的 `US-MEDIA`，晚高峰长流通过再谈迁移一半设备。
- 设备分配按站点固定到其中一台，不用轮询。同一户的视频不要在两台之间来回跳。

## 10. 执行记录最低字段

每个阶段结束时，执行记录里要有：

- 做了哪几步，停在哪一闸。
- 证据是命令输出的哪一类事实（端口、md5、ESSID、出口 IP、流量数字），并标明实测时间。
- 主动写过哪些机器上的哪些文件。阶段 B 应为「无生产写入」。
- 回退点的路径。
- 下一动作的前置条件。

没查到的依赖写「未查」，不要写「不存在」。
