## 1. 背景（为什么做）

- 管理台（Go API + PostgreSQL + nginx）目前只在 DO 新加坡 `159.223.36.119` 的 Docker 里运行。
- 路由器已有三方并行隧道（DO:28722 / TX:28722 / BWG:28722），任何一条路可达即可管理。

## 3. 核心设计：MGMT_TARGET 从 10.10.0.1 改为 127.0.0.1

**当前问题**：路由器 tunnel.conf 的 `MGMT_TARGET=10.10.0.1:8443`，即 -L 转发的目标永远是 DO 的 WG IP。如果 DO 挂了，即使路由器连上 TX，TX 也无法到达 10.10.0.1（那是 DO 的 IP）。

**解决方案**：改为 `MGMT_TARGET=127.0.0.1:8443`。这样：
- 路由器 → DO:28722 → DO 的 127.0.0.1:8443 → **DO 的管理 API**（主节点）
- 路由器 → TX:28722 → TX 的 127.0.0.1:8443 → **TX 的管理 API**（温备）
- 路由器 → BWG:28722 → BWG 的 127.0.0.1:8443 → **BWG 的管理 API**（温备）

每台 VPS 服务自己的 API。DO 活着时 agent 用 18443（主），DO 挂了 agent 自动切到 18444/18445（温备）。

**前提**：DO 的 Docker 需要增加 `127.0.0.1:8443->8443` 端口映射（当前只有 `10.10.0.1:8443->8443`）。

## 4. 实施步骤

### 第 1 步：DO 增加 127.0.0.1:8443 端口映射（10 分钟）

```bash
# DO 上执行
cd /opt/mgmt/deploy
# 备份 compose
cp docker-compose.prod.yml docker-compose.prod.yml.bak-$(date +%Y%m%d-%H%M%S)
# 在 web 服务的 ports 里加一行（保持原有 10.10.0.1:8443 不变）
# 编辑 docker-compose.prod.yml，在 web.ports 里加：
#   - "127.0.0.1:8443:8443"
# 然后重建 web 容器（不影响 api/db）
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d web
# 验证
curl -sk https://127.0.0.1:8443/api/v1/health | head -c 10
# 预期输出包含 200 或 ok
```

**注意**：只加端口映射，不动 api/db 容器。web 容器重建有几秒中断，agent 心跳会自动重试。

### 第 2 步：TX 部署温备管理台（30 分钟）

```bash
# TX 上执行（ubuntu 用户，需 sudo）

# 2a) 安装 Docker（如果没有）
command -v docker || curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER && newgrp docker

# 2b) 创建管理台目录
sudo mkdir -p /opt/mgmt-standby/deploy
sudo chown -R $USER:$USER /opt/mgmt-standby

# 2c) 从 DO 拉取管理台源码和配置
# 方法：在 DO 上打包，scp 到 TX
# （在 DO 上执行）
cd /opt/mgmt
tar -czf /tmp/mgmt-standby.tar.gz \
    backend/ deploy/docker-compose.yml deploy/docker-compose.prod.yml \
    deploy/prod-certs/ deploy/prod-nginx.conf \
    --exclude='*/node_modules' --exclude='*/.git'
scp /tmp/mgmt-standby.tar.gz ubuntu@43.134.46.44:/tmp/

# （在 TX 上执行）
cd /opt/mgmt-standby
tar -xzf /tmp/mgmt-standby.tar.gz
rm -f /tmp/mgmt-standby.tar.gz

# 2d) 从 DO 拉取最新数据库备份
# （在 DO 上执行）
# 找最新备份
LATEST=$(ls -t /opt/mgmt/backups/mgmt-backup-*.tar.gz | head -1)
scp "$LATEST" ubuntu@43.134.46.44:/tmp/latest-backup.tar.gz

# （在 TX 上执行）
cd /opt/mgmt-standby
mkdir -p /tmp/restore
tar -xzf /tmp/latest-backup.tar.gz -C /tmp/restore
cp /tmp/restore/db.sql deploy/ 2>/dev/null
cp /tmp/restore/.env deploy/ 2>/dev/null
rm -rf /tmp/restore /tmp/latest-backup.tar.gz

# 2e) 修改 compose 使用 localhost 端口（不绑 WG IP）
cd /opt/mgmt-standby/deploy
# 编辑 docker-compose.prod.yml，把 ports 改为：
#   - "127.0.0.1:8443:8443"
# （不是 10.10.0.1 因为 TX 的 WG IP 是 10.10.0.3）

# 2f) 创建温备启动脚本
cat > /opt/mgmt-standby/start.sh <<'EOF'
#!/bin/bash
# 温备启动：DO 挂了时在 TX 上执行此脚本
cd /opt/mgmt-standby/deploy
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d
sleep 10
curl -sk https://127.0.0.1:8443/api/v1/health
echo ""
echo "温备管理台已启动"
echo "路由器的并行隧道会自动连过来（18444 端口）"
EOF
chmod +x /opt/mgmt-standby/start.sh

# 2g) 验证：启动→测试→停止（温备状态容器应停止）
cd /opt/mgmt-standby/deploy
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d
sleep 15
curl -sk https://127.0.0.1:8443/api/v1/health
# 确认返回 200 后，停止（回温备状态）
docker compose -f docker-compose.yml -f docker-compose.prod.yml down
echo "TX 温备就绪（容器已停止，start.sh 一键启动）"
```

### 第 5 步：每日数据库同步脚本（15 分钟）

在 DO 的 backup.sh 末尾追加推送逻辑：

```bash
# DO 上执行：追加到 /opt/mgmt/backup.sh 末尾
cat >> /opt/mgmt/backup.sh <<'SYNC'

# ---- 温备同步：推送最新备份到 TX 和 BWG ----
STAGE_STANDBY="$STAGE/standby-push"
mkdir -p "$STAGE_STANDBY"
cp "$BACKUP_DIR/$TODAY.tar.gz" "$STAGE_STANDBY/" 2>/dev/null || true

for TARGET in "ubuntu@43.134.46.44" "root@74.82.203.175"; do
    HOST=$(echo "$TARGET" | cut -d@ -f2)
    KEY=""
    [ "$HOST" = "43.134.46.44" ] && KEY="-i /root/.ssh/id_ed25519_tencent"
    [ "$HOST" = "74.82.203.175" ] && KEY="-i /root/.ssh/id_ed25519_digitalocean"
    scp $KEY -o ConnectTimeout=10 -o StrictHostKeyChecking=no \
        "$STAGE_STANDBY/$TODAY.tar.gz" \
        "$TARGET:/opt/mgmt-standby/latest-backup.tar.gz" 2>>"$LOG" \
        && echo "$(date '+%F %T') standby sync OK → $HOST" >> "$LOG" \
        || echo "$(date '+%F %T') WARN standby sync failed → $HOST" >> "$LOG"
done
rm -rf "$STAGE_STANDBY"
SYNC
```

## 6. 安全注意事项

- TX/BWG 的管理台端口只绑 `127.0.0.1:8443`，**不暴露公网**
- 温备容器的 .env 从 DO 复制，包含相同 MASTER_KEY（数据库加密兼容）
- 数据库同步走 SSH（加密），凭据用密钥认证
- BWG 内存紧张（1GB），管理台+代理并存时注意监控
- 故障切换后 TX/BWG 上的数据是最后同步的快照（最多差 24 小时）
