## 一、经服务器（VPS）的全部访问通道

### 0. 进 VPS 本身（一切通道的根）

```bash
ssh -p 28722 -i C:\Users\Administrator\.ssh\id_ed25519_digitalocean root@159.223.36.119
```
仅密钥登录（无密码可爆破）；ufw 只开 443/28722/51820；fail2ban 在岗。
救急通道：DigitalOcean 网页 Recovery Console（账号密码只有用户本人知道）。

### 1. 外网 Claude → 医院内网服务器（AI-HMS 项目）

```bash
ssh -i ~/.ssh/id_claude_jump -J jump@159.223.36.119:28722 -p 18422 root@localhost   # 落 10.10.8.84:40022
ssh -i ~/.ssh/id_claude_jump -J jump@159.223.36.119:28722 -p 18322 root@localhost   # 落 10.10.8.83:22
```
- 链路：Claude → VPS jump 账户 → 回环 18422/18322 →（常驻反向隧道）→ 工位电脑 →（雅典娜借 IP 10.1.2.18 白名单）→ 目标机。
- 依赖：工位电脑 `AIHMS-JumpTunnel` 计划任务在线 + 电脑经雅典娜上网（拓扑见 SN-R1 文档 §1）。
- 入口私钥：`C:\tools\jump-tunnel\cred\id_claude_jump`（待私密转交后删本机份）。

### 2. 外网 → 两台路由器的排障 SSH（2026-09-23 打通）

```bash
ssh -i ~/.ssh/id_claude_jump -J jump@159.223.36.119:28722 -p 18222 root@localhost   # 雅典娜 LibWrt
ssh -i ~/.ssh/id_claude_jump -J jump@159.223.36.119:28722 -p 13222 root@localhost   # SN-R1 OpenWrt
```
- 与 Claude 通道同一把入口钥匙、同一 jump 受限账户；jump 键只允许到 18422/18322/18222/13222 四个回环口，无 shell。
- 由各路由器 `mgmt-tunnel` 服务里的 `-R` 反向口提供（雅典娜 18222、SN-R1 13222，注意 SN-R1 的 -R 目标是 192.168.132.1:22，因其 dropbear 不听 127.0.0.1）。
- 路由器登录口令见总表 §3 / §3b。

### 3. 管理台（设备状态/策略/任务）

- 工位电脑：双击桌面「管理台通道.bat」→ `https://127.0.0.1:8443`（admin + 总表密码 + TOTP）。
- 手机：开 WireGuard → `https://10.10.0.1:8443`。
- 任意有 SSH 权限的机器自建通道：`ssh -p 28722 -i <VPS私钥> -L 8443:10.10.0.1:8443 root@159.223.36.119`。
- 路由器 Agent 心跳走各自的 SSH TCP 隧道（127.0.0.1:18443 → 10.10.0.1:8443），不经公网。

### 3. 重建步骤（新 Ubuntu 24.04 机上，约 30-60 分钟）

```bash
# ① 基础：apt 更新；装 docker、docker-compose-plugin、sing-box、fail2ban、wireguard
# ② 解包备份：
tar -xzf mgmt-backup-*.tar.gz -C /tmp/restore
# ③ 管理台：mgmt-src.tar.gz 解到 /opt/mgmt；.env、prod-certs、compose、pkg 放回 /opt/mgmt/deploy
#    db 灌入：docker compose 先起 db；先建应用角色（2026-09-30 补：缺此步导入报 role "mgmt_app" does not exist）：
#      psql -U postgres -c "CREATE DATABASE routermgmt" -c "CREATE ROLE mgmt_app LOGIN PASSWORD '<从 .env 的 DB 密码段取>'"
#    再导入 db.sql，最后 up -d --build
# ④ sing-box：config.json 放回 /usr/local/etc/sing-box/，service 放 /etc/systemd/system/，systemctl enable --now
# ⑤ SSH：sshd_config + sshd_config.d 放回；authorized_keys 分别放回 /root/.ssh 与 /home/jump/.ssh（jump 用户需先建：useradd -m -s /bin/bash jump + usermod -p '*'）；重启 sshd
# ⑥ WG：wg0.conf 放回 /etc/wireguard/，wg-quick up wg0
# ⑦ 防火墙：ufw tar 解回 /etc/ufw；确认 443/28722(ALLOW)/51820 放行，ufw enable
# ⑧ cron：30 3 * * * /opt/mgmt/backup.sh
# ⑨ 验证：路由器心跳恢复在线、mihomo 出口通、jump 四个口可达
```

### 4. 一个必须知道的限制：**IP 绑定**

159.223.36.119 这个 IP 硬编码在：两台路由器的 mihomo 配置与 mgmt-tunnel、工位电脑 tunnel.bat、手机 WG 配置、黄金模板。**若换了新 VPS 而公网 IP 变了**，上述都要逐个改（路由器可经管理通道远程改，手机需重发配置）。
- 规避方案 A（推荐）：给当前 Droplet 挂一个 **DO Reserved IP**（绑定中免费），以后换机只挪 Reserved IP，路由器无感——但现在切换需逐台改一次配置，可在下次有空时做。
- 规避方案 B：出事时用同 IP 重建（DO Droplet "Rebuild" 保留 IP，但需要平时先做 Droplet 快照——当前未开启）。

### 5. 日常防灾清单

- 每周双击「拉取管理台备份.bat」（本机 F:\vps\backups 留最近一份即可）。
