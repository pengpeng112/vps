## 2. 单台完整流程（八步）

### Step 1 到货验收（5 分钟）

- [ ] 核对机型 = **雅典娜 AX6600（RE-CS-02）**；收到"亚瑟 AX1800 Pro（RE-SS-02）"走附录 A，**物料不可混用**
- [ ] 记录台账：SN（底部标签）、MAC、到货日期、原厂系统版本（App 或后台可查）
- [ ] 通电自检：能启动、LED 正常、四个网口 + 2.5G 口有链路

### Step 2 进 9008 并刷入不死 uboot（一次性，约 20 分钟，需拆机）

> 原厂最新版本（4211+）堵了软件入口，**标准路径 = 9008 拆机短接**，不受版本影响。老版本若能开 SSH 可免拆机直接 `mtd write` 写 uboot（未在本产线验证过，不推荐量产用）。

1. 拆机，找到短接触点（参考 `雅典娜短接.png` / 教程 mhtml）
2. 短接触点 → USB 线连电脑 → 插电 → 设备管理器出现高通 9008 端口
3. 运行 `QSaharaServer.exe` 按 `USB命令.bat` 依次下发**雅典娜（文件名带 `_1_` / `Athena`）**分区文件，载入**临时 uboot**（掉电即失）
4. 电脑网卡设静态 `192.168.1.10/24`（跑 flash-net-set.ps1）
5. 浏览器开 `http://192.168.1.1/uboot.html`（**必须是 uboot.html，别开错页**）→ 上传**不死 uboot bin**（上表第 2 行）→ 蓝灯闪 → 绿灯 3 秒 → 自动重启
6. 验证不死 uboot 生效：断电 → **按住 RESET 上电** → 红灯闪到蓝灯 → 松手。成功则装回外壳（此后该台设备终身免拆机）
7. ⚠️ USB 供电别久连（教程警告 5V USB 供电易损）

### Step 3 刷 GPT 分区表（约 5 分钟）

> 不刷 GPT 直接刷 >60M 固件 = 开机红灯砖（还能救：重进 uboot 重来，但浪费时间）。

1. 按住 RESET 上电进不死 uboot（红灯闪→蓝灯）
2. 电脑静态 `192.168.1.10`，浏览器开 `http://192.168.1.1/img.html`
3. 上传 **GPT 2048M**（上表第 3 行），等约 2 分钟，长亮红灯
4. 断电 → 按 RESET 进 uboot → 进入 Step 4

### Step 4 刷 libwrt 固件（约 5 分钟）

1. 不死 uboot 状态下（同上进入），浏览器 `http://192.168.1.1`
2. 上传 **libwrt factory.bin**（上表第 1 行，刷前 `certutil` 校验 MD5）
3. 蓝灯 → 绿灯 = 写入完成；重启后 LED：红 → 灭 → 绿闪 → 蓝灯 = 系统起来了
4. 网线改插 **LAN 口**，电脑改回 DHCP（flash-net-restore.ps1），应获取 `192.168.1.x`

### Step 5 系统首验（3 分钟）

- [ ] `http://192.168.1.1` LuCI 可登录：root / password
- [ ] WAN 口接上级网络能上网（系统→网络→接口，WAN 有 IP）
- [ ] SSH（22 口）root 空密码登录 **预期失败**，属正常（用 ttyd）
- [ ] 不碰 OpenClash 插件（该固件此组件损坏，见运维档案 §5.1）

### Step 6 开通（约 15 分钟，逐步打勾；全部命令与坑见运维档案）

> 输入文件统一从 `F:\vps\scripts\` 取；`run.yaml` = 黄金模板原样拷贝（含节点与 redir-port），**不得手改**。

6.1 基础三件套（quickfile `qf_client.py` 上传 + ttyd `http://192.168.1.1:7681` 执行）：
- [ ] ttyd 输 `root` 回车进 shell，`ln -sf /etc/openclash/core/clash_meta /usr/bin/mihomo`
- [ ] 上传 `run.yaml → /etc/mihomo/run.yaml`（写后 readfile 读回校验长度）
- [ ] 上传 `mihomo_fw.sh → /etc/mihomo-fw.sh`、`mihomo_init.sh → /etc/init.d/mihomo`，ttyd `chmod 755` 两个
- [ ] `/etc/init.d/mihomo enable && start`；ttyd 验证 `wget -q -O- http://127.0.0.1:9090/version` 出 JSON（失败查 `logread -e mihomo`）

6.2 管理台注册（VPS 侧 + 管理台网页/API）：

6.3 Agent 安装（quickfile 上传 + ttyd 执行；**install-agent.sh 有三个已知坑**，绕法固定）：

- [ ] 改 root 密码（发货密码按客户约定，记台账；出厂交付默认 `root/无线贴纸密码` 按需）

## 4. 雷区清单（每条都真实踩过）

1. **机型混刷是红线**：亚瑟（RE-SS-02）与雅典娜（RE-CS-02）的 GPT、CDT/QSEE、uboot、固件互不通用；9008 分区文件按文件名 `_1_`/`Athena` 区分，拿错=变砖风险。固件选择只认 `jdcloud_re-cs-02`。
2. **不刷 GPT 直接刷 71M 固件** → 开机红灯、无 IP → 重进 uboot 刷 GPT 再刷固件即可救回，但浪费 20 分钟。
3. **uboot.html 才能刷 uboot**，首页/img.html 是刷固件和 GPT 的，页面点错"前功尽弃"。
4. **9008 供电**：USB 连接时间尽量短；短接操作轻拿轻放（主板点位见材料包图）。
5. **工位电脑开 Clash TUN**：所有"不通"假象之源，验收数据全部作废重测。
6. **OpenClash 插件**（固件内置）启动会静默卡死并改写配置，永远不要点开；代理由 mihomo 直跑方案承载。
7. **「借 IP」配置严禁上发货设备**（2026-09-18）：本工位的雅典娜上有两处仅本机使用的文件——`/etc/borrow18-ssh.nft` 和 `/etc/hotplug.d/iface/99-borrow18-ssh`（借用旧 IP 10.1.2.18 连公司 10.10.8.83 用）。它们**不在** provision 刷机流程和 agent 升级包里，正常刷机不会带上；但若从本机做整机配置备份再恢复到发货设备，必须先剔除这两个文件 + 检查 `nft list tables | grep borrow18` 为空。
7. **quickfile 三个坑**：每次调用前重登录；POST 路径 percent-encode；Git Bash 会把 `/etc` 改写成 `C:/...`（用 qf_client.py 就没事）。写完必须 readfile 读回验证。
8. **ttyd 自动化**：回车必须 `\r` 嵌在 type 里；长输出重定向 `/tmp/x.txt` 再用 quickfile 读回，别信屏幕截图。
9. **install-agent.sh 三缺陷**（busybox 无 `install`、WG uci 只写一半、引导包无 mgmt_url）——Step 6.3 的绕法已固化，上游修复前列为必踩步骤。
10. **WG 地址不复用**：设备返修/换新一律新地址，避免心跳历史与流量统计串台。

## 5. 量产化路线（建议按序投入，量产后每台开通 ≤5 分钟）

1. ✅ **`provision_router.py` 一键开通脚本（2026-09-17 已建成）**：`F:\vps\scripts\provision_router.py`
   - `python provision_router.py --check` = 体检（不动设备）；`python provision_router.py --name 雅典娜-AX6600-客户A-01` = 正式开通
   - 覆盖 Step 6 全部内容：6 文件上传（写后读回校验）→ 管理台建设备/enroll → hub 登记 peer（用引导包自带地址与私钥）→ network/openclash/firewall/agent.conf/CA 五处配置 → mihomo+routermgmt 启动（先核心后规则）→ fake-ip/出口 IP/心跳三项验收 → 台账自动追加。**零 ttyd、零手工命令**；幂等可重跑；失败即停于直连安全态
   - 已验证：语法/本地文件/VPS/SSH 隧道/管理台 TOTP 登录全通（--check 实测）；路由器侧原语（quickfile/ubus）与首台实战一致。**首次对真机跑请人在场**，重点看 chmod API 是否生效（若 `[!!]` 提示则按提示 ttyd 手工补 chmod）
2. **修复 `install-agent.sh`**（mgmt 仓库）：`install`→`cp`+`chmod`；补全 WG uci（private_key + peer 段 + listen-port）；provision 引导包写入 mgmt_url。修好后可与本脚本并存（脚本已绕开它）。
3. **`new_peer.sh`（VPS 侧）**：已并入本脚本 S3（hub_register_peer 幂等实现），单台客户设备（手机/电脑）通行证发放可再抽小工具。
4. **验收脚本 `qa_check.py`**：Step 7 的断电自验仍是人工拔电；其余项已并入 provision S6。量产后把"断电后自动复验"做成管理台告警规则（设备 3 分钟不在线即标红）更省人力。
5. **Agent 远程升级（2026-09-18 已上线）**：发货后的设备不再需要回到局域网维护——管理台设备详情页点「**升级Agent**」即可远程升级。
   - 流程：HMAC 鉴权下载升级包 → Ed25519 按设备签名验签（与配置验签同构）→ `sh -n` 语法门禁 → 备份旧文件（`/etc/routermgmt/agent-bak-*.tar.gz`）→ 原子替换 → 上报结果 → 自动重启生效；任何一步失败即停、原文件不动。
   - 服务端构建新包：改完 `F:\vps\mgmt\agent\` 下文件 → 同步到 VPS `/opt/mgmt/agent/` → 跑 `/opt/mgmt/build-agent-bundle.sh`（版本号缺省=日期时间）→ 界面点升级即发最新包。
   - **例外**：首台雅典娜（rtr-1eff66）装机时的旧 agent 不认识该任务类型，需**一次性**走局域网推送更新（qf_client 上传 2 个文件后 `routermgmt restart`）；之后所有设备（含新刷机发货的，provision 装的就是新 agent）永久远程可升级。
5. **管理台批量建设备 API** + 台账自动同步（现在建设备要走网页/provision，10 台以上值得做）。
6. 量产后考虑：固件自建（libwrt 源码把 mihomo 直跑方案预集成进镜像，Step 6.1 整段消失）。

## 附录 A：亚瑟 AX1800 Pro（RE-SS-02）差异速记
