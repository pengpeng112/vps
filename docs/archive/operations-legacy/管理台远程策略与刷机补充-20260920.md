## 1. 管理台能远程做什么（设备详情页）

全部经任务队列下发；心跳也会带完整 `policy`，漏任务或路由器重启后会自己对齐。

### 1.1 运行模式（整台怎么走网）

| 界面 | 内部值 | 效果 |
|------|--------|------|
| 策略分流 | `rule` | 国内直连、境外走 VPS（默认，发货必须是这个） |
| 全局代理 | `global` | 全部走 VPS |
| 全部直连 | `direct` | 不走 VPS |

落地：`PATCH http://127.0.0.1:9090/configs {"mode":...}`，并改 `/etc/mihomo/run.yaml` 的 `mode:`。切节点后会再打一遍。

### 1.2 访问模式（哪些设备走上面的规则）

| 界面 | 内部值 | 效果 |
|------|--------|------|
| 全部设备 | `all` | 局域网谁都按运行模式走（发货默认） |
| 白名单 | `whitelist` | **只有**名单里的 IP/MAC 走代理规则，其余直连；白名单不能空 |
| 黑名单 | `blacklist` | 名单里的设备强制直连，其余仍按运行模式 |

名单：每行一个 IPv4 或 MAC（`aa:bb:cc:dd:ee:ff`），最多 32 条。
被排除的设备 DNS 会 DNAT 到 `223.5.5.5`，避免 fake-ip 把网页卡死。
落地文件：`/etc/routermgmt/state/access.mode`、`access.list`；脚本 `/etc/routermgmt/access-fw.sh`；`mihomo-fw.sh` 重装规则后会再调用一次。

### 1.3 VPS 限速（国内不限）

只限制本机访问 VPS `:443` 的流量（代理通道）。`0` = 不限。
界面预设：不限 / 1 / 5 / 10 / 20 / 50 Mbps。
落地：nft 表 `inet vps_qos`（雅典娜）。**SN-R1 无 nft，落地为 iptables 链 `VPS_QOS`/`VPS_QOS_IN`，见《SN-R1-AX3000-记录与刷机准备-20260923.md》§6。** ipq60xx NSS 硬件加速有可能绕过 nft，家宽若发现限速不准，记到该台备注。

### 1.4 定时重启

白名单 crontab，禁止任意字符串：

- 关闭（空）
- `0 0 * * *` 每天 0 点
- `0 8 * * *` 每天 8 点
- `0 */8 * * *` 每 8 小时
- `0 */12 * * *` 每 12 小时

写入 `/etc/crontabs/root`，行尾标记 `#routermgmt-reboot`。

### 1.5 授权期限（可手改）

| 字段 | 自动 | 手改 |
|------|------|------|
| 上线时间 `first_online_at` | 第一次心跳写入，之后心跳不再覆盖 | 详情页「保存时间」 |
| 期限起算 `license_started_at` | 首次心跳；点续期会改成现在 | 同上 |
| 到期 `license_expires_at` | 续期一个月/一年；空=永久 | 清空=永久 |
| 剩余天数 | 按到期算 | 只读 |

到期或点「立即停用」：PROXY→DIRECT，并丢掉去 VPS `:443` 的包。**国内直连仍可用。** 续期后恢复。

发货时建议：管理台对该设备点 **续期一年**（或按合同月数），不要留永久（除非内部机）。

### 1.6 诊断

详情页「拉取诊断」：uptime、内存、WAN、mihomo、WG、wan-watch 尾、策略指纹、qos 规则。不替代 LuCI/ttyd。

### 1.7 WAN 分层日志（本机已装，发货也应装）

| 文件 | 作用 |
|------|------|
| `/etc/routermgmt/logs/wan-watch.log` | 每 60s 一行；`event=change` 是状态翻转 |
| `/etc/routermgmt/logs/syslog` | 系统日志落 overlay，重启不丢 |

判层：`carrier=0` 网线；`wan_ip=none` DHCP 丢了；`carrier=1` 但 `gw_ping=fail` 公司/上级把口掐了。

源文件：`F:\vps\scripts\wan_watch.sh`（已复制到 `F:\vps\mgmt\agent\wan-watch.sh`）。

### 1.8 远程开关 Wi-Fi 与经 VPS 反向 SSH（2026-09-23 新增，Agent ≥2026092320）

- **开关 Wi-Fi**：详情页「关WiFi / 开WiFi」→ `set_wifi` 任务；关闭时 agent 自动布防 **300 秒无人确认自动恢复**（cron 兜底，双机实测）。管理心跳走有线隧道不受影响。
- **经 VPS SSH 进路由器**（外网排障用，端口只绑 VPS 回环）：
  ```bash
  # 雅典娜（VPS 回环 18222）：
  ssh -J jump@159.223.36.119:28722 -p 18222 root@localhost
  # SN-R1（VPS 回环 13222）：
  ssh -J jump@159.223.36.119:28722 -p 13222 root@localhost
  # 需持 jump 入口私钥（同 Claude 跳板那把）；路由器密码见总表
  ```
  落地：两台 `/etc/init.d/mgmt-tunnel` 各加一条 `-R`；VPS 侧隧道公钥加 `permitlisten`、jump 公钥加对应 `permitopen`、`99-hardening.conf` 的 `Match User root` 由 `AllowTcpForwarding local` 改 `yes`（否则 -R 被全局拒绝——2026-09-23 实测踩坑）。
- **Agent 升级引导坑**：2026092320 之前的旧 agent 执行升级时只写 `/etc/routermgmt/routermgmt-agent.sh` 不写 `/usr/bin/routermgmt-agent`（运行的是后者）→ 首次过渡需手动 `cp /etc/routermgmt/routermgmt-agent.sh /usr/bin/routermgmt-agent` 并重启服务；新版已两处都写。

### 1.9 链路质量探针（2026-09-24，双机+VPS 常驻）

"反馈网络慢"时先看这三处数据，别猜：

| 位置 | 探什么 | 日志 |
|---|---|---|
| 每台路由器 | 国内基线（223.5.5.5）+ **到 VPS 国际段** 的丢包/延迟，每 5 分钟 | `/etc/routermgmt/logs/netprobe.log`（滚存 7 天） |
| VPS | 对照组：VPS→国际参考（8.8.8.8），区分"CN↔SG 段拥堵"还是"VPS 故障" | `/var/log/netprobe.log`（滚存 14 天） |
| 管理台 | 设备详情「拉取诊断」的 **netprobe 字段** = 最近 1 小时探针 | 一键获取，无需 SSH |

**判读**：国内 0% 且 vps 段 >5% = 晚高峰国际拥堵（普通 transit 线路常态，错峰或加优化线路节点）；国内也丢 = 上级/本地问题；VPS→intl 同时丢 = VPS 侧故障。注意 VPS 对国内方向无法真实探测（ICMP 被丢+CDN 就近解析），别在 VPS 上测国内。

新装设备 `install-agent.sh` 自动带探针；脚本源 `F:\vps\mgmt\agent\netprobe.sh`（路由器）与 VPS `/opt/mgmt/netprobe-vps.sh`。

## 5. 公司网 / 拦 UDP 时启用 TCP 管理通道

**不要改上网、不要关 WG、不要重启整机。**

在路由器上：

```sh
sh /usr/sbin/setup-mgmt-tunnel.sh
# 把打印的公钥那一行追加到 VPS：
#   /root/.ssh/authorized_keys
# 然后：
sh /usr/sbin/setup-mgmt-tunnel.sh enable
```

效果：

- 本机 `127.0.0.1:18443` → VPS `10.10.0.1:8443`（SSH 端口 28722，TCP）
- `MGMT_URL` 改为 `https://127.0.0.1:18443`
- Agent 带 `curl -k`（证书 SAN 是 10.10.0.1）
- 开机：`mgmt-tunnel` START=98，`routermgmt` START=99

本机工位已启用。公钥注释名 `rtr-1eff66-mgmt-tunnel`。

无线 SN-R1 也走同一条 TCP 隧道方式，但 dropbear 太旧，只能生成 **RSA** 密钥，不能用 ed25519。公钥注释名 `snr1-mgmt-tunnel`。完整改造清单见 `F:\vps\SN-R1-AX3000-记录与刷机准备-20260923.md`。

> **VPS 28722 防火墙口径（2026-09-23 变更）**：由 `ufw limit` 改为 `ufw allow`。原因：多台设备隧道+Claude 跳板共用一个出口 IP，limit 的 recent 模式在重试风暴下会"持续敲门=永不解封"（当天双 tunnel.bat 实例互踩导致全网锁死 40 分钟）。fail2ban 仍在。若未来恢复 limit，必须同时保证各隧道重试间隔 ≥35 秒。

## 6. 审查结论：还剩什么问题

按优先级：

1. **本机 WAN 双 IP `10.1.2.18`** — 最像「用一两天整网断」的原因（DHCP snooping / IP 冲突）。若公司 SSH 能改白名单到 `10.1.2.105`，应拆掉 `.18`。发货机无此问题。
   **🔴 拆 .18 前必读（2026-09-23 补）**：.18 现在不止服务公司 SSH——它还承载 **AI-HMS 外网 Claude 跳板通道的最后一跳**（`F:\python\前后端代码\ai-hms_qhd\docs\20260922\外网Claude跳板通道搭建需求书.md`，Claude 经 VPS 反向隧道到本机、再以 .18 白名单源连 10.10.8.84/.83）。直接拆 .18 = Claude 通道无声断掉。必须先协调公司把白名单迁到 `10.1.2.105` 并复验 Claude 通道后才能拆。
2. **WG UDP 在公司网不可用** — 已用 TCP 隧道兜底。家宽应再确认握手；若家宽也丢 UDP，按 §5。
3. **限速依赖 nft** — NSS 硬件加速可能绕过。量产若要硬限速，需在 VPS 侧按设备源 IP 限，或关该流的 NSS。
4. **`SUB_URL` 仍指向 `https://10.10.0.1:8443/sub/...`** — OpenClash 已禁用，一般无影响。若以后用订阅，公司网现场要改成走 18443。
5. **dropbear `-y` 接受未知主机钥** — 首次连 VPS 有被中间人风险；可改为预置 known_hosts。
6. **上线时间回填** — 首台 `first_online_at` 用的是 9 月 19 日最后一次心跳，不是 17 日第一次上线。详情页可手改。
7. **首台授权** — 联调曾点过「续期一年」（约到 2027-09-20）。内部机可改回永久。
8. **Agent 双份文件** — `/usr/bin/routermgmt-agent` 与 `/etc/routermgmt/routermgmt-agent.sh` 必须一起更新；`agent_update` 已改为两处都写。
9. **未做的量产项** — 每设备独立 VLESS UUID、自动故障转移、告警推送 Telegram、断电后自动复验。见原 SOP §5。

**不要做的**（会直接断网）：在电脑还走这台路由上网时切全局/直连做实验、对当前电脑 IP 下白名单、重启 `network`/`firewall`/`mihomo`、拔 WAN。诊断用「拉取诊断」或只读 SSH。
