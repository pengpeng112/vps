# 分册04：单设备日额与视频/下载限速、解封执行规格（Codex核查修订v2）

> **状态：研发/能力验证，BLOCK_ENFORCE。不能照旧版图直接上线。** 本册不是CF域名接入前置。
> 原版转述的目标参数保留：SN/GL 3GiB后视频/下载各60kbit/s，雅典娜各100kbit/s；次日北京时间00:00恢复；在线调参、临时/单类/永久/紧急解封及大象流。
> “已记录需求”与“实现/现场验收通过”分开。用户本轮要求修订计划，未要求我们现在部署限速。

## 1. 本次审查纠正的关键问题

| 原写法 | 问题与替代要求 |
|---|---|
| 本机qos-gate 100%省上游流量、零风险 | 未实现/未测；用户态TCP读侧节流可能形成反压，但QUIC/UDP、上游预取、缓冲/复用会影响实际计费，必须双侧实测 |
| listeners type: socks5 | mihomo官方listener类型为**socks**；该机实际版本解析与显式proxy出口必须单测，当前R2无此listener |
| 超额时才切入gate | selector切换不会自动改路由既有流；直接踢长连接会中断，不能称无缝 |
| 单连接>100MB就是下载 | HTTP/2/3复用可能混网页/下载，长聊天也可能累计大；多连接小文件可绕过，大小不是业务用途证明 |
| 删大流连接后自动进大象桶 | 重连后计数归零，可能无限重复前100MB全速，必须证明跨重连识别或明确该功能不可交付 |
| gate掉了才检测切入 | 已在gate时仍可能崩溃；必须有运行期旁路/释放机制 |
| 整段同一端点/全IP整形 | 不能区分网页/视频/下载，尤其共享HY2与CF，必须类/设备归属 |
| 达不到固定5MB/s就解封失败 | 解封应恢复同源同路径基线，线路本来慢不能判失败；3秒是控制动作目标，不保证网络瞬间到固定速度 |
| 每30分钟解析机场确保100% | DNS轮换/多A/AAAA/在用旧连接/跳口/重载会漏；覆盖健康必须可证明，失败observe |
| 0011/新API/agent功能像已存在 | 都是开发目标，先查当前最大迁移号/任务白名单/心跳解析链再实现，不能调用不存在接口 |

服务器分类整形并非死胡同；现有executor源码有端口方向问题须修复，不能运行验证“试试”。两条候选路线都必须先证明类隔离/解封，不升级固件或安装缺失模块来凑目标。

## 2. 参数、边界与可信计量

- 3GiB=3221225472B；计入设备代理上+下行总量，口径名“代理传输字节”，不宣称就是所有国外内容净字节。
- video/download各聚合60kbit/s=7500B/s；医院100kbit/s=12500B/s；同时两类可各占速率。普通网页、上传不因本策略变速。
- 旧版“大象流”100MB与100MiB矛盾：工程候选固定为**100MiB=104857600B**，政策字段显式bytes，不能同名mb两种口径；若用户原意十进制则按已明确的新参数调整。未知分类不能自动当下载上线。
- 国内DOWNLOAD=DIRECT保持，不把国内系统更新或整个github/Telegram共享域粗暴归入下载。FOREIGN-DL需规则样本库与独立业务验收，不因域名含cdn就判大文件。
- 医院10.1.2.18及相关内网路径先排除；雅典娜100参数保留，但专机未验前保持observe。
- 日账：meter_id+boot/continuity+seq+endpoint注册世代+day_cst+freshness+coverage健康；整数增量、原子状态、并发锁、计数回退/缺样/重启/日界分段，保留误差和未覆盖项。
- 平台日账以sample身份去重，旧样本/重试不能重复累加；设备当天累计上报不能当“本次增量”直接加总。跨日/设备重装/计量重置不能无声减账或继承别机。
- 端点来自真实活动配置+provider+运行连接，按唯一IP/协议/端口去重；域名缓存保留TTL/多地址/在用旧地址；IPv6/跳口无覆盖则coverage降级。切CF域名但edge相同不能重复计数，也不能按edge独立计源站。
- 当前R2 v3有过真实入账，但本次所列端点与v39新增GIA/CF不一致，须新鲜完整对账，不能靠旧PASS放行。

## 3. 两种实现路线与选择门

**A：路由器用户态gate（候选）**，可用于无需服务端身份改造的场景，但必须完成以下证明才选为生产：

1. 隔离环境和R2临时独立实例验证listener type=socks、listen=127.0.0.1、明确proxy指向AUTO且不重新过业务rules。
2. 拓扑无递归：业务类→gate→专用回环上游→真实代理；上游AUTO/NODE-PICK/AIRPORT不得反引用gate或业务组。递归检测、连接深度/超时、管理流隔离。
3. SOCKS5域名/IPv4/IPv6、错误码、认证、半关闭、取消、超时均正确，目标域名不能退化为污染IP。只监听回环，控制接口也需本地权限。
4. TCP双向读写分离：仅下行聚合令牌桶；上传无人工限速；限最大读取预取/写缓冲，令牌等待可被解封/取消立即唤醒，不能持大锁阻塞所有连接。
5. UDP ASSOCIATE/QUIC是否真实支持独立证明。TCP-only阶段只能标TCP能力；不得把UDP silently DIRECT或排除计量后称完成。不为通过测试临时全局禁UDP改变游戏；若仅受限类QUIC降级，需明确范围、客户端回退与原有UDP443规则的关系并验收。
6. 若超额后才改selector，对既有连接只能明确“维持原路/逐条受控重连/从起初常驻gate可在线变桶”等设计取舍。不承诺无缝接管已有连接；不批量DELETE /connections，不打断管理/游戏/普通网页。
7. gate崩溃、配置损坏、控制器失联、路由器重启/日界异常时进入安全observe/恢复已记录基线路径，有独立看门狗和持续紧急锁。旁路不得降成DIRECT泄漏原代理业务。
8. 对实际CPU/架构/ABI/固件编译；不只uname -m就盲选GOARCH，检查endianness、MIPS softfloat等。无Go标准库2.5MB/3MB固定承诺，测ELF/峰值RSS/CPU/并发/FD，资源不足不部署。
9. 双侧采样验证客户端受限时上游长期字节增量真的下降，区分预取/突发/重传/协议开销；不能仅靠客户端下载慢推定省供应商流量。

**B：服务器侧按设备/业务独立身份整形（保留）**：沿既有主手册K工作包，修复方向与对象归属，独立video/download通道/每设备标记、双端协调/解封/幂等/跨端补偿。共享NAT站点IP、同一HY2端点或整个CF边缘60kbit不满足分类，不覆盖共享root。

**决策门**：先产出A/B能力矩阵、限制与测试证据，再选该设备路线；不能把A未经验证当“彻底解决”并删除B，也不要求本次CF域名等待选型。

## 4. 持久策略与解封状态机（沿用已审查约束）

策略有不可变policy_version、device_id、release_generation、expected_version/CAS、request_id幂等、原子锁。速率/阈值单位和界限校验，manual/exempt与时间字段明确，不以空值回默认60重限。

状态至少observe/normal/throttled/exempt/emergency，实际状态与期望状态分别报告。
紧急释放：**先原子持久化模式emergency/代际，再解除本人对象并验证**；同代普通apply、旧任务/迟到定时器、重启不得复活限制，只有显式resume携新代际可重新启用。
单类解封仅释放该类，保留另类；单台解封/永久豁免/限时豁免范围不能混。解封保留账本，不清配额。

次日00:00只重置合法日窗口的**自动配额动作**，不撤销长期豁免、手工紧急锁；时钟回拨/不同步进入observe。限时豁免到期是否自动恢复，由政策明确，不能由午夜脚本覆盖人工决定。

新API/agent任务要完整实现鉴权、任务白名单、签名与幂等、单设备身份、超时/补偿、UI真实有效状态、审计脱敏；迁移号先查现势，不硬写0011。默认qos_mode=observe，生产库更新/agent升级分别遵守SOP。

## 5. 一次研发批次的交付顺序

1. 先读旧主手册、11-17整改包与当前脚本，按哈希核对已经修好的内容；不再复活disabled旧脚本，也不把新v2“本地全绿”当现网通过。
2. 本地实现：可信计量补覆盖/去重、状态机/持久锁、A/B最小可行验证、实际配置渲染/防环路测试。
3. 隔离模拟矩阵全部通过，数据库测试只用隔离库；保留测试输入/期待/实际值/退出码与mock边界。
4. R2只计量先观察，完整拓扑与跨零点验证；现有观察若发生断点/覆盖改变，记录新窗口和历史未知段，不能补写虚假流量。
5. 授权试点窗口：先完整释放/紧急/重启拒旧任务，再以专用64—128KiB流测实际60，不改真实日账凑阈值。窗口至少60秒，多次/多并发，注明burst，普通网页/上传/国内受保护路径与基线比较。
6. 准备自动限制：可信观察24—48h、分类和双协议覆盖、已验证远程/本地解封、跨日、真实业务验收齐全；首次正式enforce仍仅R2。
7. R2正式enforce稳定48h且解封/现场验收通过，在线SN串行。GL离线、医院专项未验则明确待办，不“全舰队全绿”。
