### 4.1 精确改什么

**不要**改为整个 qq.com 或所有国内域名；不要关闭 fake-ip 全局模式；不要手改设备 mihomo YAML；不要清空 mihomo cache.db；不要改 WiFi/密码/主机 LAN 网段。

### 4.2 使用参考脚本

文件：`review/fleet-game-dns-reference-20261116.sh`。

- 默认 `check`，不改配置、不重载。已在 R2/R9/雅典娜以 check 模式验证解析格式兼容；shell 语法检查通过。
- `apply` 需要 **预期 device_id + 明确 apply + 修改前 DHCP SHA-256** 三项。脚本核对设备身份、无待提交 UCI、原默认上游、并发哈希，备份后只追加缺少的规则、commit、重载 dnsmasq。
- 写入分支包含失败回退，但本轮没有在其余设备生产执行过；R2 是必要的写入试点，不可以跳过试点直接循环。
- 脚本没有现场客户端验收能力。`APPLIED` 只代表路由侧配置验收通过。

调用方式：由本机读取脚本文本，设备端只通过 `sh -s` 执行 UCI 命令；不是 echo/base64 推送配置文件。

```python
# gz 已按受控凭据建立 SSHClient；dev_pw 从对应设备台账读取，不打印。
chan = gz.get_transport().open_channel(
    'direct-tcpip', ('127.0.0.1', rssh_port), ('127.0.0.1', 0))
# 建设备 SSHClient，连接 chan。不要直接公网登录设备。

# 第一次只读：
command = 'sh -s -- ' + device_id + ' check'
# device_id 必须来自上表的固定允许列表，不能接受任意 shell 字符串。
stdin, stdout, stderr = dev.exec_command(command, timeout=120)
stdin.channel.sendall(script_text.encode('utf-8'))
stdin.channel.shutdown_write()
# 读取并保存脱敏输出、exit status。check 的 CHECK_NEEDS_DNS_FIX 是诊断结果。

# 先备份 DHCP 到本机受控 backups，再取当前 SHA；确保与 check 输出一致。
# 第二次由已授权执行者调用；expected_sha 必须为刚读到的64位小写十六进制：
command = 'sh -s -- ' + device_id + ' apply ' + expected_sha
# 仍用上面的 stdin 方式。必须确认 exit=0 且 APPLIED 或 ALREADY_APPLIED_NO_RELOAD。
```

不要从 shell 里 `$(cat agent.conf)` 或整段 `source` 后输出环境。设备 SSH 日志不能回显密码。

### 4.3 逐台顺序与验收

顺序：R2 → R3 → R4 → R5 → R6 → R8 → R1 → GL → 雅典娜。R9 只跑 check；离线设备跳过并登记。

每台必须完成：

2. 向 LAN 网关:53 查询 gpp 与四个已确认服务，均有真实 A 记录且没有 198.18/16。不能只测试 `dig @223.5.5.5`，那绕过了待修路径。
3. 一个普通域名仍沿原设计解析；原默认 1053 上游保留。
4. 管理 health=200、目标反向口重新实登；至少两个心跳推进，≤90s。
5. 无线、mihomo YAML/run.yaml、tunnel.conf、self-heal 的哈希未变；无 UCI 待提交。不要检查密码内容来证明“未变”。

### 4.4 已知覆盖边界

本修复处理电脑使用路由器 dnsmasq:53 的路径。外部 DNS 请求被现有规则直接重定向到 mihomo:1053，不经过这个域名分流；应用内 DoH 也属于不同路径。

如果仍失败，先看 DNS 请求发往哪里，不要反复添加相同规则。更通用的后续方案是平台支持按设备 fake-ip-filter，或统一完整 UDP TPROXY/TUN；这两者均需另外设计、试点和回退，不能在本批直接更换全局 DNS/防火墙。

### 4.5 回退

先确认 DHCP 当前哈希仍是本次记录的 after_sha；若已被别人修改，停下对比，不能覆盖。

```sh
# BACKUP 是该台脚本 APPLIED 输出的绝对路径，不是另一台的路径。
cp -p "$BACKUP" /etc/config/dhcp
/etc/init.d/dnsmasq reload
```

复查 before_sha、DNS、心跳。脚本若输出回退失败，不能继续下一台；设备仍可 SSH 时先恢复备份并检查服务。不要断电。

## 5. P1：本周期 GIA 额度保护与路径修正

### 5.1 先核实额度，不要换个出口继续耗空

- GIA 12:10 网卡累计 848.854GB=790.557GiB；原档案 820GB、交接 828GB。**供应商面板的额度单位、计费方向、周期起止/重置日期尚未验证**。
- BWG 档案写每月 1TB，当前剩余未验证；机场余量/到期同样未验证。要求用户或已授权账号提供实际面板值，记录时间和单位，不能把备用当无限流量。
- 没有面板时可以修 DNS、部署纯计量和准备配置，但不能承诺某日恢复/某条备用足够扛整月。
- GIA 的 VLESS、HY2、CF 源站都吃同一服务器额度。切 CF 不是流量预算层面的独立出口。

### 5.2 两个重要错误

1. PROXY 切 BWG 不会同时改变 US-MEDIA。当前 US-MEDIA 是 **Fallback**，不是 Selector，不能盲发 `PUT /proxies/US-MEDIA {name:AIRPORT}`。PROXY 当前也没有 AIRPORT 成员，不能对不存在成员 PUT 后忽略 400。
2. 小包健康不代表可用带宽；当前 NODE-PICK 仍把 GIA 看作可用。因此“自动 fallback 会帮忙绕开额度限速”不成立。

### 5.3 推荐的本周期临时方案：单设备只发布额度安全节点集合

在备用额度、实际可用性确认后，SN/GL 单设备临时保留：**节点8 BWG-HY2 为唯一 primary + 节点4 BWG-VLESS 备用**；平台已配置的机场组仍可作为其后备，但必须单独验真。暂时不渲染 GIA7/GIA9/CF10/11/EDGE12/13，避免视频组或回退又绕回 GIA。

这是临时减少本周期出口集合，不是删除全局节点，也不是停止 GIA SSH/管理中继。恢复周期后依据保存的绑定逐台恢复、发布新版本，不能降低版本水位。

**不要修改 nodes 全局 enabled 来处理单台额度；不要删除节点表；不要停 GIA 的 SSH/管理中继服务。**

### 5.5 旧连接与异常回退

切组不等于把现存连接迁到新出口。读取 `/connections`，只在内存筛选 chains 确实含 GIA/CF 的连接，核对是否为非关键残留流量。需要断开时只按具体连接 ID 处理并给现场窗口；**禁止 DELETE /connections 清全部连接**。

### 5.6 雅典娜与机场的边界

- 雅典娜当前普通代理已在 BWG；没有独立视频组和机场组。保留该钉选，本批不套 SN 平台发布。若要改其 fallback 集合，按独立 run.yaml 的受控备份、结构化编辑、`mihomo -t -d <真实home> -f <候选文件>`、已核实的空 body PUT /configs 热加载流程单独执行；禁止手工 sed 拼 YAML，禁止将 SN 模板覆盖过去。
- 机场余量和真实流量测试通过后，才安排 US-MEDIA 的机场优先方案。其渲染位置在 `internal/clash/template.go`，目前 append NODE-PICK 后才 append AIRPORT；需要源码和平台发布，不能假装运行时 PUT 改好了 Fallback 成员顺序。
- 机场全不可用/余额不足时，保留 BWG 业务路径并告警。不能为了省 GIA 自动切 DIRECT，造成国外业务全断。

## 6. P2：先建立可信、可分设备的计量

### 6.1 三本账分开

1. **供应商账单**：额度、单位、计费方向、周期起止，以面板为准。
2. **服务器物理网卡账**：vnstat JSON 原始字节，包含代理两条腿、管理、协议开销、重传及其他流量；用于总量对账。
3. **每设备代理链路账**：仅该路由器与实际代理端点之间的双向字节；国内 DIRECT/SSH 不计。这个口径用于本文设备预算，不与网卡总量直接相加。

现有 metrics 是活跃连接快照，不是单调累计；禁止用它作为自动封禁的唯一依据，也不能用“×10”把缺口平均摊给设备。

### 6.2 第一阶段：GIA 服务器只加计数，不限流

GIA 实测支持 nft v1.0.9，eth0 当前 root qdisc 是 fq。**不要为了计量替换 qdisc，不要 reload 整套防火墙。** 新建独立 nft 表，只做 INPUT/OUTPUT 计数，不加 DROP/REJECT，不改现有规则。

1. 每台从直连国内 IP 回显服务确认当前公网 NAT IP，记录时间；与 GIA 接入日志交叉核对。多台共用一个公网 IP 时只能归为组，禁止冒称单台精确。
2. 枚举本服务器实际代理端口：TCP443、UDP34568、TCP2053。SSH22/28722 不匹配。
3. 使用自有新表名 `gia_usage_meter`，存在则先读其归属，不能 delete 别人的同名表。文件仅写规则和站点别名/IP，不含服务凭据。
4. 规则示意（必须将占位 IP 换成刚核实的值；执行前 `nft -c -f`）：

```nft
table inet gia_usage_meter {
  counter r6_up {}
  counter r6_down {}
  counter cf_up_shared {}
  counter cf_down_shared {}
  chain input {
    type filter hook input priority -5; policy accept;
    ip saddr <R6_PUBLIC_IPV4> tcp dport 443 counter name r6_up
    ip saddr <R6_PUBLIC_IPV4> udp dport 34568 counter name r6_up
    tcp dport 2053 counter name cf_up_shared
  }
  chain output {
    type filter hook output priority -5; policy accept;
    ip daddr <R6_PUBLIC_IPV4> tcp sport 443 counter name r6_down
    ip daddr <R6_PUBLIC_IPV4> udp sport 34568 counter name r6_down
    tcp sport 2053 counter name cf_down_shared
  }
}
```

5. 以同一模式给已验证来源加入命名计数器。CF 回源只有 CF 地址可见，先放 shared 桶，不伪分摊给设备；未映射来源也保留 unknown 桶/残差，不能丢弃。
6. 命名计数器读取 `nft -j list table inet gia_usage_meter`，每分钟采样，持久保存每日/周期增量和采样时间。不要每轮 reset counter。计数器下降、重建、boot_id 变化时记录 discontinuity，仅重建基线，不算负流量、不把缺数据当 0。
7. 每 5 分钟落盘，重启前尽可能 checkpoint；写入用临时文件+原子替换，限制大小、轮转日志，不写原始访问正文。
8. 对账仅比较可比较口径：这些计数是客户端链路一条腿；网卡总账还含目标站点那条腿。不能要求本表合计直接等于 vnstat rx+tx。
9. 只读观察至少 24 小时，验证低负载、计数增长、没有覆盖管理端口。回退仅删除自己新建的 meter 表，现有防火墙不动。

这能从部署时刻开始改善直接入站的归属，**不能修复过去缺失的历史数据**。

### 6.3 第二阶段：路由器按代理端点计量（覆盖 BWG/机场）

以实际选中的代理公网 **IP+协议+端口** 为匹配元组，从路由器本机 OUTPUT/INPUT 单调字节计数采集；不要拿整个 WAN 当国外流量。记录每设备/每提供方/每周期的持久字节账。

| 端点类别 | IPv4 | 协议/端口 | 预算归属 |
|---|---|---|---|
| GIA VLESS | 154.36.139.155 | TCP443 | GIA |
| GIA HY2 | 同上 | UDP34568 | GIA |
| CF1/CF2 | 104.18.32.7 / 162.159.135.42 | TCP2053；EDGE 可能443 | 当前源站 GIA，仍计 GIA |
| BWG VLESS | 74.82.193.113 | TCP443 | BWG |
| BWG HY2 | 同上 | UDP34567 | BWG |
| AIRPORT | 动态解析，不写死 | 由有效 provider 读取，不假设443 | 机场独立账 |

端点表从已渲染配置/有效 provider 在受控内存中提取，仅输出 IP/协议/端口，不输出 password/UUID/订阅 URL。DNS 变化时同时覆盖新旧连接，等旧连接结束再移除旧端点。

共享端点、IPv6、链式代理、CF 源站变更、管理隧道同 IP 不同端口都要定义清楚。未识别流量进 unknown 并告警，不能静默漏计。单一公网 IP 上的 SSH/WireGuard 不能因 IP 匹配就被算入代理账。

长期若需要精确到认证用户，另行设计每设备独立代理身份及服务端持久统计；不在本批直接换共享 UUID/密钥。

## 7. P3：建议限速和预算（待引擎修复后试运行）

### 7.1 数值定义

- 表中为初始试运行建议，不是认定谁滥用。医院业务先由负责人确认后才启用限制，默认只告警。

**限速不等于限额**：3Mbit/s 持续 30 天单方向就能传约 972GB，远超单台月预算；因此必须配合计量、告警和出口预算控制。

### 7.2 明确禁止直接使用旧功能当作完成

`POST /devices/<id>/ops {type:set_ratelimit,params:{kbps:3000}}` 在现实现中只覆盖一个 IP 的 TCP443，且只有一个上下对称值，**不能表达上表的上下行不同值**。不要直接调用后写“3000/1000已生效”。

需要修改的代码位置：

- `mgmt/agent/handlers/switch_node.sh:apply_vps_qos*`：端点与协议覆盖、返回值、真实内核执行结果。
- `apply_policy_fields` / `task_apply_policy`：任何限速命令失败必须任务 failed，不能写成功 policy.fp；完整事务恢复其他 policy。
- `mgmt/backend/internal/httpserver/policy.go`、`configs.go`、models/migration：若加入非对称上下行和多端点策略，必须明确定义字段及向后兼容；旧的单字段不能暗改单位。
- 计量与月预算不能继续消费 `/connections` 活跃快照正差作为精确用量。

### 7.3 推荐限速实现：代理端点分类 + 排队整形

优先采用 tc 的 HTB/TBF 排队，避免以大量 DROP 制造 TCP/QUIC 重传、反而浪费额度。

**SN 试点设计：**

1. 根据 `ip -4 route show default` 和 ubus 识别真实 L3 WAN，不能假定永远叫 eth0。记录原 qdisc/filter/link 状态。
2. 本轮 SN 的 wan root 为 noqueue，tc 可执行；GL 的物理网卡为 mq，GIA 的 eth0 为 fq，**不得统一覆盖**。有既有 SQM/HTB/自定义过滤器时停止，另做集成。
3. 上传：在实际 WAN egress 创建自有 classful 整形；仅上述代理元组分类到受限类。未分类默认类保持线路自然容量，管理/国内不进入受限类。
4. 下载：WAN ingress 仅把代理端点来源元组 redirect 到自有 IFB，在 IFB 上整体 TBF/HTB；其余 ingress 不重定向。必须有相应内核模块且规则实际命中，不能静默回退成全 WAN 限速。
5. 所有代理端点汇入同一个上行/下行设备预算类；不能给每个端点各一个3000，否则并发多个节点会叠加。
6. 机场真实端口、IPv6、动态 IP、现存旧连接要覆盖。若无法覆盖，标记不支持，不能宣称“全部国外代理已限速”。
7. 本地硬件/软件 offload 可能绕过分类，必须看实际计数与吞吐；禁止为省事全局关闭业务 offload 后不评估影响。
8. 不触碰 WiFi qdisc、br-lan 根队列、广州 SSH 的 TCP28722/22、管理反向口/WG 流量。不要在 GIA eth0 随手 `tc qdisc replace root`，那会作用于所有业务。

**实现细节要求给编码 AI：**

- 配置输入是经过校验的 JSON/结构化参数，禁止 eval/把节点名当 shell 片段。
- 创建自有 IFB/handle 前查归属；已存在且非本方案创建则拒绝覆盖。
- apply 做 preflight→备份→临时自动回退→内核规则→命中/吞吐验收→提交；失败只移除自有对象，恢复原队列和策略。
- 回退必须可在原 SSH 会话中执行且另开会话实登；不把重启整个路由器当恢复方案。
- 持久化采用 procd/受控 init 和平台 policy；重启、WAN DHCP变化、节点切换、provider更新都必须重新对拍端点，不依赖一次性内存命令。
- 不直接复制本文数值到旧的 hashlimit 代码伪装为 tc。若临时只能提供 policer，必须明确降级、限定试点、记录重传/业务影响，经用户接受后才执行。

### 7.4 限速试点验收矩阵（必须先通过）

先在隔离环境验证分类，再在 R2 单台小流量试点。每项测试保留实际规则、计数和测量结果，不能只做脚本字符串断言。

| 测试 | 预期 |
|---|---|
| BWG-HY2 UDP34567 | 命中同一代理类，达到配置的总速率上限 |
| BWG-VLESS TCP443 | 同上 |
| GIA TCP443 / UDP34568 | 在允许测试窗口分别命中；不因协议变化绕过 |
| CF TCP2053 / 实际 EDGE443 | 命中，预算仍归当前源站 |
| 机场非443端口 | 命中，证明没有写死端口443 |
| 同时两条代理连接 | 合计不超过设备上限，不能各拿满一份 |
| 国内直连下载 | 不进入代理受限类，速度无明显人为下降 |
| 广州管理 SSH / 心跳 | 不命中受限类、无断连、两个心跳推进 |
| LOL 国内 UDP | 不命中代理受限类，训练模式可操作 |
| 内核规则故意不支持 | apply 返回失败并回退，不能 task ok |
| WAN IP变化/重启/节点换IP | 策略恢复，计量连续性断点正确处理 |
| 回退 | 只撤自有对象，原服务、DNS例外、无线状态保持 |

测速不要使用大文件刷掉剩余额度。用经批准的小数据集与并发窗口，例如 2—4MiB；达上限的测量必须分清 kbit/s、Mbit/s、KiB/s，并记录窗口和重传。测试未覆盖的协议/机型不铺开。

## 8. 告警与自动处置规则

先用可信计数观察 24—48 小时，再开放自动动作。建议默认：

- 单设备小时代理字节：普通站点 0.5GiB 告警；医院可设2GiB，仅通知。来源必须是新代理计量，不是现有 WAN 小时字段。
- 单设备日告警/迁移阈值见表；月预算70%预警、90%停止新增 GIA 业务并迁往已验证有余量的备用，原已用量保留。
- GIA 总账按供应商确认的计费口径，70%预警、80%开始主动分流、90%仅保留经批准的关键业务。未确认账单单位/周期前不启用自动硬动作。
- 动作优先级：告警→限制非关键批量下载的并发/速率→迁移至独立有余量出口→人工复核。**不默认切 DIRECT，不默认断医院上传，不处罚国内流量。**
- 每设备锁、连续两次采样达到阈值才动作、15分钟冷却、每日自动迁移次数上限2；样本过期/unknown比例高时只告警。
- 退出限流/恢复 GIA 需要滞回和人工窗口：额度重置有供应商证据、实际小下载健康、备用仍保留，不能仅“日期到了”自动 PUT AUTO。
- 告警 webhook 未配置时，平台 alerts/审计仍需可见；明确“本地告警已生成/外部推送未送达”。不能把 webhook 缺失当作假装通知成功。
- 临时借用现有 `traffic_alert_hourly_mb` 时，必须把它称作“WAN 下行粗告警”，只辅助观察，绝不驱动国外配额封禁。

## 9. P4：无线优化逐台处理，不批量套参数

### 9.1 先判断是否真的在提供无线

- R2/R5/R6/R8 现为有意关闭，不为“保证正常”而打开。
- R1/R3/R4/R9/GL/雅典娜为开启设备。先核对运行接口、关联客户端、客户端信号与实际信道；接口 RX CRC 包含环境，不等于用户丢包。
- `iwpriv ra0 get_mac_table` 在 R9 用户态工具报过段错误，不再使用；SN 可用 `stainfo`，GL/雅典娜按实际驱动用 `iw dev <if> station dump` 等兼容读法。空表也可能是工具不兼容，不能贸然断言没有客户端。
- 不在用户游戏中做 SiteSurvey、wifi reload、信道切换或5G结构试验。

### 9.2 判断与修改流程

1. 现场给出复现电脑，记录至少10分钟电脑→网关、网关→上级网关的对照；保存精确故障时刻。单个路由器自 ping 国内网站不能验收 WiFi。
2. 有证据后，在用户知情的窗口扫描现场信道；2.4G 优先比较1/6/11与20MHz，按占用选择，不是全舰队一律信道1。
3. 5G 优先让支持的终端使用现有稳定5G；R1的64、R3/R4的56涉及DFS，需要看雷达日志才能归因。不要未经频段/地区校验强制某信道。
4. SN/JCG 配置可能由 dat 重建 UCI：必须备份 `/etc/config/wireless` 和整个实际 dat 目录到**持久**位置并校验；不要只放 /tmp。
5. 尽量通过已验证的原厂面板完整保存射频参数；若面板/映射逻辑不明就停止该无线阶段，不手改分号数组、vif结构或整份dat。备份本身不保证错误dat可自动恢复。
6. R9仍是UCI信道1、dat=0;0、实际信道3，**持久固定信道问题未修**。不要为了验证而主动整机reboot；等自然重启后再查三者及业务。
7. 无线改动安排一次明确断连窗口，改后检查管理、客户端重新关联、DNS、国内/国外和实际对局；不过关恢复本台备份，禁止继续下一台。
8. GL不套JCG dat方案；雅典娜不套SN iptables方案。5G AP已工作与实际用户能连、能稳定使用是不同验收项。
