### C. 本地实现和隔离验证（现在就能做，无需等观察期）

1. 用途隔离：节点/派生实例具有显式ordinary/video/download用途或等价可靠映射；R2 feature flag；普通PROXY/NODE-PICK/AUTO/订阅下载不引用BULK。非试点设备渲染保持兼容。
2. 明确分类清单与设备身份，video/download各类多连接聚合独立60，不能共一个不可拆分隧道/桶；原国内/DIRECT/管理/医院/游戏优先保留。
3. 实现proxy-meter v2：覆盖、全量整数样本、boot/continuity/seq、零与失败区分、锁/原子提交、持久日账、端点更新/排空、时钟/缺样/满盘/留存健康；不中途清旧账。
4. 实现控制器默认status/dry-run、preview、版本CAS、幂等、持久override、审计和跨端补偿；服务器凭据不下发R2。
5. 实现设备与承载服务器的独立status/release/emergency，登记真实绝对路径、哈希、输入schema和返回码；不能只写拟建名字。
6. 隔离测试覆盖阈值±1B/恰等、旧/超前世代、单类解除、重复/乱序、计数重建、跨午夜、并发、满盘/中断、控制面失联、旧watchdog和重启。

### D. 合格后部署“只计量”，开始真正的观察窗口

1. 实现/测试通过后，按对应授权只给R2迁移计量；先备份脚本/cron/state/自有规则/原始计数和哈希。
2. 新meter_id/continuity起基线，保留旧数据与切换时刻；影子对比不能双加，旧有缺口不伪补。
3. 计数专用对象，不改路由/队列、不drop；验证所有实际启用端点双向，失败明确健康错误。
4. 单独修GIA原gia_usage_meter的互斥桶与采样器；正确归属CF共享、客户端腿和unknown，BULK子账独立，不相加驱动R2全部配额。
5. 从覆盖、连续性和健康均合格的时刻起观察24—48h，报告UTC与上海起止、缺样、跨日/重启与period_complete。旧v1已经运行多久都不能代替。

### E. 同步解决BULK部署的真实阻断

- BWG需有效受控管理入口，隧道relay key不自动等于root交互管理；不循环试密/擅改认证/擅重置root。缺入口时继续本地开发，生产BWG步骤保持阻断。
- 不因BWG管理阻塞就默认切回GIA。GIA正式承载资格/预算/质量和维护范围需明确，不按日期或只凭服务active推定。
- 服务器优先隔离BULK路径整形；共享WAN root替换另案，不能“默认全速类”冒充零影响。
- 两类/多提供方预算与长连接须有明确设计；rate与ceil均正确，上传仍unchanged。单服务器实验不能外推BWG/全舰队。

### F. 最后才是60kbit/s试验与正式日阈值

顺序必须是：可信计量观察合格＋用途隔离/服务器就绪＋双端紧急解封已演练 → 专用测试流C3 → 撤测试动作验恢复 → 完整激活单/现场可用 → R2正式D。

首轮64—128KiB，限时/限字节/限重试，记录基准/实际路径/rate-ceil/burst/类计数与普通网页对照；不强求应用载荷恰好7500B/s。500KB约67秒的预算需另设外部时限，不能塞进同步配置watchdog。

R2初始下行60kbit/s保留，不重复问单位；action=3GiB按已有授权填写完整激活单，warn及其他候选不能自行当已批准。hard与自动迁移默认关闭，不偷偷加上传限制。

只有R2正式enforce稳定48h且现场/单类解封/故障恢复通过，才讨论其他设备推广。其他设备视频出口止损是独立维护事项，可另按授权安排，不等待整个限速项目。
