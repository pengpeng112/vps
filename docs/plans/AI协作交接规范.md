# AI 协作交接规范

修订：2026-10-02。适用于不同开发工具和模型交替接手同一任务；它是文档约定，不是生产任务队列或自动授权。

## 接手

先读 [共用入口](../AI协作入口.md)、[当前状态](../current/当前状态.md)顶部、[索引](../INDEX.md)和用户指定计划。检查 `git status --short` 与相关文件内容，识别其他会话留下的未提交改动；不因旧记录写“下一步”而执行。任务若涉及现网，先确认读取或诊断命令的副作用与授权边界。

## 记录位置

| 信息 | 放置位置 |
|---|---|
| 经核验的现网概况与冲突修正 | `docs/current/当前状态.md` 顶部，写时间和来源 |
| 某任务的过程、检查点、剩余工作 | 对应 `docs/plans/` 计划或执行记录；新任务可用 `主题-YYYYMMDD.md` |
| 一次性测试结果、报告、证据 | `docs/reports/`，保留采集时点 |
| 稳定操作步骤 | `docs/operations/`，引用当前状态，不复制易变拓扑 |
| 旧计划与旧脚本 | `docs/archive/`、`scripts/archive/`，路径映射写 manifest |

交接最少记录：任务目标与本轮授权；已完成的具体文件/操作；证据与验证时间；未验证项、阻塞和影响；**下一条精确动作**；负责会话或工具、日期。区分“已做”“计划”“建议”。示例：

```text
任务：文档入口修正｜工具：〔名称〕｜时间：〔本地时间〕
完成：〔文件及变更〕
证据：〔命令/报告/采集时点；不能复核则写未验证〕
未验证/阻塞：〔具体缺口〕
下一步：〔明确到文件、命令或待用户决策的事项〕
```

同一任务优先更新其既有执行记录，避免每个模型另起一份互相矛盾的“最终总结”。若多个会话并行，先按文件划分负责人；合并前复查差异与链接。不要复制密钥、密码、token、完整 DSN、设备身份或业务原文到交接记录。
