## 背景根因（实测数据，2026-11-16 09:48）

1. 无线：2.4G 信道 auto（RADIO2G.channel='0'）自动跳频致断连；5G 被禁用（rax0.disabled='1'）；2.4G 实测 **Rx CRC 错误率 93.5%、Tx 失败率 36.3%**（信道极度拥挤）；实际速率被降到 MCS5/BW20。
2. LOL 延迟：游戏流量走 DIRECT（路由正确，qq.com 直连 23ms）——延迟大全是无线丢包重传造成的瞬时飙升。**修无线即修游戏**。
3. 隧道风暴：tunnel.conf 里 BWG 备用端点是死 IP（74.82.203.175，现役=74.82.193.113），每秒重连失败刷屏（load 1.05 主因）。

## 红线（执行 AI 必须遵守）

- **禁 reboot**（除非进入"硬恢复"分支）
- **禁动**：mihomo 配置、主端点（广州/GIA）、agent.conf、self-heal、cron
- **禁从设备 WiFi 侧操作**（全程 13231）
- 改 dat 前**必须备份 + 放开写权限**（JCG 高危坑：断电/写坏 dat 坏闪存——AGENTS.md X11）
- 无线 reload 会断 WiFi 客户端 **10-60 秒**：提前告知现场（客户端自动重连，无需手动）
- 每阶段完成即验证心跳（`广州库 last_heartbeat_at ≤90s`）——心跳断=远程失联前兆，立即回退

## 阶段 2：无线优化（核心，15 分钟，WiFi 断连窗口 ≤60 秒）

### 2.1 扫描选信道（只读）

```bash
# 2.4G 周边占用（选 1/6/11 中 Bss 数最少、信号最弱的）
iwpriv ra0 set SiteSurvey=1
sleep 3
iwpriv ra0 get_site_survey 2>/dev/null | awk 'NR<=2 || $3 ~ /^[0-9]+$/' | sort -k3 -n | head -30
# 记录：各信道 BSS 数与最强 RSSI。选目标 CH2G（1/6/11 择优）
# 5G 同理（若 rax0 可扫）——默认目标 CH5G=149（或 36，取扫描干净者）
```

### 2.2 UCI 修改（设备层 channel 固定 + 5G 开启）

```bash
# 2.4G：固定信道（用 2.1 选出的，示例 6）
uci set wireless.RADIO2G.channel='6'
# 5G：开启 + 固定信道 + 独立 SSID（游戏设备连这个，密码同舰队值从凭证总览读）
uci set wireless.RADIO5G.channel='149'
uci set wireless.rax0.disabled='0'
uci set wireless.rax0.ssid='109-5G'
uci set wireless.rax0.encryption='psk-mixed'
uci set wireless.rax0.encryptmode='TKIPAES'
uci commit wireless
```

### 2.3 dat 层同步（JCG 关键坑：开机 wifi 会用 dat 覆盖 UCI，不同步=重启回滚）

```bash
DATFILE=$(ls /etc/wireless/mediatek/*.dat 2>/dev/null | head -1)   # 找到实际 dat
[ -n "$DATFILE" ] && {
  chattr -i "$DATFILE" 2>/dev/null; chmod 644 "$DATFILE"
  sed -i "s/^Channel=.*/Channel=6/" "$DATFILE"          # 2.4G，与 UCI 一致
  grep -i "^Channel" "$DATFILE"                          # 验证
  # 若 dat 内含 5G 段（第二 radio）：同样把 5G Channel 改 149；结构不明则 cat 全文比对
}
```

### 2.4 生效（断连窗口开始）

```bash
wifi reload 2>/dev/null || { wifi down; sleep 2; wifi up; }
sleep 20
# 验证无线起来
ifconfig ra0 | head -1; ifconfig rax0 | head -1          # 两个接口 RUNNING
iwpriv ra0 stat | grep -E 'Channel|Last T' 2>/dev/null || iwconfig ra0 2>/dev/null | grep -i channel
# 客户端会自动重连；游戏设备手动连一次 109-5G
```

**验证**：ra0/rax0 均 RUNNING；信道=固定值；现场反馈手机连上且能上网。
**失败分支 A（WiFi 起不来）**：`cp /etc/config/wireless.bak-20261116 /etc/config/wireless && wifi reload`——回到改前。
**失败分支 B（dat 改坏导致无线服务异常）**：`cp -a /etc/wireless/mediatek.bak-20261116/* /etc/wireless/mediatek/ && wifi reload`。

### 2.5 硬保障确认（不主动 reboot）

- 00:00 cron 自动重启存在（`crontab -l | grep reboot`）——重启后 dat/UCI 一致性自然验证；**次日检查信道是否保持**。
- 若次日回滚：重复 2.3（dat 未改对字段，cat 全文找 5G 段）。

### 5G 开启失败原因与决策（重要）

dat 的 vif 结构里 **5G AP 段缺失**（SSID1=109 / SSID2=WIFI-Mesh-F780 / SSID3=WIFI-Guest-F780——MTK 脚本按 dat 结构生成接口，5G 无段可启动，UCI disabled=0 不被尊重）。改 12 段分号格式 dat 风险=无线全灭，**果断止损回滚**（红线：不影响使用）。后续如需 5G：走 JCG 原厂 web 面板开 5G（它写 dat 的方式是安全的），或接受 2.4G 现状。
