# 三方管理冗余方案（DO + TX + BWG 并行隧道）— 2026-09-30

## 目标
- 路由器同时与三台 VPS 建立管理隧道（并行，非主备切换）
- 任一 VPS 不可达时，其余两条路径仍可控制路由器
- 不买域名，不需要 DDNS

## 架构

```
路由器 (mihomo 代理不依赖管理面，客户上网不受任何影响)
├── SSH 隧道 1 → DO:28722   (-L 18443→管理API) (-R 1322x→远程Shell)  ← 现有
├── SSH 隧道 2 → TX:28722   (-L 18444→管理API via WG) (-R→远程Shell)  ← 新增
└── SSH 隧道 3 → BWG:28722  (-L 18445→管理API via WG) (-R→远程Shell)  ← 新增
```

## 前提条件

| 服务器 | 需要什么 | 现状 |
|---|---|---|
| DO | WG hub (已有) + sshd:28722 (已有) | ✅ 就绪 |
| TX 腾讯 | 装 WireGuard → 加入 DO mesh；开 sshd:28722；加路由器密钥 | ❌ 需改造 |
| BWG 东京 | 同上 | ❌ 需改造 |

## 四步实施

### 第 1 步：WG mesh（TX 和 BWG 加入 DO 的 WireGuard 网络）
- DO 已有 wg0 (端口 51820)，有现成 hub
- 在 TX 和 BWG 各生成 WG 密钥对，DO 加 peer
- TX 分配 WG IP: 10.10.0.3，BWG: 10.10.0.4
- 配置 persistent-keepalive 维持 NAT 穿透
- 验证：TX/BWG 能 ping 10.10.0.1 并 curl https://10.10.0.1:8443/api/v1/health

### 第 2 步：SSH 中继端口（TX 和 BWG 开 28722）
- sshd 增加 ListenAddress:28722（或第二个 sshd 实例）
- ufw 放行 28722/tcp
- 路由器的 SSH 公钥添加到 TX/BWG 的 authorized_keys
- PermitOpen="10.10.0.1:8443"（只允许转发到管理API）
- 验证：从管理机 ssh -p 28722 root@TX 能连

### 第 3 步：路由器隧道脚本改造（最核心）
- tunnel.conf 支持多端点格式
- mgmt-tunnel init 脚本为每端点创建独立 procd instance
- agent 心跳改为多端口尝试（18443→18444→18445）
- 路由器需要：TX 和 BWG 的 SSH 主机密钥 pin

### 第 4 步：备份冗余（Plan A + B）
- backup.sh 同时推送备份到 TX 和 BWG
- TX 预装 Docker 环境，放好恢复脚本
- DO 挂了 → 在 TX 上 30 分钟内恢复管理台

## 安全考量

1. WG 隧道端到端加密（Curve25519），TX/BWG 只是中继不落地数据
2. SSH 密钥有 PermitOpen 白名单，只能转发到管理 API 端口
3. 管理台 API/DB 仍然只在 DO 的 Docker 网络内运行
4. TX/BWG 的 28722 端口仅接受路由器密钥（公钥认证，无密码）

## 耗时估算

| 步骤 | 耗时 | 风险 |
|---|---|---|
| 1 WG mesh | 30 min | 低（新增配置，不动现有） |
| 2 SSH 中继 | 15 min | 低（只加端口和密钥） |
| 3 路由器脚本 | 45 min | 中（改隧道脚本需逐台试点） |
| 4 备份冗余 | 15 min | 低 |
| 5 测试 | 30 min | — |
| **合计** | **~2.5h** | |

## 对 R4 的即时价值
R4 当前"能到腾讯但不能到 DO"——并行隧道上线后，R4 连 TX:28722 即可接入管理，无需换线。

## 与域名方案的对比

| | 本方案（三路并行） | 域名+DDNS |
|---|---|---|
| 成本 | ¥0 | ~¥75/年 |
| 切换速度 | 即时（三路同时活） | DNS 生效 1-5 分钟 |
| DO 整机挂掉 | 管理台不可用（冷备恢复） | 管理台不可用（同样冷备） |
| 某条线路不通 | 另外两条可用 ✓ | 需要手动改 DNS |
| 复杂度 | 中（脚本改造） | 低（只改配置） |
| 结论 | **不买域名就用这个** | 买了域名更好（两者可叠加） |
