# 全在线路由器BWG对照与端口可用性判断（2026-11-19，Codex）

结论：当前9台在线物理设备均通过BWG-HY2/UDP34567访问国外，BWG并非全IP/全协议不可用；但9台到BWG TCP443的限时连接及VLESS HTTPS探测均未成功，存在协议/端口路径的选择性不通。不能笼统说“完全没受影响”，也不能据此宣布所有TCP或整台服务器被封。

本轮全程只读，无生产写入、代理组切换、节点发布、服务重启或认证修改。

推断：更支持各站宽带、跨境路由/丢包/拥塞或协议传输差异；尚未核实具体运营商与瓶颈点。未据此把问题归为硬件故障、Wi-Fi必坏或服务器全局统一限速。

## 2. BWG是否被封：按协议分别看

- HY2 UDP34567：9台当前真实业务均经它，18次下载完整，证明本轮该路径可双向传输。
- VLESS TCP443：9台各一次HTTPS节点探测失败（核心HTTP错误），各一次5秒TCP连接未成功；只能说本轮从这些站点未连通，不将错误码独立当封锁证明。
- BWG服务器端TCP443监听存在；sing-box/hysteria/s-box-ws/cf2053-guard均active。香港来源到其TCP443连接成功；本机iptables INPUT为ACCEPT、只显示2053的CF限源跳转；fail2ban只看到sshd jail。
- BWG未装ufw命令，不能把ufw查询无输出当作防火墙全部正常；本轮未完整核验所有原生nft/云安全组/沿途设备，具体拦截位置未定。现象与此前“直连TCP受阻、HY2仍可用”的历史一致。

## 3. 服务器自身对照

16:45 BWG load约0.05，可用内存约653MiB，同一512KiB文件0.090秒完成、约5839501B/s，实际出口JP/NRT。没有观察到本轮服务器自身整体出国能力耗尽。小样本不能证明所有目标、所有时段及所有用户都快。

## 4. 当前应如何处理

1. 保留当前已验证的BWG-HY2路径及其它后备，不因TCP443失败删除整台BWG/重置认证/重启全舰队。
2. TCP443节点不要在未验恢复时提升为primary；先独立定位网络路径，不用“换个端口一定好”作承诺。
3. 对东营/R1/R2慢站分别做同目标、分时段、与香港的有回退单台体验对比，结合现场卡的网址判断，不把临时改组冒充长期迁移。
4. 用户已确认的目标仍为普通设备香港默认、66云/BWG后备、雅典娜默认BWG；正式迁移仍需处理CF入口/实际出口校验，不能绕过既有门禁。
5. GL/R7/R10/R11当前离线未做本轮性能测试；旧雅典娜档案不是第二台物理设备。不能写成全舰队所有设备已验。
