## 三、必须先知道的硬约束（决定用哪个节点名）

**66云 154.36.139.155 目前 TCP 已被墙，只有 UDP 可用**（2026-11-20 三重实测）：

| 测试 | 结果 | 说明 |
|---|---|---|
| 中国→66云 ping | 通 151ms | 服务器活着 |
| 中国→66云 TCP 22/443/2054 | **全部超时** | IP 级 TCP 封锁 |
| 美国→66云 TCP 22/443/2054 | 全通 0.9ms | 服务器健康，是 GFW 封锁 |
| 经 66云 **VLESS（TCP 443）** | 000 全失败 | ❌ 不可用 |
| 经 66云 **HY2（UDP 34568）** | chatgpt 200 / gemini 200 | ✅ **当前唯一可用入口** |

### 因此：主力必须选 `GIA-HY2-US-01`（UDP），不能选 `US666-CN2GIA-01`（TCP，已不可达）
- `US666-CN2GIA-01` = 66云 VLESS（TCP 443）→ 现在不可用
- `GIA-HY2-US-01` = 66云 Hysteria2（UDP 34568）→ **可用**
- `BULK-LAX-GIA-01` = 66云另一条 VLESS（端口 2054，TCP）→ 同样受 TCP 封锁影响

> 若日后 66云 换新 IP 且 TCP 恢复，可再切回 `US666-CN2GIA-01`（TCP 质量更稳）。

## 四、变更内容（二选一，推荐方案 A）

### 方案 A：文件持久化（推荐，重启不丢）
编辑 `/etc/mihomo/run.yaml`，把 **NODE-PICK 组的成员顺序**改为把 `GIA-HY2-US-01` 提到第一位：

```yaml
proxy-groups:
  - name: "NODE-PICK"      # 找到这一段
    type: fallback
    proxies:
      - GIA-HY2-US-01      # ← 提到第一位（主力，走 66云 HY2）
      - BWG-HY2-JPTY-01    # 其余顺序保持原样
      - US666-CN2GIA-01
      - BWG-VLESS-JPTY-01
      - CF-CDN-GIA-01
      - CF2-CDN-GIA-01
      - VPS-TX-SG-02
      - VPS-SG-01
```

再把 **PROXY 组**从"固定 BWG-HY2"改为 `AUTO`（让 fallback 按新顺序生效）：

```yaml
  - name: "PROXY"
    type: select
    proxies:
      - AUTO
      - US666-CN2GIA-01
      - GIA-HY2-US-01
      ...
```
（即 PROXY 选择 AUTO 即可；各节点名保留在列表里不影响）

改完必须：
```sh
cp /etc/mihomo/run.yaml /etc/mihomo/run.yaml.bak-gia-main-<日期>   # 先备份
/usr/bin/mihomo -d /etc/openclash -f /etc/mihomo/run.yaml -t        # 语法校验，必须 successful
/etc/init.d/mihomo restart                                          # 重启生效（LAN 中断约 10 秒）
```

### 方案 B：即时切换（不持久，重启回原样，仅用于先验证）
```sh
# 1) 先试即时切换
curl -X PUT http://127.0.0.1:9090/proxies/PROXY \
     -H 'Content-Type: application/json' -d '{"name":"GIA-HY2-US-01"}'
# 2) 验证通过后再按方案 A 落配置文件，否则重启会丢
```

## 八、风险提示

1. **66云只有 UDP 一条腿**：HY2 一旦被运营商 QoS 或服务器故障，没有 TCP 备份可用（VLESS 已封）。**CF 域名节点保留在组内即为兜底**（cf.k3x9m2.top 走 Cloudflare，不受 66云 IP 封锁影响）。
2. **66云有带宽限速历史**（11-16 全舰队实测 gstatic 6-7 秒、YouTube 16 秒）：切为主力后，医院局域网内的大流量/视频可能明显变慢；如体验不可接受，立即按第七条回退。
3. **雅典娜承载医院业务**（10.1.2.x 网段设备、白名单地址 10.1.2.18）：重启 mihomo 会中断局域网外网约 10 秒，建议在非业务高峰执行。
4. **NODE-PICK 健康检查 URL 仍是旧地址**（captive.apple.com）：它不能反映海外可用性，可能导致 fallback 判断失真（本次按要求不改，属已知缺陷）。
5. **不要走平台发布**：当前平台二进制为 11-12 旧模板，发布配置会覆盖全舰队的 MATCH,DIRECT 改造与政务站直连规则。
