# Cloudflare 域名中转方案 — k3x9m2.top（2026-10-30）

## 一句话用途

k3x9m2.top 是专门购买用于 **Cloudflare CDN 中转出国流量** 的域名：把设备上网从"直连服务器裸 IP"改为"设备 → Cloudflare 边缘（WebSocket）→ 源站服务器"，解决出口服务器 IP 被 GFW 轮番封锁、换 IP 无效的问题。

**该域名只承载代理流量，与管理面 / 远程控制 / 反向 SSH 通道完全无关，任何操作不得波及管理面。**

## 背景（为什么需要它）

2026-10 以来 DMIT、BWG、GIA 的出口 IP 先后被 GFW 封锁（TCP 选择性阻断），且实测换新 IP 后仍被封（按运营商 IP 段封，换 IP 治标不治本）。已验证的事实：

- Hysteria2（UDP）可绕过部分 TCP 封锁（坊子 R4 已跑通），但 UDP 路线也可能被封，属于备份而非长期方案
- YouTube 等站点还按 IP 信誉墙数据中心 IP（不是 GFW 所为）
- Cloudflare CDN 是长期稳定解：CF 边缘 IP 与数百万正常网站共享，GFW 不敢整体封锁；域名被针对只需花几块钱换一个，服务器真实 IP 不再暴露给客户端

## 流量架构（目标状态）

```
设备(mihomo) --TLS/WSS:443, SNI=cf.k3x9m2.top--> Cloudflare 边缘 --WebSocket--> GIA 源站新端口 --> 国外网站
```

- 设备侧看到的目标是 `cf.k3x9m2.top:443`（CF 边缘 IP），不是服务器真实 IP
- CF 边缘到源站走 CF 支持的回源端口（候选 2053/2083/8080 等，部署时定）
- 现有直连节点（GIA 443 REALITY、HY2/UDP）全部保留，CF 节点作为新增选项加入自动切换组

## 部署计划（四步，每步可独立回退）

1. **NS 切换生效** —— 用户在 NameSilo/Cloudflare 手动操作（进行中）
2. **GIA 源站部署 VLESS+WS** —— 独立进程监听 CF 支持端口，不重启、不改动现有 443 REALITY / HY2 / rssh 中继服务
3. **Cloudflare 配置** —— 加 A 记录（`cf.k3x9m2.top` → GIA IP）+ 开橙色云（Proxied）+ SSL 模式 Full
4. **设备侧推送 CF 节点** —— 平台给 mihomo 配置加 `vless+ws+tls` 节点（端口 443、SNI=cf.k3x9m2.top）：先坊子 R4 实测（YouTube 可用性 + 延迟），通过后再铺全舰队

## 红线约束（其他 AI 必须遵守）

- **不影响远程控制**：管理面 = 设备反向 SSH → 广州（134.175.151.213，端口 13221-13233 段）+ GIA 备份双 -R 通道。这套通道与本域名方案完全隔离，不得改动。
- GIA 服务器现有服务（443 VLESS+REALITY、HY2、rssh 中继、管理转发链）保持不动；本方案只允许"新增独立进程/记录"，不允许"修改现有服务"。
- Cloudflare 账号、NameSilo 账号凭证不入库、不写入任何文档。
- 设备侧节点推送必须先单台（R4）验证再全量，回退 = 删除新增节点记录。
