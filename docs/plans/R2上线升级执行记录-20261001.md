## 5. 事故二：温备会话 authorized_keys 逗号格式 bug（已修复，跨会话协调项）

**时间线（UTC）**：另一会话执行温备预备：04:29 改 DO authorized_keys → 04:35 停 TX socat、TX sshd 加监听 28722 → 04:37 改 BWG authorized_keys → 04:41 R3 隧道一次普通抖动重连 → **认证全部失败，管理面全断**（反向 13224、三路 -L 全死；代理走 BWG vless 不经 DO，客户上网不受影响，BWG 上确认有活跃 vless 连接）。

**根因**：authorized_keys 里写 `permitopen="10.10.0.1:8443,127.0.0.1:8443"`（**一个 permitopen 塞逗号列表是非法语法**）→ sshd 整行密钥报废 → 客户端 "Connection closed by authenticating user [preauth]"。R2 因隧道恰好是 03:48（改动前）建立的旧会话而幸免。

**对照实验**（DO 上临时 sshd 2299 实测）：旧单值格式 ✅ / 重复选项 `permitopen="a",permitopen="b"` ✅ / **逗号列表 ❌**。

**修复**：三台 VPS 全部 sed 改为重复选项格式（各自留 `.bak-commafix`）：DO 04:56Z（R3 秒级自愈，13224 恢复）→ BWG → TX root（ubuntu 的文件本来就没路由器行，查的时候别查错对象）。TX socat→sshd 直连的架构切换是温备会话有意为之（root authorized_keys 12:56 已加 5 台路由器密钥），保留该设计，只修格式。

**遗留**：R3 的 `MGMT_TARGET` 被温备会话改成 `127.0.0.1:8443`（新设计：每台 VPS 本地服务 API），但 TX/BWG 上管理台容器还没部署 → BWG 路径 18445 转发到无人监听端口。已把 R3 改回已验证的 `10.10.0.1:8443`（R2 一直就是这个值），恢复 3/3。**温备会话后续部署完 TX/BWG 控制台后再统一切 127.0.0.1:8443，切换前别再动 MGMT_TARGET。**

**⚠️ 给温备会话的硬警告**：如果温备脚本幂等重跑会重新写 authorized_keys，**必须用重复选项格式**，否则三台 VPS 的路由器认证会再次全灭（R2/R3 当前隧道是已建立会话，重连即死）。

## 10. 第三阶段（16:0x—16:4x）：WiFi 开机自关 bug 根治 + MGMT_TARGET 误诊纠正

### 10.1 用户报障：13:15 远程开 WiFi → 重启后被自动关闭

**根因三层叠加（都实测确认）**：
1. rc.local 旧钩子语义反向：agent 的 `wifi.disabled` 是"禁用中+300s 自动恢复布防"标记，钩子却当"已启用"读（`[ -f wifi.disabled ] || 强制关`）→ **开启状态一重启就被关**；反向地，禁用状态重启反而被固件开回来。
2. 刷机在 MTK dat 写死 `RadioOff=1`，固件开机不拉射频；agent 的"开"只是运行时 ifconfig up → **skip-down 不够，必须主动 up**。
3. MTK 驱动开机初始化射频要十几秒，固定 sleep 6 打在未就绪接口上无效 → **v3 钩子带重试**（最多 6×5s，见 ra0 UP 才停）。

**修复（R2/R3 已部署，R2 重启实证 ra0=UP+SSID 广播）**：
- agent handler（仓库+设备 md5 2c58a38a）：开启建 `wifi.enabled` 标记、关闭删；300s 自动恢复路径也建标记。
- rc.local v3：`(sleep 8; _w=up; [ -f wifi.enabled ] || _w=down; 重试循环 ifconfig) `。
- 语义=**开了不自动关，除非人工关**；新设备无标记→默认关（舰队策略保持）。
- flash-snr.py 模板同步 v3。

**我方失误两笔（已补救）**：①修 WiFi 时 sed `/# wifi-default-off/,$d` 误删 netprobe 钩子（已补回+重启验证）；②早期"重启后 WiFi 正常"验证用 iwconfig 看 ESSID——**ESSID 显示≠射频 UP**，必须 `ip link` 看 state（又一测量假阴性）。
