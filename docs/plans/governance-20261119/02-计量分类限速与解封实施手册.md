## Q1. 先把账算可信：日账不是一个total字段

### Q1.1 明确三本账，各有用途

1. **设备配额账**：按设备唯一、覆盖实际代理传输端点的上下行字节，用来判断3GiB。需要连续性/资格，缺失不能填0。
2. **服务商预算账**：按供应商周期与其计费口径核对，来源优先供应商面板/授权API；vnStat整网卡和服务器计量作交叉证据。
3. **旧平台估算账**：现有agent轮询`/connections`，对活跃连接字节求和，短连接/已关闭流会丢，和单调累计不同。UI可保留“估算”，不能无声升级为精确配额。

源码核查另有待测问题：`traffic.go`对sample_id去重，但不能仅凭注释认定所有乱序已处理；新模块必须覆盖唯一但乱序样本/并发心跳/计数下降。先在隔离夹具复现，未经证实不对生产历史月账全量重算。

### Q1.2 注册表与覆盖

1. 以正式配置、provider当前有效列表、实际使用节点和连接变化为输入。过滤订阅的余额/到期等元信息，保持与核心exclude-filter相符；不把40条未解析名称都算有效节点。
2. 静态IP、域名多A/AAAA、TTL、DNS失败/负缓存、机场切换、旧长连接仍用旧IP均处理。新地址计数规则先准备再允许业务使用；撤旧地址前结算，并保留仍有连接者。
3. IPv6如果实证已禁用且没有代理/外层IPv6流，可将该能力标“不适用且有证据”；否则补IPv6计量。不要一律安装IPv6模块，也不要忽略正在使用的AAAA。
4. 核心计量键为`方向|IP|传输协议|端口`或经证明等价的稳定身份。多个域名共CF边缘2053只算一次；节点名称是展示标签，不能当总账主键。标签改名不能重新把历史计数灌入。
5. 当前生成器手工拼JSON，要补引号/反斜线/换行/Unicode名称测试和可靠编码；不能让一个机场名称破坏coverage文件后还health=ok。
6. 规则生成/替换须在锁内，旧末样本→新注册表→新基线可追踪；数据源不能读一半更新中的provider。解析失败保留旧已知有效集合并标降级，不输出“空表成功”。

### Q1.3 采样、重启、日界、持久化

- 保留已修独立up/down与iptables完整-C判重；不得回退到每天新增规则或只算down的版本。
- 每个样本包含device_id、meter_id、采样ID/seq、boot_id、continuity_id、registry_generation、epoch、day_cst、上下行整数、coverage/health、partial和资格依据。
- 计数下降、缺样、入口缺失/恢复、防火墙reload、核心/设备重启都记录事件和未知区间；不把读失败当0，也不凭流量曲线猜补历史。
- 正常计划重启要在业务停止/计数销毁前结算，并在业务恢复前装好计数；验证执行顺序。无预告断电若丢未持久化量，应降级当天资格。每天重启不能每天悄悄丢几分钟又称完整。

## Q3. 唯一锁定执行路线：路由器本机 `qos-gate`（禁止再在服务器侧 `tc` 内耗！）

### Q3.1 架构定案与 PoC 停点

**正式锁定“路由器本机轻量 Go 令牌桶 `qos-gate` + `mihomo v1.19.31` `listeners: type: socks`”为唯一实施路线**（不要求 38 个机场节点或 Cloudflare 配合服务端，零内核模块依赖，SN/GL/雅典娜 ARM64 全通用）。
- Batch 2 必须首先完成最小 PoC，并在 R2 真机按实测证据验收 4 项：**① TCP 与所需 UDP 转发 ② 存量连接接管 ③ 真实上游省流（Q3.3） ④ R2 CPU/内存/磁盘资源**。
- **硬停点**：若 PoC 出现无法解决的阻塞（例如无法通过反压降低上游发包），**立即停批并附完整证据向用户汇报，严禁自行退回修改已废弃的 `ratelimit-server-executor.sh` 或做整条出口 WAN 限速！**

### Q3.2 候选拓扑及最低实现要求

逻辑拓扑：业务规则→两类独立gate入口→专用回环上游入口→原有正常代理链。普通网页/国内/游戏/管理不进入gate。使用独立入站身份或端口确定类，不依赖连接目标IP猜类。

1. mihomo listener使用实际支持的`type: socks`，不是socks5。入站明确选择上游`proxy`，不得重新进入包含gate的业务rules形成环。具体字段须在设备固定v1.19.31独立工作目录验证，当前官方文档不能代替固定版本实测。
2. 端口从实际空闲回环端口选；监听127.0.0.1，控制接口优先有权限的Unix socket；不监听0.0.0.0，不开放未认证管理端口。
3. SOCKS5域名/IPv4/需要的IPv6、错误码、超时、取消、半关闭均实现；禁止把目标域名错误地先解析为污染IP。
4. 视频/下载各一个聚合下行令牌桶，所有连接共享。只限下行，上传/ACK等必要控制流不被同一个小桶拖住。避免大锁跨等待，紧急解除可立即唤醒全部等待者。
5. 明确burst、最大read-ahead、写缓冲、每连接/每类队列上限、FD/超时；不要把服务器已下载几十MB缓存到路由器后慢发，冒称省上游流量。
6. 对现有可用业务所需UDP ASSOCIATE/QUIC做实际验证；TCP-only标TCP_ONLY，不能自动当完成。当前golden已有UDP443 REJECT规则，不能为测试随意新增/移除全局UDP禁令；验证既有客户端回退和其它UDP路径，受保护游戏不得被改变。
7. 若业务从正常时就常驻gate，阈值后可在线改桶，存量流仍归同一对象；要证明未限时性能接近同路基线。若只在超额时切selector，必须明确既有连接不能自动接管，不能全删连接或称无缝生效。
8. gate进程/控制器崩溃时有独立恢复机制：恢复记录的正常代理路径，避免新增DIRECT泄漏或阻塞管理；既有用户会话可能重连，真实记录中断边界。

### Q3.3 真正“省国外流量”的证明

## Q4. 持久策略、解封与故障安全

新策略协议可按下面语义设计；这是**拟新增契约，不是可立即POST的现有API**：

```json
{
  "device_id": "rtr-a9bcba",
  "mode": "observe",
  "quota": {"period": "daily", "timezone": "Asia/Shanghai", "trigger_bytes": 3221225472},
  "classes": {"video": {"down_bps": 60000}, "foreign_download": {"down_bps": 60000}},
  "upload": "unchanged",
  "policy_version": 1,
  "release_generation": 1
}
```

1. 至少有observe/normal/throttled/exempt/emergency，期望与实际分开；API权限、设备身份、签名任务、幂等request_id、expected_version/CAS、release_generation与审计完整贯通。
2. `mode=observe`绝不触发真实tc/分流切换；status/preview尽量零写。当前本地控制器入口会mkdir/开锁，即使status也不能当天然纯只读工具在生产随便运行。
3. 紧急解除：先原子持久化emergency与新代际，再解除本人对象并验证。释放一半失败就报告PARTIAL_FAILURE及残留对象，不提前清manifest/报成功。
4. 迟到旧apply、重启、自愈/定时器不能复活旧限制；恢复自动策略必须有明确resume/新代际，不因字段空缺回落60。
5. 单类解除只动该类；临时/永久豁免范围分清，保留真实账本。临时到期行为显式编码，不能由午夜脚本擅改人工决定。
6. 新日00:00只撤旧日自动限额动作；人工紧急锁/永久豁免仍有效。断网、时钟回拨、跨日任务竞态须进入安全状态。
7. 计量/coverage不可信时不新增自动限速；已有自动限制按预先验证的fail-open策略释放本策略对象、恢复正常路径并告警，不撤销其它安全策略。记录失去配额保护的时间，不声称期间仍有效省流。
8. 控制器掉线不能把用户永久锁在60。执行器/gate的本地独立看门狗、持久状态和恢复路径要真实验证；不能全靠平台在线才可解封。
9. “3秒解封”以本地收到有效解除请求到对象/桶限制解除为控制目标，另外记录端到端API/任务延迟；恢复到同路基线，不要求线路立即达到固定5MB/s。
10. UI按钮必须显示请求中/实际成功/部分失败、作用设备/类、原因/期限、审计时间。旧VPS限速入口不能悄悄映射到新功能。

## Q8. 配额能省多少：不要许诺流量一定够用

60kbit/s每类全天持续约648000000B，约0.6035GiB；两类约1.207GiB/日。理想化假设每日很快用完3GiB且之后两类全速到午夜，单台约4.207GiB/日，8台×30日约1009.68GiB；这只是量级示例，不是严格上界或真实预测。

普通网页/上传不受限、检测延迟/协议开销、机场/CF重复链路与服务商单/双向计费都会改变预算。因此上线前还须：

1. 记录各供应商本周期总额/已用/剩余/重置时点/计费单位和方向，不能填猜测值。
2. 由真实流量分配到GIA/BWG/HK/机场，评估未来剩余天数；未知桶与重叠桶不能相加。
3. 若预测仍不足，给用户提交有数据的后续策略选择，如更低触发额/只把批量下载迁到有余量出口；**不在本批擅改已确认3GiB/60参数**。
4. 60kbit/s会让视频/大下载非常慢，这是已确认政策的预期，不把它当新线路故障；但网页等被拖慢则是分类/实现问题。
