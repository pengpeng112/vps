## 2. 只读边界与资源预算

- 不执行 INSERT/UPDATE/DELETE、DDL、迁移、种子数据、VACUUM、ANALYZE、REINDEX、权限变更、恢复、清理、统计重置、序列推进、写入函数、加锁读取或应用任务。
- 不使用“先更新再回滚”测试权限；不运行 EXPLAIN ANALYZE；不调用未审查的函数、存储过程、视图、外部表或扩展。SELECT 这个词本身不保证无副作用。
- 不启动应用、部署、登录管理 API、启用插件或重启服务来帮助探索。此类操作可能写审计、清过期数据或触发后台任务。
- 使用已有、经核验的最小只读角色，检查继承权限、对象所有权、超级用户/BYPASSRLS、函数执行权限；`mgmt_app` 在本地迁移中明确有 DML 权限，**不能当成只读账号**。没有合适账号则停该库的在线查询，继续源码/已授权离线分析；账号创建列为独立管理员任务。
- 默认每库 1 个连接、总并发 1；每条查询目标不超过 5 秒，锁等待不超过 1 秒；一批事务尽量低于 30 秒。客户端再设墙钟上限；超时不自动增大预算。
- 先目录与估算，再有索引的时间窗和少量字段；默认窗口近 24 小时，必要时扩至 7 天。明细最多 100 行，普通结果最多 1 MB，超出保存摘要及截断说明。LIMIT 不能保证扫描便宜，聚合也可能扫全表。
- 不用全表 COUNT/DISTINCT、无界 JSON 扫描或长期一致性事务作为默认盘点。性能异常、锁等待、磁盘压力、两次同类超时即暂停该库；不杀生产会话。
- 报告不含密码/哈希、TOTP、密文正文、token、配置正文、医疗/个人数据。连接配置来自受控来源，不打印完整 DSN；命令、错误信息也要脱敏。
- 只读指无主动业务/配置写入；数据库自身日志、统计、临时磁盘、SQLite 锁协调仍可能发生，不承诺“磁盘零写入”。

## 5. D1：只读连接验证

### PostgreSQL

用原有受控通道和已有只读身份连接；无需开放 5432 或修改 compose。psql 禁止自动加载个人启动文件（使用 -X），凭据不进命令文本和报告。核对 current_database/current_user 与用户指定环境匹配，检查角色及可见授权；只读事务是第二层保护，不替代账号权限。

每批由客户端预先设置连接/查询超时，再执行如下模板（**仅示例，本次未运行**）：

```sql
BEGIN TRANSACTION READ ONLY;
SET LOCAL statement_timeout = '5s';
SET LOCAL lock_timeout = '1s';
SET LOCAL idle_in_transaction_session_timeout = '15s';
SELECT current_database(), current_user, version();
SHOW transaction_read_only;
-- 只放已审核、带边界的目录/业务查询
ROLLBACK;
```

任何错误后先结束当前事务；新的连接或重连必须重新建立限制。一般使用短 READ COMMITTED 批次；只有需要同一快照比较的少量查询才用短 REPEATABLE READ，并记录快照时间差。不要在长事务里等用户回复。

PostgreSQL 的只读事务禁止常见写入，但不是防止所有磁盘写入的机制，且会话默认值可被覆盖，见 [PG16 事务说明](https://www.postgresql.org/docs/16/sql-set-transaction.html)。超时配置的作用域和语义参考 [PG16 客户端参数](https://www.postgresql.org/docs/16/runtime-config-client.html)。

### SQLite / ZCode

先记录主库与 `-wal/-shm` 是否存在、文件大小和修改时间，不显示数据库内容。使用 URI `mode=ro`，随后 `PRAGMA query_only=ON` 并读取该值确认；客户端设置 busy timeout 和进度处理/墙钟取消上限。不安装或加载扩展，不执行 journal_mode 切换、checkpoint、VACUUM 或 repair。

示意连接：`sqlite3.connect(Path(db_path).resolve().as_uri() + '?mode=ro', uri=True, timeout=1)`，db_path 从已确认清单获得。普通文件不存在时必须失败，不能自动创建空库。

活跃 WAL 库不能只复制主文件就当一致性快照；也不能对可能变化的源设置 `immutable=1` 来绕过锁。若在线只读无法正常打开，记录阻塞；需要一致性副本时另安排受控快照过程，保留原库不动。URI 行为见 [SQLite URI](https://www.sqlite.org/uri.html)，额外限制见 [query_only](https://www.sqlite.org/pragma.html#pragma_query_only)。

## 7. D3：管理系统质量分析

先设计查询再执行，每条编号 Qxxx，明确分母、窗口、NULL 处理与抽样策略。动态表名只来自已审核清单；值使用参数化。优先按设备 ID 与时间索引查询，避免全表 JSON 解码。

| 主题 | 要验证的假设 | 需要防止的误判 |
|---|---|---|
| 设备/版本 | 心跳新鲜度，desired/current/highest 的组合，生命周期和授权时间关系 | 未同步不直接等于失败，手动期限调整可能合法 |
| SSH与心跳 | remote_ssh 状态与检查时间，心跳离线但排障通道在线的组合 | 探测陈旧不等于设备 down；NULL 不等于 false |
| 任务 | pending/leased 超期、长期 unknown、终态与执行时间、配置关联 | 以实际代码状态枚举为准，不能臆造状态 |
| 绑定 | 每设备至多一个 primary，启用节点/绑定/实际出口关系 | 客户端双线自动切换未必同步 current_node_id |
| 配置 | device+version 唯一、任务引用缺失、发布与实际版本差异 | 不解密正文；版本跳号不必然异常 |
| 指标 | 时间间隔、未来时间、重复 sample、WAN 空值、alive 未知率 | 计数器重启/epoch 切换不是负流量故障 |
| 流量 | 相邻样本增量、月聚合与状态基线对齐、时区边界 | 90天保留后的数据不足以完整重算旧月份 |
| 告警 | 长期未确认、恢复后的旧告警、重复活动 dedup、投递失败 | ack 与 resolve 当前实现可能混用，先核代码 |
| 身份/审计 | TOTP 配置比例、API key 使用时间、审计动作覆盖 | 不取秘密字段；没有审计记录不证明没执行 |

每个问题给样本数/估算行数、覆盖比例、严重度、影响、复核查询编号、可能原因和证伪方法。报告使用稳定匿名设备代号，需要映射时留在受控本地附件。

## 8. D4：权限、性能、容量

核对本地 0002 的 DML 授权与实际角色，尤其 audit_log 是否仍仅追加、对象所有者能否绕过限制、新迁移表的默认权限。不能只看 SQL 文件就判定生产安全。

读取现有统计：库/表/索引大小、估算行数、扫描计数、死元组估算、统计重置时间、autovacuum/analyze 历史、当前锁与长事务的脱敏摘要。统计字段是估算或累计值，应写观察窗口。已有 pg_stat_statements 才能使用，需过滤 SQL 中敏感字面量；未安装则记缺口，不能启用扩展。

只用 EXPLAIN（不 ANALYZE）查看已审核查询估算计划；索引建议需同时考虑查询频度、选择性、写成本，未证明就标“候选”。不以 seq scan 就断言有问题。容量预测用实际多时点样本；只有单点时报告情景估算和假设，不承诺增长率。产物 `04-权限与性能.md`。
