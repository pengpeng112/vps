> 依据：Codex 纠偏提示词 §3-§5、R2 proxy-meter v1 实测缺陷（无 2054、无日账、无断点管理）。
> 性质：**设计文档**（供执行 AI/开发者照做），本轮未实施。对应手册 v2.5 §M（新增节）。

## M1. proxy-meter v2 设计（R2 路由器侧，唯一日阈值数据源）

### 修正点（对照 v1 缺陷）

| v1 缺陷 | v2 修正 |
|---|---|
| 规则固定 12 条，漏 BULK 2054 | 端点表含 2054；机场 provider 动态端点按"名称前缀+端口"映射，每日刷新 |
| 增量=前后差，重启后计数清零丢失 | `boot_id+iptables 计数器起始值` 记入 state；boot 变化时记 discontinuity，增量从新基线起算（不记负、不补假） |
| 明文 state 无序列保护 | 原子写（tmp+mv）+ flock 并发锁 + sequence 单调号 |
| 无日账 | 每 5 分钟采样落 state（单调累计+日切分）；Asia/Shanghai 自然日切分；日账 JSON 落 `/etc/routermgmt/state/proxy-meter-daily.json` |
| 无留存/满盘管理 | 日账保留 35 天；日志 5MB 轮转；写前查可用空间，<10MB 时告警停写 |
| 失败静默 | nft/iptables 读取失败→输出 `status=read_fail` 不写 0；日志区分 fail/zero/discontinuity |

### 验收（部署 R2 后逐项）

1. 2054 流量命中 BULK-GIA-2054 双向计数（真实小流量）。
2. 重启 mihomo/路由器后 continuity 正确，日账不清零、不翻倍。
3. 机场 provider 更新后端点自动覆盖，旧连接排空后移除。
4. 云flare/gstatic 探测流量计入（小、可区分）；国内 DIRECT 不出现。
5. 24-48h 与 GIA bulk meter 交叉对比趋势一致（不要求相等：口径不同）。

## M2. GIA gia_bulk_meter 修正

- unknown 桶范围与 cf_shared 重叠修正：cf 规则限 `tcp dport 2054`（BULK 回源无此流量，实为防御性）与 `tcp dport 2053`（CF-WS）分开，unknown 匹配排除已知站点+CF 段。
- 采样器 gia-meter-sample.sh 增加 flock + 原子写 + 失败重试一次；`gia_bulk_meter` 纳入同一采样。
- 沿用"counter 不 reset、discontinuity 记录、bytes 为单调值"语义。

## M3. 明确不做

- 不补 10-26 以来的历史分设备账（不可考）；
- 不用旧 `metrics.proxy_rx/tx_bytes` 参与新日阈值（仅历史趋势展示）；
- 不以服务器网卡总量倒推设备配额。

## E5. 本地控制器 dry-run 设计（执行 AI 开发规格）

### 形态

`/etc/routermgmt/ratelimit-ctl.sh`（R2 试点）+ 广州侧 `ratelimit-ctl-gia.sh`（GIA 服务器），统一子命令：

```text
status  [device]                # 当前 enforcement/用量/类/filter/版本/世代
preview [policy.json]           # 校验+diff，不落盘
apply    [policy.json]          # 需 expected_policy_version + idempotency-key
release  [scope] [mode] [reason] # 单类/单台/紧急
emergency-stop                   # 立即撤全部自有对象，转 observe
```

### 策略 schema v2.1（手册 §C1A 已定义，此处补齐执行细节）

- `rate.bps` 必须为正整数（60000）；`unit` 仅限 `kbps|KiB/s`，底层统一 `bits_per_second`。
- `expected_policy_version` CAS：不符→拒改并输出当前版本（防并发覆盖）。
- `release_generation` 单调：每次 release +1，旧 apply 带 ≤当前 generation 的 policy 拒绝（防旧策略复活）。
- 幂等键 24h 内去重。
- 所有动作写审计 JSONL（时间/操作者/原因/old/new/task/用量窗口），不含凭据。

### dry-run 与隔离测试（先于生产）

1. `--dry-run` 模式：完整执行分类/计算/规则生成，只打印不落内核。
2. fixture 测试（不耗真实额度）：
   - 用量=阈值±1B、恰好等于、超 1MiB；
   - 计量 read_fail/unknown 高/断点；
   - 并发 apply/乱序 apply/旧版本 apply；
   - 单类 release 不影响另一类。
3. 阈值评估每 5 分钟由 proxy-meter 采样触发检查（cron 复用），`observe` 模式只写日志。

### enforce 前置（全部满足才允许）

1. B2/B3 计量连续 24-48h 无 unknown>5%、无 read_fail；
2. E3/E4 已落地（BULK 通道+2054 计量）；
3. R2 现场可配合验证（紧急解封可达）；
4. 用户对 R2 单台的明确限速授权（已有：60kbit/s + 3GiB，其他设备另批）。

### enforce 动作（到达 action 阈值时）

| 对象 | 动作 |
|---|---|
| GIA gia_bulk_meter/HTB | R2 bulk 类 rate 设 60000bit/s（rate=ceil，记录 burst/cburst/quantum） |
| R2 US-MEDIA | PUT → BULK-LAX-GIA-01（select 已可手选） |
| 审计 | 完整记录，见 §C1A.3 |
| 不动作 | WEB 不变；DOWNLOAD 保持 DIRECT（不改代理）；不切 DIRECT |

### 解封（release）动作

| scope | 动作 |
|---|---|
| video | 撤 GIA bulk 类 60kbit → US-MEDIA→NODE-PICK |
| download | 当前 DOWNLOAD=DIRECT 无代理对象；仅解除状态标记 |
| all/emergency | 撤全部自有对象（服务器 bulk 类+设备组选择），转 observe |

release 后 `release_generation+1`；恢复 limited 需新 preview。
