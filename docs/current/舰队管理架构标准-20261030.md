
## 五、自动保护体系（已部署）

| 层 | 机制 | 触发条件 | 动作 | 响应时间 |
|---|---|---|---|---|
| 1 | procd respawn | 进程退出 | 自动重启进程 | 秒级 |
| 2 | self-heal v4 | mihomo/agent 进程死或端口不通 | 重启对应服务 | ≤1 分钟 |
| 3 | tunnel-watchdog v2 | 18443-18447 全部不通 | 重启隧道 | ≤3 分钟 |
| 4 | mihomo lazy:false | 出口节点不可达 | 自动切换到下一健康节点 | ≤2 分钟 |
| 5 | fw3 include | 防火墙重载 | 自动重跑 mihomo-ipt | 即时 |
| 6 | 00:00 重启 | 定时 | 全设备重启 | 每日 1 次 |

## 七、新设备/新站点接入标准流程

```
1. 确认设备型号 MT7981/AX3000，root 密码已知
2. 接线：WAN → 雅典娜 LAN（192.168.2.x）或现场路由器
3. 刷机：python scripts/flash-snr.py --num <N> --host <IP>
4. 验证：15 关关卡自动通过
5. 绑定：平台分配出口节点（GIA 主用 + HY2 备用）
6. 确认：心跳秒级 + 排灾口在广州监听 + 出口实测
```

## 八、故障排查速查

| 症状 | 可能原因 | 快速检查 | 恢复方法 |
|---|---|---|---|
| 国外不通，国内正常 | 出口节点被封 | 设备 curl GIA:443 | 平台切节点或等 lazy:false 自动切 |
| 管理断（心跳停） | agent/隧道死 | 广州看排灾口 | self-heal 自动修或应急脚本 |
| 全部不通 | 站点线路故障 | ping 网关 | 等运营商或现场处理 |
| 透明代理丢规则 | fw3 重载竞争 | iptables -t nat -S | fw3 include + mihomo-guard 自动修 |
| mihomo 死 | 进程崩溃 | curl 127.0.0.1:9090 | self-heal 自动重启 |
