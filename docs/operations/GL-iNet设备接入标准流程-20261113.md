# GL.iNet 设备接入标准流程（2026-11-13 定稿，通用版）

> 适用：GL.iNet 系（OpenWrt 21.02+，fw3/fw4，chronyd）新设备接入舰队管理面。
> 实测基线：GL-MT3600BE（rtr-e9ccdd，2026-11-11~13 全程踩坑+修复）。
> 与 SN-R 标准映射：15 项标配 13 项全对、2 项场景豁免（WiFi 保持开、MAC 无需固定）。
> 脚本：`scripts/glinet-onboard.py`（通用参数化，幂等续跑）。

---

## 一、前置准备

| 项 | 要求 |
|---|---|
| 设备连接 | PC 连 GL WiFi（出厂热点，密码=底贴 KEY）或网线直插 LAN 口 |
| 管理台 | 广州主平台（nginx 8443 → gz-api 8080），本机可 SSH 到广州 ubuntu |
| 口令 | web/SSH root = 舰队统一口令（GL web 改密码与 SSH 同源生效） |
| TOTP | 从 `登录信息与配置总表-20260917.md` 读取 |
| 组件源 | `mgmt/agent/`（仓库为准） |
| mihomo 二进制 | `firmware/openclash/mihomo-linux-arm64-v1.19.31.gz` |

## 二、GL 特有坑（8 条，全部实测踩过）

| # | 坑 | 对策 |
|---|---|---|
| G1 | OpenSSL 1.1.1 无 Ed25519 raw 验签 | 跳过 install-agent.sh 自测，手工写 agent.conf；**如需配置任务验签，从 SN-R1 复制 `/usr/bin/openssl-mgmt` + `/usr/lib/mgmt-ssl/{libcrypto.so.3,libssl.so.3}`**（handler 自动 export LD_LIBRARY_PATH） |
| G2 | dropbear 无 sftp-server | 文件全走 base64+md5 双端对拍（脚本 push_b64） |
| G3 | `/usr/bin/ssh` 是指向 dropbear 的 symlink | 实测可当客户端（dbclient 多调用），mgmt-tunnel-v3 无需改动 |
| G4 | 自带 chronyd（无 sysntpd） | 插线联网自动校时；**NTP 源必须 IP 直连**（GL DNS 劫持域名到 fake-ip） |
| G5 | tunnel.conf 键名 `VPS_PORT` | **勿照模板写 `VPS_SSH_PORT`**（解析器白名单只认 VPS_PORT，静默忽略致隧道不启动） |
| G6 | busybox nc 是裸版（无 -z/-w） | **连通测试禁用 `nc -z`**（全报假 FAIL）——用 curl/ssh 实测 |
| G7 | 时钟停出厂值 + DNS 劫持 | 心跳 401"时间戳超窗"先修时钟；chrony server 必须 IP 直连 |
| G8 | WAN 地址 dhcp 会变 | **改静态 IP + 上联 DHCP 静态租约双保险**（豁免规则依赖固定地址） |

## 三、标准步骤（脚本化，幂等）

### 一键执行

```bash
python scripts/glinet-onboard.py \
  --name GL-MT3600BE-02 \
  --rssh 13235 \
  --host 192.168.8.1 \
  --note "办公室XX位置"
```

参数：
- `--name`：设备名（唯一，用于 authorized_keys tag）
- `--rssh`：反向口（13234-13299，自动占用检测）
- `--host`：设备 IP（默认 192.168.8.1）
- `--note`：位置备注（可选）
- `--skip-gia`：跳过 GIA 备用排障口（默认加）

幂等：广州 `/tmp/pkg-<name>.json` 存在即复用身份，可断点续跑。

### 人工步骤（如脚本失败，按此手动）

1. **平台录入**（经广州本地 API，TOTP 登录）：
   - `POST /devices {name, location_note}` → `POST /devices/enroll {enroll_code}`
   - pkg.json 改 `mgmt_url=https://127.0.0.1:18443`、`transport_mode=mock`、`sub_url=空`
   - 落广州 `/tmp/pkg-<name>.json`（幂等锚点）

2. **组件推送**（base64+md5 对拍，16 件）：
   routermgmt-agent.sh / handlers/switch_node.sh / access-fw.sh / netprobe.sh / connlog.sh / init/routermgmt / init/mgmt-tunnel-v3 / init/wan-watch / wan-watch.sh(+hotplug) / setup-mgmt-tunnel.sh / tunnel.conf.example / install-agent.sh（存档不执行）/ mgmt-port-discovery.sh / tunnel-watchdog.sh / wan-watchdog.sh / onboot-hooks.sh / self-heal.sh

3. **隧道密钥**：`dropbearkey -t rsa -s 2048 -f /etc/routermgmt/id_dropbear_mgmt`（600）

4. **agent.conf 手工写入**（G1）：jsonfilter 从 pkg 提 device_id/hmac_key/mgmt_url/sign_public_key → agent.conf(600, 五键齐全) + sign_pub.pem(644)

5. **tunnel.conf**（G5）：`VPS_PORT` 键名；主=广州 28722（-L 18443 + -R <RSSH>）；备=VPS2 TX/VPS3 BWG/VPS5 GIA；DO 不配；RSSH_TARGET=127.0.0.1:22

6. **mgmt_active_port 双补丁**（flash 原文两段 awk/sed）：多端口选路 + 心跳失败触发 discovery；补丁后 `sh -n` + grep 双验证

7. **cron 五条**（与 R8 逐字一致）：
   - `* * * * * /etc/routermgmt/self-heal.sh #self-heal`
   - `* * * * * /etc/routermgmt/mgmt-port-discovery.sh #mgmt-port`
   - `*/5 * * * * /etc/routermgmt/netprobe.sh #routermgmt-netprobe`
   - `*/5 * * * * /etc/routermgmt/connlog.sh #routermgmt-connlog`
   - `0 0 * * * /sbin/reboot #routermgmt-reboot`

8. **watchdog**：tunnel-watchdog.sh + wan-watchdog.sh（mode=log）+ onboot-hooks.sh 落位，`sh -n` 全过

9. **服务使能**：routermgmt/mgmt-tunnel/wan-watch enable；respawn 校验双处 3600 0 0

10. **公钥登记**（广州+GIA 两处，同款约束）：
    `no-agent-forwarding,no-X11-forwarding,no-pty,permitopen="10.10.0.1:8443",permitopen="127.0.0.1:8443",permitlisten="127.0.0.1:<RSSH>" <pub> rtr-mgmt-tunnel-<name>`
    GIA 经广州 sshpass

11. **凭证档案**：`backups/<设备名>-凭证档案-<日期>.md`

## 四、出口栈补装（如需要 mihomo/机场）

在管理面就位后执行：

1. **mihomo 二进制**：`firmware/openclash/mihomo-linux-arm64-v1.19.31.gz` 推送解压到 `/usr/bin/mihomo`
2. **数据文件**：geosite.dat / Country.mmdb → `/etc/mihomo/`
3. **init.d/mihomo**：respawn 改 3600 0 0（R8 原版 5 0=漏网勿照抄），S99 自启
4. **SUB_URL 注入**：`https://127.0.0.1:18443/sub/<devid>?token=<pkg.sub_token>` 写入 agent.conf
5. **平台节点绑定**：照 R8 模式（7主+9+4+10+11）INSERT 到 node_assignments
6. **AIRPORT env**：gz-api 需配 `AIRPORT_SUB_URL` + `AIRPORT_GENERATION=g02`（已配好，GL 发布自动带机场组）

## 五、透明代理（GL 适配版）

脚本：`scripts/glinet-mihomo-ipt.sh`（LAN=192.168.8/24，NODE_IPS 已更新为当前活节点清单）

部署：
1. 推送到 `/etc/mihomo-ipt.sh`（base64+md5）
2. fw3 include：`uci add firewall include; uci set firewall.@include[-1].type=script; uci set firewall.@include[-1].path=/etc/mihomo-ipt.sh; uci set firewall.@include[-1].reload=1; uci commit firewall`
3. cron 兜底：`* * * * * /etc/mihomo-ipt.sh #mihomo-ipt-guard`
4. **幂等检测**：规则齐全则秒退（防 dnsmasq 每分钟 restart 抖动）

验证：连 GL WiFi 客户端 `nslookup youtube.com` 应返回 `198.18.x.x`（fake-ip）

## 六、上联路由器豁免（关键）

GL 上联雅典娜时，雅典娜透明代理会截获 GL 全部流量（含管理隧道）→ **GL 管理面依赖雅典娜 mihomo 存活**。

**修复**（雅典娜 `/etc/mihomo-fw.sh`）：
1. NODE_IPS 补齐 7 IP（DO/TX/GIA新/BWG/CF×2/广州）
2. flush 后首条加 GL 源豁免：`nft add rule inet mihomo prerouting ip saddr <GL_WAN_IP> counter return`

换节点 IP 时的**三处同步清单**：①GL `/etc/mihomo-ipt.sh` ②雅典娜 `/etc/mihomo-fw.sh` ③平台 nodes 表

## 七、插 WAN 后验收（G1-G6 + 时钟）

| 关 | 检查 | 标准 |
|---|---|---|
| G1 | 心跳入库 | last_heartbeat_at ≤90s |
| G2 | 远程实登 | 广州 `ssh -p <RSSH>` root 实登 OK |
| G3 | 时钟（GL 加严） | chrony 同步后 date 与北京时差 <60s |
| G4 | 出网/补丁实效 | agent 日志时间戳正常；`/tmp/mgmt_active_port` 机制可用 |
| G5 | 备用端点实效 | 隧道实例数=4（广州+TX+BWG+GIA）；GIA 备用 -R 通 |
| G6 | 自愈在位 | self-heal v3.1 md5 329c6081 + cron 5 条 + 无 pause |

任一 FAIL 停下排查；全过 → 档案补"上线实测"段 + 当前状态.md 加条目。

## 八、USB 5G/LTE modem（蜂窝 WAN）

Beryl 7 无 SIM 槽，GL 固件已预装 modem 驱动（qmi_wwan/cdc_ether/cdc_ncm/option）+ modem 服务全套。

**方案 B 实施**：
1. 采购 USB modem（华为 E3372h-320 / 中兴 MF833U1 / 移远 EG25-G / 广和通 FG150）
2. SIM 插 modem → USB 连 GL → 面板 Internet → Cellular → APN 按运营商填
3. **VPS 访问零新配置**：GL mihomo 经 VLESS/TCP 443 连 GIA（蜂窝 NAT 兼容），管理隧道经蜂窝 WAN 直连广州
4. 面板设"以太网优先、蜂窝备份"自动 failover

**验收**：插卡后 GL 获 wwan 地址 → `curl -x 7890 ipify` 出 GIA → 心跳新鲜 → 拔以太网测试 failover

## 九、安全基线

- fw3 wan zone `input=DROP` → WAN 侧 22/80 不可达
- 反向口约束 no-pty + permitopen×2 + permitlisten×1（无 restrict——X2 禁令）
- WiFi 密码统一舰队值（弱出厂密码已改）
- WAN 地址静态 + DHCP 静态租约双保险
