## 一键刷机

**前置物理条件**（每台相同）：
1. 新设备 WAN 口 → 雅典娜 LAN 口或公司网（能 DHCP 上网即可）
2. PC 网线 → 新设备 LAN 口（192.168.132.x）
3. PC 无线保底外网（管理台隧道走公网）

**执行**（PC 上）：
```
python F:\vps\scripts\flash-snr.py --num 5 --rssh 13225
```
参数：`--num` 设备序号（5 → SN-R5-AX3000）；`--rssh` 反向 SSH 端口（顺延 13225/13226/…，**别与在线设备重复**）。

**脚本自动完成**（12 步，无需人工）：
1. 端口探测 + telnet 登录（root / abc@1234）
2. root 口令 → 统一口令 `[REDACTED]`（已固化进脚本）
3. 出厂预装清理（dockerd/telnetd/ksmbd/miniupnpd/start_autoupdate/mtk_dut/wsdd2 停用+禁自启 + m-box 双路径清除 + done 里 telnet 注释）
4. NTP 裸 IP（192.168.2.1 + 公网备胎；**否则时钟停在出厂时间 → 心跳 HMAC 全拒**）
5. openssl 全局替换 3.0.16（源：firmware/snr1-openssl3/）
6. 管理台创建设备 + enroll（引导包注入 mgmt_url）
7. agent 13 文件推送 + install-agent.sh + 手工补装（busybox 无 install 命令）
8. 隧道：密钥生成 → VPS authorized_keys 追加（permitopen/permitlisten 限制）→ tunnel.conf 加 RSSH → pin-hostkey → 启动
9. mihomo：仓库 firmware/openclash/ 直推（mihomo-linux-arm64 + geosite + country.mmdb；**不依赖雅典娜在线**）+ init.d + 启动 + 透明代理规则 + QUIC drop
10. 发布双节点配置（DO 主用 + TX 热备，v1）+ PROXY→AUTO
11. WiFi：dat 文件改 SSID/密码 [REDACTED] + RadioOff=1 + uci 镜像 + rc.local 开机默认关钩子（带 agent 状态门）
12. MAC 采集 + 凭证档案生成 + 管理台 mac_addr/location_note 录入

**完成后管理台应显示**：设备在线、心跳滚动、AUTO 择优、配置 v1。

### 2026-10-09 增补：WAN/LAN MAC 固定（标准步骤）

**背景**：AX3000 固件出厂未烧录有线 MAC，每次重启随机生成，WAN IP 随之漂移（光猫侧 IP-MAC 绑定/端口映射会失效）。R2 实测确认，uci 固定后重启验证不变。

**刷机时必做**（在初始化网络配置阶段执行）：

```sh
# WAN MAC 固定（末字节建议用 19 这类固定值，逐台错开）
uci set network.wan.macaddr='76:a7:c8:e0:4f:19'
# br-lan MAC 固定（与 WAN 错开末字节，避免两个网段同 MAC）
i=0; while uci -q get network.@device[$i] >/dev/null 2>&1; do
  if [ "$(uci -q get network.@device[$i].name)" = br-lan ]; then
    uci set network.@device[$i].macaddr='76:a7:c8:e0:4f:1a'
  fi
  i=$((i+1))
done
uci commit network
```

验收：重启后 `cat /sys/class/net/wan/address` 与设定值一致、WAN IP 不漂移。WiFi 口 MAC（a4:d8:ca OUI）天然固定，无需处理。台账需登记每台固定值与回退备份路径（`/root/network.bak-macpin-*`）。

#### 评估确认（2026-10-09，方案可行性六项全过）

**可行性六项**：①机制=OpenWrt 原生 uci，netifd 每次启动自动应用（R2 二次重启实测不变）；②合法性=首字节 0x76 满足本地管理位+单播位（不撞厂商 OUI）；③唯一性=WAN/LAN 错开末字节、不同台按编号错开；④冲突面=grep 确认 wireless/firewall/dhcp/MTK dat 均无 macaddr 引用；⑤副作用=管理隧道认 SSH 指纹不认 MAC（改动全程在线），WiFi 口天然固定无需处理；⑥回退=两行 uci + 备份，一条 `uci delete` 即还原。

**边界（执行者须知）**：①只对**新刷设备**自动生效（flash-snr.py 按 N 错开末字节），已上线设备（R2 手动已做、R3/R4 待用户点头）不追溯、不动生产；②固定前缀 76:a7:c8:e0:4f 是约定俗成，满足"本地管理+单播+全局唯一"即可，换前缀不影响正确性；③WiFi MAC 不在本步骤范围（天然固定）。

### 2026-10-10 增补：异构设备（雅典娜类）接入标准

**适用**：非 SN-R 系 AX3000 的 OpenWrt 设备（如雅典娜 JDCloud RE-CS-02/LibWrt）。本次雅典娜 v3 迁移实战沉淀。

**必须裁剪/禁改的部分（红线）**：

### 2026-10-13 增补：R7 刷机实战新坑（四条，全实测）

1. **陈旧本地隧道劫持管理 API**：mgmt_api_test 默认 BASE=127.0.0.1:18444，若本机残留旧隧道（R7 案例中指向 DO 旧库），录入会静默落到错误平台（症状：设备 agent.conf 的 DEVICE_ID 在 DMIT 库查不到）。**录入前必须**：`netstat -ano | grep 18444` 核对隧道归属，或显式 `MGMT_API_BASE=https://127.0.0.1:8444`（已验明指向 DMIT 的端口），录入后立即在 DMIT 库 `SELECT` 验证记录存在。
2. **R7 类新机无 /etc/routermgmt/logs/syslog 文件**（logread 落文件机制未配）：心跳验证用 `logread | grep heartbeat` 或平台 DB，别 grep 文件得"无心跳"假阴性。
3. **paramiko exec 通道写可能被 dropbear 即关**（"Socket is closed"）：小文件（conf/pem）改用命令内嵌 base64 + `openssl base64 -d -A` 落盘 + md5 对拍（雅典娜标准同款）。
4. **pgrep -x 匹配不了 15 字符截断进程名**（routermgmt-agent→routermgmt-agen）：进程核验一律 `ps w | grep xxx | grep -v grep`。

**中断续跑方法**（R7 实战两次验证）：中断后先 SSH 探断点标志（shadow 哈希前缀 $1$snrNuni=步骤1过；m-box 删除/telnet 停用=步骤2过；libcrypto.so.3=步骤3过；/etc/routermgmt 目录+隧道进程=步骤5-6过；出口 IP 非直连=步骤8过；SSID=SN-Rx=步骤9过），从断点步骤起复刻脚本命令块续跑，禁止盲目重跑全量（telnet 已关、口令已改，全量必挂）。

**新设备授权公钥范围**（2026-10 起现行设计）：DMIT（-L+-R）+ TX/BWG（仅 -L）；**不再分发 DO**——DO 端点(v3 conf 里保留)因无公钥自动不可用，八关"隧道监听>=3"按 18443/44/45 三口判定。

## 四、批量并行（flash-batch.py）

`python flash-batch.py`（或 `--detect` 只探测 / `--auto` 无人值守）。内置：两网段全扫（telnet 23）→出厂指纹验证（root/abc@1234 + **MAC 白名单防误刷现役**）→编号/端口预分配（平台最大序号+1、DMIT 132xx 最大+1）→并行线程刷机→汇总 ✅/❌。进程锁防重叠（90 分钟兜底）。日志：`backups/.flash-N{num}.log`。

## 五、失败续跑（检查点法，勿全量重跑）

### 2026-10-13 增补（四）：重启实战验证沉淀——两处"教科书级"根因与最终根治（R7 四次重启迭代）

**方法论**：静态清理后必须做**真实重启验证**（PC 经被测设备上网的场景注意断网代价，优先借用夜间定时重启收尾）。R7 四次重启迭代出的两个根因：

**根因一：QUIC 顺序竞态（全舰队潜伏）**
- 现象：每次开机/重载后 REJECT 与 DROP 的先后随机。
- 根因：`/etc/mihomo-ipt.sh` 自己用 `-I FORWARD 1` 插 DROP——**它每次执行都必然把 REJECT 挤到第二位**；onboot-hooks 只在开机 20 秒后修一次，mihomo-ipt 在其后跑就翻案。

- ⚠️ R2-R6 同病（mihomo-ipt 同源），修复=同样两条自压命令，待授权逐台做。

**根因二：数据盘挂载的"九命猫"（三层 uci 封堵全部无效）**
- 逐层破案：注释 fstab target 行无效（blockd 按 UUID 挂载）→ mount 块 enabled=0 无效（全局 anon_mount/auto_mount=1 自动挂未配置分区）→ 全局关掉仍无效（**hotplug.d/block/10-mount 直接按签名挂载，绕过 uci**；dd 抹头部后还能按 ext4 备份超级块挂回）。

**sed 教训（本轮翻车三次）**：经 SSH 多层转义对远端文件做 sed 插行/替换是雷区——`58a\` 多行会塌成一行（命令被注释吞掉且 `sh -n` 照样通过）、`\&` 破坏子 shell 括号、`\|` 丢字。**修远端脚本一律整文件 base64 推送+md5 对拍**（雅典娜标准同款）。

**其他口径坑**：`ps w | grep -c pattern` 计数含 sh 包装+grep 自身（假阳性×2）；自启检查必须只数 `rc.d/S*`（K9=停止标记非自启）。
