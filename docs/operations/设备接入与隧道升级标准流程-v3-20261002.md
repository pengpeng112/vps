# 设备接入/隧道升级标准流程 v3（2026-10-02 定稿）

> 提炼自 R2/R3 的实际执行过程（含事故教训），R4 及后续设备（R5/R6/新机）一律照此执行。
> 每步的验证标准即验收闸门：**绿了才走下一步，红了立即回退/停止报告**。
> 全局铁律：远端写文件必须 md5 与源一致；>8KB 传输分段+逐段校验；authorized_keys 禁逗号列表。

## 适用前提
- 设备管理通道可用（排障口经 DMIT：R2=13223 / R3=13227 / R4=13224；新设备先走接入引导）
- DMIT 主台常开（179.255.137.64），DMIT 已装 sshpass
- 本地有 mgmt/agent/init/mgmt-tunnel-v3（v3 init，当前 md5 3fcb54af3951536db533a4f98248cbad）

## 标准步骤（已验证序列）
### S0 前置五检（全过才继续）
1. 设备身份（经现有排障口）：`grep DEVICE_ID /etc/routermgmt/agent.conf`
2. DMIT 三件：console=200、28722 监听、设备公钥在（permitlisten=设备端口）
3. 本地 v3 md5 记录（闸门基准）
4. 设备→DMIT 连通：`/usr/bin/ssh -i /etc/routermgmt/id_dropbear_mgmt -p 28722 -N -y -o ExitOnForwardFailure=yes -L 127.0.0.1:28443:127.0.0.1:8443 root@179.255.137.64 &` → curl 28443=200 → kill
5. **WAN MAC 固定性核对**（2026-10-10 增补）：`uci -q get network.wan.macaddr` —— 空值=未固定（AX3000 出厂不烧录，重启随机漂移），记入执行记录并按 S6 在本轮收尾补固定；非空=与台账（`backups/SN-R系列凭证总览.md` MAC 档案）比对，一致通过、不一致先查明再动

### S1 部署 v3 init + 追加/重写 conf（写入校验段，不重启）
- 备份：`tunnel.conf.bak-stable-TS`、`mgmt-tunnel.bak-stable-TS`
- 传输：脚本经 DMIT 放 /tmp → 设备 `dbclient exec cat 流式拉取`（或 base64 分段+逐段校验）
- **md5 闸门**：设备上 `md5sum /etc/init.d/mgmt-tunnel` 必须等于 S0-3 记录值

### S2 重启 + 验证（不动主端点时的灰度验证）
- `nohup sh -c "sleep 1; /etc/init.d/mgmt-tunnel restart" &`（连接闪断正常）
- 等 30s：实例数=5（v3 全起）；18443=200、18446=200；心跳正常
- 灰度观察（新设备/重大变更 ≥2h，常规 ≥45min，期间 18446 持续 200）

### S3 切主（conf 内 VPS_HOST ↔ VPS4 交换）+ 验证
- 备份 `tunnel.conf.bak-pswitch-TS`；sed 交换；restart
- 验证五件：DMIT 侧排障口监听+banner；设备身份经 DMIT 新通道确认；18443(DMIT)=200、18446(DO 兜底)=200；心跳实时落 DMIT（两次间隔查询）；DO 侧冻结

### S4 agent 选路补丁 + discovery（如设备尚未有）
- discovery 四端口版落到 /etc/routermgmt/mgmt-port-discovery.sh（755）
- agent.sh 补丁（幂等）：主循环 while 行后插 `[ -f /tmp/mgmt_active_port ] && MGMT_URL=...`；心跳失败行加 `|| discovery &`
- crontab 加 discovery 条目；`sh -n` 校验；杀残留测试进程

### S5 代理分流/换绑（经 DMIT 主台）
- 绑定节点（assignments/batch apply=false）→ preview → apply（发布配置）
- 节点 delay 实测（慎重门槛：通过率/延迟可接受）→ switch_node → 出口 IP 双验

### S6 WAN MAC 补固定（S0-5 检出未固定时执行；2026-10-10 增补）
> 规则与 `scripts/flash-snr.py` 一致（N=设备序号）：WAN=`76:a7:c8:e0:4f:{0x20+N}`、br-lan=`76:a7:c8:e0:4f:{0x30+N}`。
> 已用值：R2=19/1a、R3=23/33、R4=24/34、R5=25/35、R6=26/36。**必须与台账核对无冲突再用。**

1. 备份：`cp -a /etc/config/network /root/network.bak-macpin-$(date +%Y%m%d-%H%M%S)`
2. 写入：`uci set network.wan.macaddr='<目标WAN>'`；br-lan 用 `uci set network.@device[$i].macaddr='<目标>'`（循环找 name=br-lan 的 device，同 flash-snr.py:286-291 写法）；`uci commit network`
3. 生效：`ifup wan`（WAN 重新 DHCP，管理隧道闪断约 30-60s，代理进程不受影响）
4. 验证：`uci -q get network.wan.macaddr`=目标值；心跳恢复刷新；排障口可入
5. 回退：`cp -a /root/network.bak-macpin-*/network /etc/config/network && ifup wan`
6. **与其他闪断步骤（S2/S3/S5）不同日执行**，避免叠加断因难排查
7. 收尾：更新凭证档案 MAC 档案表与当前状态一行（ESSID/位置不动，只记 MAC 与备份目录）

### 回退预案（按步骤逆向）
- S3 后异常：`cp tunnel.conf.bak-stable-* 回来 + restart`（DO 兜底端点+心跳仍落 DO）→ 经 DO 旧台 repair 任务
- 失联终极：现场 WiFi 处置手册（R2 模式：恢复 bak-stable 备份）
