# GL.iNet 设备接入标准流程（2026-11-12 定稿）

> 依据：GL-MT3600BE（Beryl 7）2026-11-11~12 实际接入全程 + 与 SN-R 标准（flash-snr.py 15 项）逐项比对沉淀。
> 适用：**GL.iNet 系（OpenWrt 21.02+，fw4/nftables，chronyd）** 新设备接入舰队管理面。JCG/AX3000 系继续走 `scripts/flash-snr.py`，两套流程不互换（fw3/fw4、mihomo、PCDN 项差异见 §二）。
> 本流程实测基线：**rtr-e9ccdd**（GL-MT3600BE，等插 WAN 状态，管理面全就位）。

---

## 一、场景与前提

| 项 | 本流程假设 |
|---|---|
| 设备连接 | PC ↔ 设备 **WiFi**（GL 出厂热点，密码=底贴 KEY）或网线直插 LAN 口；**WAN 线最后插** |
| 管理台 | 广州主平台（nginx 8443 → gz-api 8080）；录入经本机→广州 SSH（ubuntu@134.175.151.213）+ TOTP 登录本地 curl |
| 口令 | web/SSH root = 舰队统一口令（GL web 改密码与 SSH 同源生效）；勿按底贴/官方默认猜 |
| 用途定位 | A=纯管理接入（无 mihomo，本流程默认）；若要 B=代理出口，另按 SN 流程补 §三映射中标注"跳过"的项 |

## 二、与 SN-R 标准（flash-snr.py 15 项）映射表

| SN 标配 | GL 本流程 | 说明 |
|---|---|---|
| ① 身份预检 | ✅ 保留 | 录入前查重（脚本幂等：广州 /tmp/pkg-glinet.json 存在即复用，防止重复建设备——**实测教训：rtr-bf0292 曾重复创建被 revoke**）|
| ② PCDN 六面清理 | ⛔ 不适用 | GL 原厂固件无 JCG 厂商残留（如遇二手机可跑只读核查）|
| ③ openssl3+agent | ⚠️ 改造 | **GL OpenSSL 1.1.1 无 Ed25519 raw 验签（pkeyutl 无 -rawin）→ install-agent.sh 自测必拦 → 手工写 agent.conf**（agent 运行时只用 HMAC-SHA256，兼容；Ed25519 仅配置任务验签用）|
| ④ 隧道 v3.1 | ✅ 保留 | 广州主端点 + VPS2/3/5 备用 + 双-R（主口 13234 + GIA 备用口）。**键名只认 `VPS_PORT`——模板的 `VPS_SSH_PORT` 会被静默忽略致隧道不启动（舰舰队级坑）** |
| ⑤ 录入+绑定 | ⚠️ 半保留 | 录入照做；**节点绑定按用途**：纯管理=不绑（11-11 初版）；要出口栈=照 R8 模式绑（7主+9+4+10+11，11-12 补装实测）|
| ⑥ 公钥三向校验 | ✅ 保留 | 广州 + GIA 两处 authorized_keys（TX/BWG 仅 -L 不需公钥侧写）；md5 对拍 |
| ⑦ mihomo 配置 | ⚠️ 按用途 | 出口栈=mihomo（`firmware/openclash/mihomo-linux-arm64-v1.19.31.gz` 推送解压）+ geosite/Country + init（**respawn 改 3600 0 0**；R8 原版 5 0=漏网勿照抄）+ SUB_URL 注入（`https://127.0.0.1:18443/sub/<devid>?token=<pkg.sub_token>`）+ **gz-api 需配 `AIRPORT_SUB_URL`+`AIRPORT_GENERATION` env（AIRPORT 机场组=平台级渲染非设备字段，缺了发布不带机场）**；透明代理 fw4/nft 规则插线后另实测 |
| ⑧ WiFi/MAC | ⚠️ 改造 | WiFi **保持开**（便携用途；SN 是关）；MAC 无需固定（无 JCG 断电随机化）|
| ⑨ 网页密码 | ✅ 已含 | GL web 改密码即 SSH 同源；SSID 保留出厂（可选统一）|
| ⑩ fw3 include/mihomo-ipt | ⛔ 不适用 | GL=fw4/nftables（与雅典娜同理，iptables 脚本禁套）；access-fw.sh 推送存档但**不挂自启**|
| ⑪ connlog+netprobe | ✅ 保留 | cron 与 R8 完全一致（5 条，见 §四步骤 6）|
| ⑫ 00:00 定时重启 | ✅ 保留 | `0 0 * * * /sbin/reboot #routermgmt-reboot` |
| ⑬ 终验关卡 | ✅ 保留 | 复用 G1-G6（§六），插 WAN 后执行 |
| ⑭ 下发双验 | ⚠️ 按用途 | 纯管理=跳过；出口栈=插线后发布配置并核 desired=accepted（含 AIRPORT 组渲染验证）|
| ⑮ 凭证档案 | ✅ 保留 | 照 [GL-MT3600BE-凭证档案-20261111.md](../../backups/GL-MT3600BE-凭证档案-20261111.md) 格式 |

## 三、GL 特有坑（4+1，全部实测踩过）

| # | 坑 | 对策 |
|---|---|---|
| G1 | OpenSSL 1.1.1 无 Ed25519 raw 验签 | 跳过 install-agent.sh（其自测 fail 即退出），手工写 agent.conf+sign_pub.pem（§四步骤 4）|
| G2 | dropbear 无 sftp-server | 文件全走 base64+md5 双端对拍（脚本 push_b64；heredoc/echo 链禁止——X1）|
| G3 | `/usr/bin/ssh` 是指向 dropbear 的 symlink | 实测可当客户端（dbclient 多调用），mgmt-tunnel-v3 无需改动；换新固件需复测 |
| G4 | GL 自带 chronyd（无 sysntpd） | 插线联网自动校时，无需配置；上线后仍须核时钟（G2 关卡）|
| G5 | tunnel.conf 键名 `VPS_PORT` | **勿照 tunnel.conf.example 模板写 `VPS_SSH_PORT`**（解析器白名单只认 VPS_PORT，静默忽略致隧道不启动）|
| G6 | busybox nc 是裸版（无 -z/-w） | **连通测试禁用 `nc -z`**（全报假 FAIL）——用 curl/ssh 实测（11-12 实测教训：nc 假象延误上线排查一轮）|
| G7 | OpenSSL 1.1.1 缺 Ed25519 raw → switch_node 任务"签名验证失败" | 从 SN-R1（13222）复制 `/usr/bin/openssl-mgmt`+`/usr/lib/mgmt-ssl/{libcrypto.so.3,libssl.so.3}`（handler 自动 export LD_LIBRARY_PATH，无需改脚本）|
| G8 | 时钟停出厂值 + GL DNS 劫持域名到 fake-ip | 心跳 401"时间戳超窗"先修时钟；chrony server **必须 IP 直连**（203.107.6.88/106.55.184.86），域名会被 GL DNS 劫持 |

## 四、标准步骤（幂等，可断点续跑）

**脚本化主入口：`scripts/glinet-onboard-20261111.py`**（幂等：广州 `/tmp/pkg-glinet.json` 存在即复用身份不重复录入）。人工操作时按以下顺序：

1. **平台录入**（经广州本地 API，TOTP 登录）：`POST /devices {name, location_note}` → `POST /devices/enroll {enroll_code}` → pkg.json；改 `mgmt_url=https://127.0.0.1:18443`、`transport_mode=mock`（不配 WG）、`sub_url=空`；落广州 /tmp（幂等锚点）。
2. **组件推送**（base64+md5 对拍）：16 件清单=routermgmt-agent.sh / handlers/switch_node.sh / access-fw.sh / netprobe.sh / connlog.sh / init/routermgmt / init/mgmt-tunnel-v3 / init/wan-watch / wan-watch.sh(+hotplug) / setup-mgmt-tunnel.sh / tunnel.conf.example / install-agent.sh（存档不执行）/ mgmt-port-discovery.sh / tunnel-watchdog.sh / wan-watchdog.sh / onboot-hooks.sh / self-heal.sh。
3. **隧道密钥**：`dropbearkey -t rsa -s 2048 -f /etc/routermgmt/id_dropbear_mgmt`（600）。
4. **agent.conf 手工写入**（G1）：jsonfilter 从 pkg 提 device_id/hmac_key/mgmt_url/sign_public_key → agent.conf(600, 五键齐全) + sign_pub.pem(644)。
5. **tunnel.conf**（G5）：`VPS_PORT` 键名；主=广州 28722（-L 18443 + -R <RSSH>）；备=VPS2 TX/VPS3 BWG/VPS5 GIA；DO 不配；RSSH_TARGET=127.0.0.1:22。
6. **mgmt_active_port 双补丁**（flash 原文两段 awk/sed）：多端口选路 + 心跳失败触发 discovery；补丁后 `sh -n` + grep 双验证（awk 锚点漂移会静默落空），再 cp 到 /usr/bin/routermgmt-agent。
7. **cron 五条**（与 R8 逐字一致）：self-heal 每分钟 / discovery 每分钟(#mgmt-port) / netprobe */5 / connlog */5 / `0 0 * * * /sbin/reboot`。
8. **watchdog**：tunnel-watchdog.sh + wan-watchdog.sh（mode=log）+ onboot-hooks.sh 落位，`sh -n` 全过。
9. **服务使能**：routermgmt/mgmt-tunnel/wan-watch enable；respawn 校验双处 3600 0 0。**不手动 start**（无网空转无意义，插线自启）。
10. **公钥登记**（广州+GIA 两处，同款约束）：`no-agent-forwarding,no-X11-forwarding,no-pty,permitopen="10.10.0.1:8443",permitopen="127.0.0.1:8443",permitlisten="127.0.0.1:<RSSH>" <pub> rtr-mgmt-tunnel-<tag>`；GIA 经广州 sshpass。追加后 grep 对拍。
11. **凭证档案**（⑮）：backups/ 一份，含身份/口令/通道/坑位/待办。

## 五、安全基线（本流程默认态，实测）

- fw4 wan zone `input=DROP` → WAN 侧 22/80 不可达（dropbear 虽监听 0.0.0.0，被防火墙挡）✅
- 反向口约束 no-pty + permitopen×2 + permitlisten×1（无 restrict——X2 禁令）✅
- WiFi 出厂密码弱 → 已由用户改舰队统一口令；SSID 保留出厂 ✅

## 六、插 WAN 后验收（G1-G6 + 时钟）

| 关 | 检查 | 标准 |
|---|---|---|
| G1 | 心跳入库 | last_heartbeat_at ≤90s（rtr-e9ccdd）|
| G2 | 远程实登 | 广州 `ssh -p 13234`（或 GIA）root 实登 OK |
| G3 | 时钟（GL 加严） | chrony 同步后 date 与北京时差 <60s |
| G4 | 出网/补丁实效 | agent 日志时间戳恢复正常；`/tmp/mgmt_active_port` 机制可用（discovery 有写）|
| G5 | 备用端点实效 | 隧道实例数=4（广州+TX+BWG+GIA）；GIA 备用 -R 通 |
| G6 | 自愈在位 | self-heal v3.1 md5 329c6081 + cron 5 条 + 无 pause |

任一 FAIL 停下排查；全过 → 档案补"上线实测"段 + 当前状态.md 加条目。
