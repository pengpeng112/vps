## 一、核心原则（不可违反）

| # | 原则 | 出处 |
|---|---|---|
| P1 | **禁止通过反向 SSH echo/base64 链推送文件**；文件只走 SCP/SFTP/LAN | R8 10-29 文件损坏全服务挂 |
| P2 | **一次只推一个变更，验证通过再推下一个** | R8 一次推 6 组件全失败 |
| P3 | **改动前备份原文件 + 记录 md5** | 每轮脚本标配 |
| P4 | respawn 修改后 `/etc/init.d/<svc> restart` 即生效（procd 重建实例重读参数），**无需整机断电重启** | R8 10-31 实测（uptime 33min 未重启整机，服务稳定） |
| P5 | **-L 与 -R 是独立实例，分开验证**（-L 通不代表 -R 通） | Codex 实证 |
| P6 | 应急脚本走本地 LAN（向日葵），不走远程隧道 | LAN 直连可靠 |
| P7 | self-heal v3.1 事务保护不绕过；配置应用窗口 `touch /tmp/selfheal.pause` 双保险 | R6 回滚事故 10-30 |

## 二、平台硬前提（每次升级前必做）

### 2.1 平台分工（2026-10-31 晚更新：§2.2 已完成）

| 平台 | 角色 | 状态 |
|---|---|---|
| 广州 gz-api（nginx 8443 TLS → Go 127.0.0.1:8080） | **全功能主平台**：心跳、任务、配置发布、监控、远程 SSH | ✅ 2026-10-31 完成二进制重编译（含 vless-ws/istarshine）+ CF/CF2 节点导入 + 签名私钥同步 DMIT，R8 v6 发布实测全通 |
| DMIT api 容器 | 参照库/温备（设备不再连它，任务收不到） | ✅ 运行中 |

Go 后端无内置 TLS、端口只认 `LISTEN` env（`-port` 参数无效）——10-31 根因定案，勿再试。

### 2.2 ~~第 0 步阻塞项~~（✅ 2026-10-31 晚已完成，留存操作记录）

广州平台补齐实录（后续重建/再迁移照此）：
1. **二进制**：本地 `mgmt/backend` 交叉编译 `GOOS=linux GOARCH=amd64 CGO_ENABLED=0` → 广州 `/opt/mgmt/server`（旧件备份 `server.bak-20261031`，库备份 `db-backup-20261031.sql`）。
2. **节点**：DMIT 库 `format()` 导出 nodes 10/11 为 INSERT（密文直拷，密钥一致故有效；布尔值必须输出 `true/false` 字面量——`t`/`f`/整数都会语法错）。
3. **签名私钥**：DMIT `/data/signing_ed25519(.pub).pem` → 广州 `/data/`（设备端验签公钥认 DMIT 系）。**pub 指纹 DMIT=81b85fe1**，广州自生成的（22ea1f8e）作废。
4. **MASTER_KEY 教训（X14）**：`mgmt/deploy/.env` 里的值是**过时未生效值**；DMIT 容器与广州 unit 的运行真值=0d5665c7…（两者一致）。**对拍密钥必须取运行中进程/容器的 environ，不能取仓库配置文件**。曾按 .env 换 KEY 导致 TOTP 全 401，回滚即恢复。
5. 验收链：`strings | grep vless-ws` ≥1 → TOTP 登录 TOKEN_OK → preview diff 方向核对 → apply → 任务 ok → 设备端 G1-G6。

### 2.3 服务器三件套（1 分钟检查）

```bash
curl -sk https://127.0.0.1:8443/api/v1/health   # 200
systemctl is-active nginx gz-api                 # 双 active
ss -tln | grep -E ':8443|:8080|132[0-9]{2}'      # 目标设备反向口状态
```
任一不满足 → 先修平台再动设备。广州 8443 **公网必须保持 000**（安全组收口；设备走 SSH -L 不受影响）。

## 五、S0 在线升级（逐项推送，风险从低到高）

```
① uci 命令（fw3 include、网页密码）— 无文件传输，最安全
② 小文件 via SCP from 广州（<2KB）
③ 脚本文件 via SFTP→SCP 链（self-heal.sh、tunnel-watchdog）
④ init 脚本 via SFTP→SCP 链（最后推，风险最高；推完 sh -n，择窗 restart）
```

- 配置发布（平台任务）：等 §2.2 完成。发布前导出设备当前 config.yaml+md5；发布后核对 desired=accepted；期间 `touch /tmp/selfheal.pause`，验收后删除。
- agent/handler 更新：旧 agent 包（2905/2906）缺多端口选路补丁，**推送前核对包内容与 main 一致**；handler 新文件需 agent restart 才加载。

## 六、S3 离线回线（R7/R9/R10/R11 适用）

这些设备 10-14 刷机后端点全部失效（DMIT 旧 IP 被墙、GIA 已换 IP），**通电后隧道必然建不起来**。

1. **通电前**（广州侧）：清目标设备 stale 反向口会话（`ss -tlnp | grep 132xx` → 只杀该口 sshd-session，不动其他）。
2. **向日葵现场**：`scripts/emergency-kit/fix-router.bat` + `fix-cmds.txt`（plink stdin，勿手敲）。一轮完成 T1-T7，成功判据=现场窗口看到 `HEALTH: 200`、`EGRESS: <GIA IP>`、`AGENT: ≥1`、`CRON: 1`、`ALL_DONE`。
3. **FAIL 处理**：现场重试不超 1 次；再 FAIL 改跑 `diag-cmds.txt` 收 `DIAG_DONE` 输出回来分析，禁止盲改。
4. **回管验证**：广州库心跳 ≤90s + 132xx sshpass 实登 + 时钟核对（R8 实证：时钟漂移让 TLS 心跳假死）。
5. 转路径 A 补齐剩余项（配置发布等 §2.2）。

### 应急脚本维护规则

| 规则 | 说明 |
|---|---|
| 修复时间目标 | <60 秒 |
| 文件大小 | <8KB（plink -m 安全范围） |
| 必含 | 隧道修复（T1-T3）+ respawn（T4）+ self-heal v3.1（T5） |
| 可选 | fw3 include（uci 命令，安全） |
| 禁含 | init 脚本推送（太大 + 损坏风险） |
| 修改后 | 必须先在一台在线设备验证一轮再交付现场 |
