## 5. SN-R1 上装的代理

没有换整机系统。用雅典娜同一份分流配置（`F:\vps\scripts\clash-config-router.yaml`）。

| 项 | 路径 |
|----|------|
| 程序 | `/usr/bin/mihomo`，Meta v1.19.31。本机原件 `F:\vps\firmware\openclash\mihomo-linux-arm64-v1.19.31.gz` |
| 配置 | `/etc/mihomo/config.yaml` |
| 规则库 | `/etc/mihomo/geosite.dat`、`geoip.metadb`、`country.mmdb` |
| 开机 | `/etc/init.d/mihomo`，源文件 `F:\vps\scripts\snr1-mihomo.init` |
| 透明代理 | `/etc/mihomo-ipt.sh`，源文件 `F:\vps\scripts\snr1-mihomo-ipt.sh` |
| 防火墙回调 | `/etc/firewall.user` 里调用 `/etc/mihomo-ipt.sh` |

规则和雅典娜相同：国内直连，境外走 `159.223.36.119:443`。只劫持 `br-lan` 上的 TCP 和 DNS。私网、以及 **VPS 整个 IP（全端口）**，不劫持（`mihomo-ipt.sh` 里 `-d ${VPS}/32 -j RETURN`，不只是 443——28722 管理隧道/管理 SSH 都直连，这点排查网络时很关键）。

**2026-09-23 深夜补：QUIC/HTTP3(UDP 443) 必须丢弃**（`iptables -I FORWARD -i br-lan -p udp --dport 443 -j DROP`，已入脚本）。否则 Chrome 优先走 UDP 443 直连出公司网，被安全设备干扰后报"异常的错误凭证/HSTS"（chatgpt.com 当天实际踩中；TCP 链路本身证书是真的）。雅典娜版 mihomo_fw.sh 一直有这条，iptables 移植时漏了。另有 PC 侧坑：**双网卡挂在两台路由时代留下的旧 DNS（无线曾指 192.168.2.1）会造成两台 mihomo 的 fake-ip 交叉污染**——两网卡都在 SN-R1 时 DNS 必须统一 192.168.132.1。

硬件加速在装规则时写成关闭：`echo 0 > /sys/kernel/debug/hnat/hook_toggle`。不关的话，转发会绕过 iptables，代理不生效。

装的时候路由器时钟停在 2024 年，HTTPS 证书会失败。已把时间拨到 2026-09-23 并打开 `sysntpd`。同类机器如果证书报日期错误，先对时。

撤回透明代理、不删程序：`/etc/mihomo-ipt.sh stop`。这会拆掉劫持规则，并把 DNS 改回原来的上级解析。

验收时：路由器上 `curl -x http://127.0.0.1:7890 https://github.com/` 返回 200；百度走直连。电脑有线百度仍是 200。

## 6. SN-R1 上装的远程管理

管理台下发的能力和雅典娜相同：VPS 限速、授权到期/停用、运行模式、访问模式、定时重启、拉取诊断。

| 项 | 值 |
|----|----|
| 心跳地址 | 路由器里的 `https://127.0.0.1:18443` |
| 隧道 | `/etc/init.d/mgmt-tunnel`，转到 VPS 的 `10.10.0.1:8443`，SSH 端口 28722 |
| 密钥 | `/etc/routermgmt/id_dropbear_mgmt` |
| VPS 公钥注释 | `snr1-mgmt-tunnel`，只允许转发到 `10.10.0.1:8443` |
| Agent | `/usr/bin/routermgmt-agent`，配置 `/etc/routermgmt/agent.conf` |
| 策略落地 | `/etc/routermgmt/handlers/switch_node.sh` |
| 访问控制 | `/etc/routermgmt/access-fw.sh`，源文件 `F:\vps\scripts\snr1-access-fw.sh` |

和雅典娜的差别：

- 限速用 iptables 链 `VPS_QOS` / `VPS_QOS_IN`，只打到 VPS 的 443，国内不限。授权关掉时，这两条链改为直接丢弃到 VPS 的 443。
- 访问模式用 ipset `rmgmt_acc` 和 nat 链 `MIHOMO_ACC`。白名单、黑名单目前只认 IPv4，不认 MAC。
- 运行模式除了热切换，还会改 `/etc/mihomo/config.yaml` 里的 `mode:`。雅典娜改的是 `/etc/mihomo/run.yaml`，两边脚本现在都会改这两个文件里存在的那份。
- 配置热加载失败时，会再试 `/etc/init.d/mihomo restart`。

当前下发结果：授权开、限速 0、策略分流、全部设备。心跳已成功。

**2026-09-23 晚补充（验签修复 + 全功能回归）**：
- 发现厂商 openssl 1.1.1s 的 `pkeyutl` **无 `-rawin` 选项**（Ed25519 验签必需，3.0 才有）→ switch_node / reload_proxy / agent_update 一律"配置签名验证失败"。

- 修复后全功能实测通过：switch_node（配置 v1，出口 159.223.36.119）、reload_proxy、set_proxy_state 停用/启用（group DIRECT/AUTO）、重启闭环（boot_id_changed=true，约 48s 回网、代理/心跳/隧道全自愈）。

管理台入口不变：电脑上打开「管理台通道.bat」，浏览器进 `https://127.0.0.1:8443`，设备列表里找 SN-R1-AX3000。

## 8. 下一台同样的 SN-R1 怎么做

1. 网页登录后**立即改 root 口令并换掉全部 Wi-Fi 密钥**（网页/SSH 同源 shadow；busybox 无 chpasswd，用交互式 `passwd root`；发货机严禁带默认口令出厂——SSH `abc@1234`/网页 `12345678`/Wi-Fi `12345678` 这类都是出厂弱口令，必须全换）。
2. SSH 进去，按第 4 节卸掉 PCDN，关掉 Telnet、文件共享、UPnP、自动升级和 `mtk_dut`。
3. WAN 接到一台已经能上网的上级（本工位是雅典娜 LAN）。确认路由器自己能 ping 通 `223.5.5.5` 和 `159.223.36.119`。
4. 如果系统时间停在旧年份，先 `date -s` 并打开 `sysntpd`，否则 Reality 证书失败。
5. 上传第 5 节的 mihomo、规则库、配置和 iptables 脚本，`/etc/init.d/mihomo enable && start`。先确认 GitHub 经 `127.0.0.1:7890` 返回 200，再让它装劫持规则。核心没起来时，`mihomo-ipt.sh` 会拆掉劫持，避免把局域网 DNS 卡死。
6. 管理台新建设备，用注册码 enroll。dropbear 用 RSA 做隧道密钥，公钥追加到 VPS `/root/.ssh/authorized_keys`，限制为 `permitopen="10.10.0.1:8443"`。
7. `MGMT_URL=https://127.0.0.1:18443`，启动 `mgmt-tunnel` 和 `routermgmt`。健康检查应是 200，日志里有 `heartbeat ok` 和 `policy applied`。
8. 若操作员电脑同时插着雅典娜网线又连着这台 Wi-Fi，把无线 DNS 指到雅典娜，不要用 SN-R1 的 DNS。
9. **PCDN 清理后重启一次复查**：`rc.local` 里的 `# disabled-pcdn` 注释还在、`/etc/m-box` 未再生、crontab 仍只剩 `factory checkMem`。
10. 运维红线：电脑上的 `AIHMS-JumpTunnel` 计划任务已常驻跳板隧道，**不要手动再双击 `tunnel.bat` 起第二个实例**——双实例抢 -R 端口会无限重试，2026-09-23 曾把 VPS ufw 的 limit（recent 模块）打成全网 28722 连接锁死 40 分钟（持续敲门=永不解封）。当天已把 VPS 28722 从 LIMIT 改为 ALLOW（fail2ban 仍兜底）规避，但双实例本身仍会互抢端口。
11. **同机型必须部署 openssl3**（见 §6 补充）：官方 21.02 源的 1.1.1t 也不行（`-rawin` 是 3.0 特性），直接用 `F:\vps\firmware\snr1-openssl3\` 三件套传到 `/usr/bin/openssl-mgmt` + `/usr/lib/mgmt-ssl/`。验证：`LD_LIBRARY_PATH=/usr/lib/mgmt-ssl /usr/bin/openssl-mgmt pkeyutl -help | grep rawin` 有输出。

不要把雅典娜上的 `/etc/borrow18-ssh.nft` 和 `99-borrow18-ssh` 拷过来。
