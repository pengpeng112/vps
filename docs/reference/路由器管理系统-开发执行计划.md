## 2. 总体架构（已定稿，勿改）

```
管理员电脑/手机 ──WireGuard Peer──> 管理VPS（业务公网入口仅 WireGuard UDP）
                                      ├─ API（仅监听 WG 内网 10.10.0.1:8443）
                                      ├─ PostgreSQL + 配置仓库(带版本)
                                      ├─ 订阅生成器（per-device token URL）
                                      └─ WireGuard Hub（每路由器一个 Peer，独立密钥）
路由器 ×20~30 ──主动回连 WG──> 管理VPS          （NAT 友好，家庭侧零入站端口）
路由器 ──VLESS+Reality TCP 443──> 出口VPS池 ×N   （sing-box，与管理VPS物理分离）
```

**铁律：**

1. 管理面与代理面物理分离。出口节点全挂，仍能经 WG 管路由器。
2. 路由器只主动外连（WG + 任务轮询）。LuCI/SSH 仅允许可信 LAN 与管理员 WG Peer 访问，禁止路由器 Peer 互访。
3. 每台设备独立：WG 密钥对 + 订阅 token + Agent HMAC 密钥。单台泄露可单独吊销。
4. 配置变更 = 版本化 + 健康检查 + 自动回滚。禁止默认下发任意 shell。
5. 管理网页只绑 WG 私网。公网业务入口只开 WG UDP；运维 SSH 是明确例外，限定管理员来源并仅密钥登录。换端口不能替代访问控制。

**地址约定（写死，避免各写各的）：**

| 用途 | 地址 |
|------|------|
| 管理 VPS WG 地址 | `10.10.0.1/24` |
| 管理员 Peer | `10.10.0.2/32`～`10.10.0.9/32`（不得占用设备地址池） |
| 路由器 Peer | `10.10.0.10`～`10.10.0.250`，与 device_id 绑定后不再变 |
| API | `https://10.10.0.1:8443`（由 web 反代统一提供；CA 随离线引导包固定） |
| 订阅 | `https://10.10.0.1:8443/sub/{device_id}?token=...`（只走 WG） |

## 3. 分流与省流量铁律（P0，订阅生成器验收项）

出口 VPS 按流量/带宽花钱。错误分流会把 B 站/抖音/微信 CDN 打到新加坡。

2026-09-13 在出口节点日志里已抓到反例：`st.pinyin.sogou.com`（搜狗拼音）走了 VPS。原因是当时 Clash 只有 `GEOIP,CN`，没有 `GEOSITE,cn` / 国内视频名单，且本机 TUN 把非 CN IP 的国内域名送进节点。

### 3.1 策略

| 流量 | 出口 | 实现 |
|------|------|------|
| 内网 RFC1918 / CGNAT / 链路本地 | 直连 | `GEOIP,private` + CIDR |
| 节点自身公网 IP | **直连** | `IP-CIDR,<node_ip>/32,DIRECT,no-resolve`。不做这条，Clash TUN 会把 SSH 绕回节点；服务端已拒绝访问自身 IP，表现为 `Connection closed` |
| 国内视频/短视频/直播（B 站、爱奇艺、优酷、腾讯视频、芒果、抖音、快手、小红书、西瓜） | **直连**，且 `CN-MEDIA` 组只允许 DIRECT | GEOSITE + DOMAIN-SUFFIX，见黄金模板 |
| 国内互联网（腾讯/阿里/百度/网易/小米/微信/淘宝等） | 直连 | `GEOSITE,cn` + 厂商 geosite + `GEOIP,CN,DIRECT,no-resolve` |
| Steam 内容 / Windows Update / Apple swcdn | 默认直连 | `DOWNLOAD` 组：DIRECT 在前，PROXY 备选 |
| 境外网站（Google/YouTube/GitHub/ChatGPT 等） | VPS | `MATCH,PROXY` |
| 未被前面直连规则命中的 UDP/443 | REJECT | 保留模板当前策略，促使相关客户端回退 TCP；不是全局封禁国内 QUIC，也不据此推断协议不能承载 UDP |

`CN-MEDIA` 组的 proxies **只能有 DIRECT**，防止有人在面板里把视频组切到节点。

### 3.2 订阅生成器硬性检查（CI / 单测必须 assert）

生成出来的 YAML 必须同时满足：

- 含 `GEOSITE,cn,DIRECT` 与 `GEOIP,CN,DIRECT,no-resolve`
- 含 `CN-MEDIA` 组且该组 proxies 只有 `DIRECT`
- 含节点公网 IP 的 `IP-CIDR,<host>/32,DIRECT,no-resolve`（host 来自该设备绑定节点）
- `MATCH,PROXY` 是 rules 最后一条
- 含 `dns.enhanced-mode: fake-ip`（没有 fake-ip 时，污染 IP 会被 GEOIP,CN 误判直连，境外站打不开；有 fake-ip 但没有 GEOSITE,cn 时，国内域名会进节点烧钱）
- **不得**把 `akamaized.net` 整段送 CN-MEDIA（国内外站点共用）

完整规则以 `scripts/clash-config-router.yaml` 为策略基线。原文件含现网凭据，禁止直接复制或 `go:embed` 整个原文件。先提取删除 proxies 及静态节点引用后的无凭据模板，再按绑定节点渲染并做结构差异测试。动态替换全部节点直连地址，不得遗留原节点硬编码。Session 1 节点 host 限 IPv4 字面量；域名/IPv6 节点在实现解析与对应直连规则前返回明确的校验错误。

分流验收验证规则实际命中，不承诺仅靠一份域名表覆盖所有国内服务。未知域名按末尾 MATCH 处理；发现误分流须补充最小范围规则并增加用例。管理 VPS 公网 endpoint 也必须直连，避免 WG 套入代理。

### 3.3 流量计量（省钱可观测）

心跳指标必须能区分：

- `wan_rx_bytes` / `wan_tx_bytes`：WAN 口累计
- `proxy_rx_bytes` / `proxy_tx_bytes`：Clash/OpenClash 走节点的累计（OpenClash 连接统计或 `iptables` 标记链，必须识别实际经过代理节点的连接并按增量累计，不能把 Clash 全部连接总量当节点流量；不可采集时返回 null 与 unavailable，不得伪造为 0，详见 §19.5）
- Dashboard 展示「本月节点流量」排在「WAN 总量」前面，并设阈值告警（默认 80GB/设备/月，可配）

## 7. Agent 通信协议（按此实现，不要自行发挥）

### 7.1 设备请求头（心跳、拉任务、回结果）

```
X-Device-Id: rtr-008
X-Timestamp: 1760000000
X-Nonce: <每次请求新生成的32位小写hex>
Authorization: HMAC-SHA256 <hex>
```

Canonical 字符串（UTF-8）：

```
{device_id}\n{timestamp}\n{nonce}\n{METHOD}\n{path}\n{sha256hex(raw_body)}
```

- `path` 不含 query。例：`/api/v1/agent/heartbeat`、`/api/v1/agent/tasks`
- GET 的 body 视为空，`sha256hex("")` = `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`
- HMAC-SHA256 的 key 统一为 **32 字节随机数编码成的 64 个小写 hex 字符的 ASCII 字节**，不再解码。服务端与 Agent 必须遵守同一规则。
- 时间窗 ±120 秒，超出直接 401；验签通过后原子占用 `(device_id, nonce)`，重复请求拒绝。nonce 至少保留 300 秒并持久化，服务重启不得清空防重放状态。重试必须生成新 nonce。
- METHOD 大写；path 为固定接口的原始路径，不含 query；Agent 接口禁止 query 参数，避免未签名参数影响行为。身份以签名中的 device_id 和请求头一致值为准。比较签名使用常量时间比较。
- 服务端用 AES-GCM 解出原始 HMAC key 再算，**不能只存 sha256 哈希**（哈希无法验证 HMAC）

openssl 示例（ash）：

```sh
# BODY_FILE 保存实际发送的 UTF-8 JSON 字节；GET 使用空文件。
# 不把原始随机二进制密钥放入 shell 变量。
BODY_HASH=$(openssl dgst -sha256 -hex "$BODY_FILE" | awk '{print $NF}')
SIG=$(printf '%s\n%s\n%s\n%s\n%s\n%s' \
  "$DEVICE_ID" "$TS" "$NONCE" "$METHOD" "$REQUEST_PATH" "$BODY_HASH" \
  | openssl dgst -sha256 -hmac "$HMAC_KEY" -hex | awk '{print $NF}')
# POST 用 curl --data-binary @"$BODY_FILE"，确保验签字节与发送字节一致。
```

上例字段间是真实 LF，末尾没有 LF。不得使用 `MSG="...\n..."` 再 `printf '%s'`，该写法会签入字面量反斜杠。不得用 PATH 作请求路径变量（会覆盖 shell 命令搜索路径）。提交跨 Go/ash 的固定输入、canonical 字节和期望签名测试向量；仅使用测试密钥。

```json
  ]
}
```

回结果 `POST /api/v1/agent/tasks/{id}/result`（HMAC）：

```json
{ "lease_id": "...", "status": "ok|failed|rolled_back", "detail": { "exit_ip": "...", "error": "" } }
```

连续 `rolled_back` ≥ 2 次 → 告警。

### 7.5 switch_node 原子流程（必须含回滚）

1. 持久化任务 ID，获取任务绑定的不可变配置版本（HMAC 下载）；检查设备 ID、版本、内容哈希与签名。不得从“最新订阅”代替指定版本。
2. 配置下载到同文件系统的临时文件，权限 600；使用已探测的 mihomo 核心进行配置校验。核心路径与命令须在目标版本验证，不得猜测成功。
3. **切换前**备份当前配置、活动路径与组选择状态，并落盘事务日志。设置不依赖 API 连通性的本地回滚看门狗。
4. 原子替换活动配置，通过已验证的 OpenClash 适配器加载；确保 PROXY 指向目标节点，避免 AUTO 或持久化旧选择使“切换节点”失效。
5. 30s 内等待服务就绪；在任务总时限内验证代理出口、国内直连和管理 HTTPS 连通。固定 IP 节点要求两次代理出口探测与 `expect_exit_ip` 一致。探测地址可配置，外部探测服务不可用与节点不可用分别记录。
6. 成功后提交当前版本、取消回滚看门狗、持久化结果并回报 ok。回报失败只重传结果，不再次切换。
7. 应用/健康检查失败，或中途进程退出后恢复时发现未提交事务：恢复切换前备份与选择状态并重启代理；验证恢复成功才报 rolled_back。恢复也失败则报 failed、`rollback_failed=true` 并触发高优先级告警。

签名 payload 精确定义（UTF-8，字段间 LF、末尾无 LF）：

```text
lowercase_hex(SHA256(yaml_bytes)) + "\n" + device_id + "\n" + decimal_version
sig = Ed25519.Sign(private_key, payload)
```

响应头：`X-Config-Version`、`X-Signature`（128 个小写 hex 字符）、`Cache-Control: no-store`、`Content-Type: text/yaml; charset=utf-8`。签名针对返回的 YAML 原始字节；不得在签名后重排或重新序列化。

Agent 固定 PEM 公钥，签名解码为二进制后验签。安装时用已知测试向量检查目标 OpenSSL 是否支持 Ed25519；缺能力就明确阻止配置应用，不得跳过验证。首次基线版本为 0，新版本严格递增；同版本同哈希重复任务只返回已有结果，不重执行。本地恢复已验证备份允许回到旧活动版本，但保留最高已接受版本，防止重放。管理员回退必须将旧内容重新发布为更高版本。

### 7.6 订阅 `GET /sub/{device_id}?token=`

- 用 `sha256(token)` 比对 `sub_token_hash`
- 仅返回该设备已经发布的最新不可变配置；无绑定节点或尚未发布返回 409，禁止回退到全部节点。候选节点只包含授权绑定且 enabled 的节点。GET 不生成版本、不更改当前生效状态。
- 保留订阅 URL 作为受控导出/诊断接口，只允许 WG 或本机开发访问。**正式配置只能由 Agent 下载、验签、应用；禁止开启 OpenClash 原生订阅定时更新**，避免绕过签名和回滚。订阅 token 不持久化明文，因此服务端不能重新展示完整 URL；管理员丢失后只能轮换。

密钥：`MASTER_KEY` 32 字节做 AES-256-GCM。JWT 另用 `JWT_SECRET`。开发首次启动若空，生成并写入持久化 `DATA_DIR`（文件 600、目录 700）；生产缺失密钥直接报错。MASTER_KEY 使用 64 hex 配置并解码成 32 字节，勿与 HMAC 的 ASCII 约定混淆。AES-GCM 每次随机 nonce，并绑定记录 ID/字段名作为 AAD。签名私钥、JWT_SECRET 与 MASTER_KEY 分开持久化；数据库有数据时禁止静默重建密钥。备份须含加密数据的解密材料。

## 11. 安全需求（验收勾选）

### 11.1 管理台（开发必须做）

1. 裸进程开发默认监听 loopback；容器 API 可监听容器内 `0.0.0.0:8443`，不发布宿主机端口。web 开发仅映射 `127.0.0.1:8080`，生产仅映射 `10.10.0.1:8443` 并终止 TLS。
2. DB 不映射公网端口（compose 不要 `5432:5432`，只用内部网络；开发可另开）
3. HMAC key / WG 私钥 / 节点 proto params：AES-GCM 落库；订阅 token 只存 hash
4. YAML 必签；Agent 拒签失败与版本回退
5. 审计无删除 API
6. argon2id + TOTP；JWT 12h
7. 日志/前端/异常 **禁止**打印 uuid/pbk/sid 全文
8. 依赖与镜像扫描 Session 2 再接 trivy，Session 1 不阻塞

### 11.2 出口 VPS（已于 2026-09-13 落地，开发 AI 不要回滚）

现网 `159.223.36.119`（Ubuntu 24.04.4，sing-box 1.14.0，SSH 28722 仅密钥）已做：

| 项 | 结果 |
|----|------|
| 公网监听 | 仅 `443/tcp`（sing-box）与 `28722/tcp`（sshd）。UFW deny 22 |
| 残留 Xray | `/usr/local/bin/xray` 已删除（服务本就 disable） |
| sing-box | `log.level=warn`（不再 info 记录每个目标域名）；`route`：`ip_is_private reject` + 拒绝本机 IP / `169.254.169.254` / VPC `10.104.0.0/16`（防经代理打 SSH/元数据） |
| systemd | `ProtectSystem=strict` 等沙箱；**不要**加 `MemoryDenyWriteExecute`（会弄死 Go） |
| sshd | 禁密码、禁 X11、禁 TCP 转发、`MaxStartups 10:30:60`（不要再用 3:50:10，扫描会占满未认证槽） |
| fail2ban | jail `sshd` port 28722；Ubuntu 24.04 的 unit 是 `ssh.service`，filter `journalmatch` 必须用它，不能写 `sshd.service` |
| sysctl | 关 send_redirects、accept_ra，suid_dumpable=0 等 |
| 无用服务 | ModemManager、multipathd 已 disable |
| 未动 | Reality 密钥/UUID/443 端口；do-agent / droplet-agent 保留（DO 控制台救援需要） |

脚本：`scripts/vps-harden.sh`（可重复执行）。sing-box 1.14 **禁止**在 inbound 写 `sniff` 旧字段，用 `route.rules: [{action: sniff}, {action: reject, ...}]`。

客户端 TUN 必须把节点 IP DIRECT，见 §3.1。本机已加持久路由：`159.223.36.119 → 10.1.2.254`。

### 11.3 出口 VPS 仍建议由人做、开发不做

- DigitalOcean 账户开 2FA；赠金约 2026-09-29 耗尽，需绑卡
- SSH 私钥加口令：`ssh-keygen -p -f C:\Users\Administrator\.ssh\id_ed25519_digitalocean`
- 每设备独立 UUID（Session 2 管理端生成，另用脚本写入 sing-box `users` 数组后 reload）

## 14. Agent 行为要点

- 配置文件 `/etc/routermgmt/agent.conf` mode 600，内容：`DEVICE_ID` `HMAC_KEY` `MGMT_URL` `SUB_URL` `SIGN_PUB`
- 主循环：心跳 60s、任务 10s；单任务超时 deadline 或 120s
- `switch_node` 见 §7.5；`reboot` 必须先落盘执行标记，重启后确认 boot_id 变化再回报成功；`reload_proxy` 需健康检查；`ping_test` 参数 `{host}` 回 delay，限制目标格式/次数/超时，不经 eval 或拼接 shell 执行。
- OpenClash 配置目录以真机为准，安装脚本探测：
  - `/etc/openclash/config/`
  - 若无则 `/etc/clash/`
  - 找不到则任务失败并上报路径列表，禁止瞎写
- 缺依赖由安装脚本探测、安装并验证；无法安装则明确失败。禁止用 sed/正则解析任务 JSON；使用 jsonfilter。不得对服务器参数 eval；配置文件若被 source，只允许经过严格编码的本地生成内容。

## 19. 实现补充规范（与前文共同构成验收要求）

### 19.1 首次注册与信任引导

生产 API 只在 WG 内可达，因此没有 WG 的路由器不能直接向管理 API enroll。统一采用以下流程，禁止临时开放公网 enroll 接口：

1. 管理员通过自己的 WG 登录，创建设备并取得一次性 enroll_code（32 字节随机数的 hex，有效期 30 分钟，数据库仅存 hash）。
2. 管理员在受信任电脑上使用交付的 provisioning CLI 代设备调用 enroll。Session 1 使用 localhost HTTP；生产使用 WG HTTPS 并校验证书。
3. CLI 将响应写为离线引导包，包含设备凭据、WG 配置、固定的管理 CA 与签名公钥、管理 URL。文件权限 600，不在终端打印秘密，不写入代码目录或测试报告。
4. 管理员通过可信 LAN 的 SSH/本地介质把引导包交给安装脚本。路由器导入配置后建立 WG，再开始 HMAC 心跳与拉取任务。引导包使用完毕清理临时副本。
5. Session 2 enroll 先记录 Peer 为 provisioning，由宿主机受限适配器同步到 WG；同步成功才将设备标记 approved 并发放有效引导结果。重试不得重复分配 IP；同步失败可修复重试。
6. enroll_code 消耗、凭据生成和设备更新须事务化，只允许一个并发请求成功。若响应丢失，管理员重置 pending 注册并重新生成整套凭据，旧 Peer/凭据先撤销；不得为重取秘密开放匿名接口。

Session 1 可以不启动 WG，但响应必须标明 `transport_mode=mock`。生产不允许空 Hub key/endpoint，也禁止 `curl -k`。`/meta` 仅供显示，不能作为首次信任根。

WG Hub 对每个设备 Peer 的 AllowedIPs 仅配置该设备 `/32`；路由器只路由管理网段，不接管默认路由。主机防火墙同时限制设备 Peer 互访及管理端口权限，不能仅依赖 AllowedIPs。部署前检测 `10.10.0.0/24` 是否与现场 LAN 冲突；有冲突时阻止安装并记录待调整地址规划。

### 19.2 任务领取、重试与幂等

- 创建运维任务要求 `Idempotency-Key`。同管理员、设备、key 和相同请求返回原任务；key 相同但内容不同返回 409。批量操作返回每台设备的任务或错误，不假装全成功。
- 一台设备最多一个有副作用的运行任务。服务端以数据库事务原子领取，返回 `lease_id`；运行期间正常心跳附带 task_id/lease_id 续租。任务硬 deadline 不因续租延长。
- `pending → running → ok|failed|rolled_back`；尚未领取就超期为 expired，撤销设备时未执行任务为 cancelled。已执行但租约丢失/结果不明为 unknown，不能直接按失败再次执行。
- Agent 持久化任务 ID、执行阶段与最终结果。网络重试仅重传结果；新 nonce 用于通信防重放，task_id 用于副作用去重，两者不可互相替代。
- 结果回传验证设备归属及 lease_id；相同最终结果重复回传返回成功，冲突结果返回 409。未知状态通过同一任务的落盘记录与当前状态核对，不新建一个 reboot 重试。
- reboot 必须有重启前持久化标记和重启后 boot_id 证据。没有重启后心跳只能保持 running/unknown，不能提前报 ok。
- 单任务默认 120s；心跳与结果重传不得被长任务阻塞。Session 2 的 speedtest 单独设置时限、并发上限与流量预算，并在 UI 执行前展示预计消耗。
- change_wifi、set_dns、reload_wireguard 都属于可能断连的配置任务，沿用预备份、本地超时恢复与恢复后校验；不允许只调用命令就报成功。

### 19.3 配置版本、绑定与故障转移

- 区分 desired_config_version（已发布目标）、current_config_version（设备证实生效）、highest_accepted_version（Agent 防重放高水位）；创建任务不能直接改写 current。
- `(device_id, version)` 唯一且单调递增；发布、保存加密快照与任务入队必须在同一事务内完成。任务保存 config_id/version/hash，不保存含 token 的 config_url；响应中按需构造 HMAC 下载路径。
- 修改节点或绑定只影响后续版本，不改历史快照。批量绑定默认只更新期望绑定；请求中明确 `apply=true` 才为每台设备生成发布任务，响应逐台列明结果。
- 设备配置只能引用绑定且启用的节点；必须有且仅有一个 primary。无可用节点时禁止发布，保留设备当前配置并告警。节点 TCP 可达不等于 Reality 鉴权或代理出口可用，分别展示探测类型。
- Session 1 手动 switch_node 固定 PROXY 到所选节点。Session 2 自动故障转移仅在明确启用 auto_failover 时生效，使用绑定候选节点中的 fallback 组；保留国内直连策略，增加这一明确的动态组差异测试。故障时不隐式切 DIRECT；持续主节点故障才切换，并设置恢复冷却时间，避免频繁来回切换。
- 原模板 AUTO 为 url-test，表示择优测速，不能把它的存在作为“主备故障转移已完成”的证据。UI 分别展示期望主节点、实际节点、自动模式与最近切换原因。
- preview 返回 revision/hash 与掩码 diff；apply 携带 revision，若绑定/节点参数期间发生变化返回 409，要求重新预览。
- 禁止用户在 OpenClash 中开启会绕过 Agent 的订阅自动更新。安装时检查策略覆写、当前 PROXY 选择和 geosite 数据源；规则文件存在不代表运行时规则生效。

### 19.4 测试数据、秘密与管理员认证

- 默认开发和 CI 全部使用虚构节点与专用测试密钥，不自动读取现网秘密。现网 YAML、引导包、`.env`、数据库备份与本地 DATA_DIR 必须排除出版本控制。
- YAML 快照、节点参数、WG 私钥、HMAC key、TOTP secret 均加密落库。API 用明确 DTO 白名单序列化，禁止直接序列化 GORM model；审计、错误和反代访问日志同样脱敏。
- `pbk` 虽是公钥，仍按项目要求掩码。前端创建凭据表单允许输入，保存后的响应、列表、详情和预览不得返回完整值。
- TOTP setup/login ticket 有效期 5 分钟、一次性、限定用途；TOTP 验证限流并记录已消费时间步，防止同一验证码重复登录。连续失败产生审计事件。
- Session 1 单管理员权限即可；多角色 RBAC 与 api_keys 不要求实现。不要为了空表制造没有后端能力的 UI。TOTP 丢失恢复通过宿主机本地 CLI、验证运维身份后重绑，并留审计。
- 运行态数据库账号对 audit_log 只有 INSERT/SELECT 权限；迁移使用独立角色。append-only 指应用权限不可修改/删除，不宣称抵御数据库超级管理员篡改。

### 19.5 流量统计与告警口径

- WAN 指标名称统一 `wan_rx_bytes/wan_tx_bytes`，以设备 WAN 接口为方向；代理指标按路由器视角下载/上传计数。均使用非负 64 位整数，JSON 编解码避免 JavaScript 超过安全整数范围后失真。
- 每份心跳携带 sample_id，数据库 `(device_id, sample_id)` 唯一；boot_id 标识系统启动，proxy_counter_epoch 标识代理采集计数器周期。重复、乱序样本不重复累加。
- 同一计数器周期内取相邻有效样本差值；首样本仅建立基线。计数器下降或 epoch 变化重新建立基线，不产生负流量或把全部新累计值当增量。
- 代理流量只累计实际经过节点的连接增量；先在固定 mihomo 版本验证 `/connections` 等接口的含义及断连/重启行为。若轮询会漏掉短连接，界面明确标「估算」，记录采集间隔与误差来源。不能直接把所有连接 downloadTotal/uploadTotal 当收费节点流量。
- 缺数据用 null、unavailable/partial 状态；页面显示「暂无数据/采集不完整」，告警不能因未知值当作 0 而错误解除。
- 月份按 `Asia/Shanghai`，底层时间存 UTC，阈值采用十进制 GB（1 GB = 1,000,000,000 bytes），默认下载+上传 80 GB/设备/月。有效增量归到当前样本所在月份，明确跨月采样边界的近似误差；月聚合独立保留至少 12 个月，原始 metrics 保留 90 天。
- 页面写「本月代理流量（设备侧统计/估算）」；不将其等同 VPS 账单，协议开销、探测、服务商计费方向与漏采会造成差异。
- 离线、节点失联、出口变化、连续回滚、流量阈值告警均去重；离线阈值 90s，扫描周期不超过 10s。连续回滚以设备连续已完成的配置任务计算，成功后清零；pending/running 不改变计数。
- webhook 在事务外异步投递，有超时、重试和发送记录；下游故障不能阻塞心跳。Session 1 用本地接收器验证接口，Session 2 才接真实 Telegram/Bark，不在默认测试中向真实账号发消息。

### 19.6 凭据吊销与轮换

- 管理凭据（WG/HMAC/订阅 token）与代理 UUID 分开管理。吊销管理凭据不等于旧代理 UUID 已失效，UI 必须分别显示状态。
- revoke 立即拒绝 HMAC/token/enroll，取消未执行任务，并排队删除 WG Peer；Peer 删除失败显示待同步且告警，不宣称完成。Agent 离线时已落盘代理配置仍可能使用。
- rotate 采用维护窗口的离线重新引导：生成新引导包，撤销旧管理凭据并通过可信 LAN 重新导入；UI 明示设备将暂时失联。自动在线无缝轮换不在本期范围，不能靠 API 返回新密钥就宣称路由器已更新。
- Session 2 单独建 `device_node_credentials(device_id,node_id,uuid_enc,sync_status,confirmed_at)`，UUID 按设备和节点独立；Reality 公钥/short-id 等节点级参数不必伪称每设备独立。
- 管理端生成 UUID 后状态为 pending_sync；独立脚本实际更新 sing-box 并确认结果后才为 active，可被新订阅引用。移除 UUID 同样需确认，失败为 sync_failed。管理服务不持有出口 SSH 私钥。
- 实施前已有共享 UUID 仅用于明确标识的过渡联调；未完成出口端独立 UUID 配置前，不得验收「单设备代理凭据独立吊销」。

### 19.7 接口与数据库交付要求

- 提交 `mgmt/docs/openapi.yaml`，包含管理端、Agent、enroll、订阅接口，定义字段类型、必填项、状态码及鉴权方式；前后端以它对齐。
- 列表统一 page/page_size（默认 20、最大 100）与 `{items,total,page,page_size}`。错误统一 `{code,message,request_id}`；401 未认证、403 越权、404 不存在、409 状态冲突、422 参数错误、429 限流。错误不得附带原始配置或密码。
- 为 §8 补齐 migrations：设备 desired version、任务 lease/idempotency/config_id/deadline、指标 sample/epoch/质量、月聚合、nonce 去重、凭据同步、告警状态等。本文模型是字段最低要求，不是可原样生成的 SQL。
- 配置版本、设备 IP、节点分配主键、任务幂等键、指标去重使用数据库约束；并发正确性不能只靠先查后插。
- 对 metrics(device_id, ts)、tasks(device_id, status, created_at)、alerts/device 与 audit 时间查询建立必要索引。启动迁移有明确版本，不只依赖 GORM AutoMigrate 猜测生产结构。

## 20. 开发 AI 的执行与交付方式

按以下依赖顺序实施，每步通过后继续下一步，不要只提交空目录、TODO handler 或静态前端：

1. **基础工程**：检查现有文件 → 建立 `mgmt/` → 无秘密的 `.env.example` → Postgres 迁移 → API health → compose 启动。
2. **协议与认证**：OpenAPI → 管理员首次 TOTP → 加密存储 → enroll/引导 CLI → Go/ash HMAC 测试向量与防重放。
3. **设备与监控**：真实心跳入库 → 设备列表/详情 → 在线状态 → WAN/代理流量质量与聚合 → Dashboard。
4. **配置与运维**：脱敏模板 → 节点与绑定 → 不可变版本/签名 → 任务领取/幂等 → Agent 状态日志/应用/回滚 → 前端操作闭环。
5. **Session 1 收口**：审计与告警写库 → 前端生产构建 → 集成测试与浏览器验收 → README + 测试报告 + 剩余事项。
6. **Session 2**：WG 与离线安装 → 真机适配 → 其余白名单/自动故障转移 → webhook → 独立 UUID 同步 → 备份恢复与压测。

### 20.1 最低自动化验收矩阵

| 范围 | 必须证明 |
|------|----------|
| 注册 | 过期/重复注册码失败；并发 enroll 只有一个成功；设备 IP 不重复 |
| 身份 | HMAC 固定向量互通；错误密钥、改 body、过期时间、重复 nonce 被拒；A 设备读写 B 设备任务/配置失败 |
| 管理登录 | 未完成 TOTP 无完整访问权限；ticket 过期/重用失败；登录限流有效 |
| 订阅 | 黄金规则、动态地址和组引用正确；无绑定拒绝；掩码预览无秘密；重复 GET 不增版本 |
| 签名 | 改一个 YAML 字节、换设备、换版本均拒绝；重复版本不重复应用；本地回滚不降低防重放高水位 |
| 任务 | 并发轮询不重复执行；丢失结果重传不重启；过期/吊销后未领取任务不执行 |
| 回滚 | 模拟配置校验失败、健康失败、应用中 Agent 退出；验证文件与选择状态恢复，并区分 rollback_failed |
| 统计 | 重复/乱序/计数重置/跨月/未知采集不产生虚假增量；月数据不随 90 天原始清理丢失 |
| 持久化 | 重建容器后 DB、加密密钥和签名验证正常；开发及生产 compose 入口绑定符合 §13 |

使用 Postgres 跑数据库集成测试；Agent 用 BusyBox ash 环境测试，不能仅用 bash 通过代替兼容性。前端执行类型检查和生产构建，浏览器完成 §12 操作闭环。Session 2 再用目标 mihomo 核心校验生成配置，并通过实际连接链/抓包确认国内样本直连、境外样本走节点、管理通道不依赖代理。

### 20.2 每阶段必须提交的证据

- `mgmt/README.md`：从干净环境启动、登录、创建设备、mock 接入和演示步骤。
- `mgmt/docs/验收记录.md`：实际命令、运行环境、测试结果及失败/跳过原因；区分「代码完成」「mock 通过」「真机通过」。不能把未执行检查写成通过。
- `mgmt/docs/开发进度.md`：已完成项、当前断点、下一步命令、待办及阻塞依赖。聊天上下文不足时先更新此文件，再由下一次会话继续。
- Session 2：运维手册、安全自查表、备份与恢复脚本，以及实际恢复演练记录。管理 VPS 未采购或真机未就绪只阻塞对应验证，不阻塞其余编码与本地验收。

遇到实现细节可自行作合理决定并记录；不得擅自更换架构、降低签名/直连/回滚要求或操作现网出口。若官方工具版本与本文示例不兼容，先核对官方文档和目标环境，记录差异与兼容实现，禁止静默跳过检查。
