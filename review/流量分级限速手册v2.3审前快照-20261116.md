## 需求背景与用户目标（对话整理版，执行前必读）

> 本节是用户需求的忠实整理，不是原始聊天逐字记录，也不是技术验收结论。执行 AI 可能缺少项目上下文，因此必须先理解“为什么做、做到什么程度、哪些不能动”，再阅读后续命令和验收步骤。

### A. 需求是怎么一步步形成的

1. **用户提供了 Codex 编写的执行手册、逐台实测报告和 DNS 参考脚本，要求从第0节开始执行。** 执行过程中必须坚持稳妥、逐台验证、失败即停，不能批量蛮干。P0 游戏 DNS 已按该授权完成，后续阶段不能因为手册写着“下一步”就自动推进。
2. **用户随后要求评估手册是否可行，并再次强调“一定要稳妥、不要影响使用”。** 用户特别询问限速逻辑：国内业务不能受影响，主要限制国外流量，尤其是每天超过一定流量后的下载和视频行为。
3. **用户要求把原计划修订为足够详细、可交给其他 AI 执行的版本。** 新手册必须自包含，不能依赖执行者记得此前对话；必须写清每一步的前置条件、执行顺序、验收、回退和停止条件。用户同时要求：某些设备必须可以解除限速，不能只能限不能解。
4. **用户发现流量统计明显不一致。** 用户指出：GIA 从10月26日至今供应商侧已用约820GB，而平台国外流量统计不足100GB，要求检查原因并把统计纠偏追加到计划中。由此确定：旧平台估算只能作参考，必须先建立可信计量，不能拿旧数据直接封禁。
5. **用户进一步要求限速参数可调整。** 不是把阈值和速率写死在脚本里，而是可以按设备修改“超过多少流量”和“超过后限到多少”。用户给出的需求示例是：某设备超过3G流量后，视频和下载限速到“60kb”。该例说明需要的是**可配置的阈值与动作**，不是已经批准所有设备统一使用3G/60kb。
6. **用户最后要求把需求对话也整理进手册。** 目的是让后续执行 AI 明白前因后果，避免只截取某一个数值或某一条命令而误伤业务。

### B. 用户真正希望达到的使用效果

- 日常未超阈值时，用户上网体验不发生变化。
- 国内网站、国内游戏、公司管理、医院白名单和远程控制始终不受影响。
- 普通国外网页、邮件、API、即时通信尽量保持畅通。
- 真正需要重点约束的是**持续下载、大文件、视频等高消耗行为**，不是简单封掉所有国外访问。
- 某台设备当天国外代理流量超过设定值后，先告警，再只对下载/视频采取降速或经核实后的出口迁移。
- 超限后视频可以降低清晰度、下载可以变慢，但**不能直接国外全断，更不能国内一起变慢**。
- 某些设备有临时大文件或特殊业务时，可以单台、单类、临时或长期解封；发生误伤时可以紧急解封。
- 限速参数应能按设备在线修改，并有版本、审计和回退；解封期间仍保留计量，不能靠清零流量“恢复”。

### C. 用户明确不希望发生的事情

- 不希望执行 AI 未经确认就全舰队批量下发限速或重启服务。
- 不希望把现有不准确的流量统计当成真实配额依据。
- 不希望把“tc速率限制”误当成“每天多少GiB”的流量限额。
- 不希望只限制单一 TCP443，导致 HY2、CF、机场等协议绕过。
- 不希望限速后普通国外网页也无法使用，或用 DIRECT/断网代替治理。
- 不希望国内网站、LOL、医院业务、广州管理通道受到任何影响。
- 不希望设备限速后无法解封，或解封后被旧策略自动改回。
- 不希望执行 AI 把“60kb”等含糊单位自行解释后直接落盘。

## 1A. 流量统计失真纠偏（v2.1 新增，必须先修口径）

### 1A.1 用户指出的矛盾

用户看到：GIA 从 10 月 26 日至今供应商侧用量约 **820GB**，而平台国外流量统计不足 100GB。**这个矛盾是真实存在的，不能再用“统计差不多”掩盖。**

但“820GB”与“平台不足100GB”不是同一指标，不能直接相减后把差额归给某台设备，更不能按固定倍数平均分摊。

### 1A.2 造成差异的七类原因

| 原因 | 影响 | 正确处理 |
|---|---|---|
| 时间窗口不同 | 供应商是 10-26 起；vnstat 数据库实际建立时间、平台近14/30天、11月自然月各不相同 | 所有报表必须显式带 `window_start/window_end/timezone`，先对齐再比较 |
| 单位不同 | 供应商可能用十进制 GB，平台常用 GiB；820GB≈763.7GiB | 底层只存原始字节，展示时才换算并标明单位 |
| 网卡双向账 | 用户下载一段数据，服务器通常同时产生面向客户端的出站和面向目标站的入站；供应商若 rx+tx 计费，总量约为用户链路两倍再加开销 | 不得把网卡总量直接当用户下载量 |
| 其他网卡流量 | 管理隧道、CF回源、协议开销、重传、扫描及非业务流量都可能计入 | vnstat只用于服务器总账，不分设备归责 |
| 平台是活跃连接快照 | agent 每次对当前仍活跃且 chains[0] 非 DIRECT 的连接生命周期字节求和；连接关闭时值会下降，后台只加正差会漏掉采样间已结束连接 | 旧 `metrics.proxy_rx/tx_bytes` 只能做趋势参考，不能作为配额依据 |
| 重启与口径覆盖 | mihomo重启、计数epoch变化、US-MEDIA与PROXY选择不一致、只取chains[0]、BWG/机场混合，都会造成漏计或错归 | 不依据 `exit_node` 把全部流量归给当前PROXY；新计量按真实端点记账 |
| 历史无分用户字节 | GIA此前未开启按用户/按源IP的持久字节统计，sing-box日志主要是连接事件 | 10-26以来的精确分设备历史无法补回，明确标“不可考”，禁止伪造回填 |

补充：源码默认心跳约60秒，不能把 agent 与 connlog 一律写成5分钟采样；connlog只记录下行、≥1MiB增量，也不能直接当国外专用账。

### 1A.3 三本账的新权威顺序

1. **供应商账单账**：决定套餐额度、计费方向、账单周期和是否超额；只认面板/供应商API。
2. **服务器物理网卡账（vnstat）**：用于GIA总量对账，包含代理两条腿、管理、开销、重传及其他流量；不分设备。
3. **新部署的每设备代理端点账**：只统计路由器与代理端点间的双向字节，用于本文的日阈值和限速动作；这是唯一允许驱动自动处置的设备级数据。

旧平台估算字段更名为展示语义 `estimated_proxy_bytes`，新计量字段使用 `metered_proxy_bytes`，两者不得混排相加。

### 1A.4 对账规则

设新设备代理链路真实字节为 `U`，服务器网卡总账为 `N`：

```text
N ≈ 代理客户端腿 + 目标站点腿 + 管理/CF/协议开销/重传/其他
U 只是其中与特定设备、特定端点相关的一部分
旧平台估算 E ≤ U，且可能远小于U
```

- 不允许使用 `N/U=固定倍数`、`缺口×10`、`按连接数分摊` 等伪精确算法。
- 对账只比较同窗口、同单位、同方向、同端点的趋势；总量无法精确相等时记录差值和 unknown，不强行调平。
- 新计量部署前的历史报表统一标注：`estimated / incomplete / not_for_enforcement`。
- 新计量部署后从0开始累积；**不得把历史估算伪造成新计量的期初值**。

### 1A.5 新计量数据最小字段

```text
device_id, provider, endpoint_ip, protocol, endpoint_port,
direction, bytes_total_monotonic, sampled_at, boot_id,
continuity_id, window_start, window_end, source=gia_nft|router_meter,
confidence=metered|shared|unknown, discontinuity_flag
```

计数器下降、boot_id变化、表重建时新建 continuity_id 并记录断点；缺失样本记 unknown，不记0。

## 2. 总体限速逻辑（执行 AI 必须能复述）

### 2.1 计入“国外代理流量”的范围

只统计每台路由器与实际代理端点之间的流量：

| 出口 | 匹配元组 | 预算归属 |
|---|---|---|
| GIA VLESS | `154.36.139.155 TCP/443` | GIA |
| GIA HY2 | `154.36.139.155 UDP/34568` | GIA |
| CF1/CF2 | `104.18.32.7`、`162.159.135.42 TCP/2053`；EDGE 若存在按实际端口 | 当前回源 GIA，计 GIA |
| BWG VLESS | `74.82.193.113 TCP/443` | BWG |
| BWG HY2 | `74.82.193.113 UDP/34567` | BWG |
| 机场 | 从有效 provider 动态读取 IP/协议/端口 | 机场独立账 |

上下行分别计数，日配额按“上行+下行合计”。**不能把整个 WAN 流量当国外流量。**

### 2.2 永远不计入、不限速的流量

- 国内 DIRECT 和国内游戏 TCP/UDP；
- 广州管理 SSH 22/28722、反向排障口、心跳、管理 API；
- WireGuard、公司 TCP 管理通道；
- 医院白名单业务；
- WiFi、br-lan、普通 LAN 流量。

同一公网 IP 上不同端口必须区分：例如 SSH 管理端口不能因与代理服务器同 IP 而被计入代理账。

### 2.3 业务分类

1. **普通国外浏览**：网页、API、邮件、即时通信。优先保持可用，不进入“下载/视频子类降速”。
2. **视频类**：由 US-MEDIA 组及其明确规则识别（如 YouTube/Netflix 等）。超额后只处理该组。
3. **下载类**：由 DOWNLOAD 组和持续高吞吐连接识别。系统更新、网盘、大文件优先降速；短请求不误判为下载。

### 2.4 速率与配额是两套机制

- `3000/1000 kbit/s` 是**整台设备全部国外代理连接共享的上下行速率**，不是每条连接各一份，也不是每个节点各一份。
- “每日 2GiB”是**累计配额**，必须由可信计量和阈值动作实现，tc 本身不会按天统计。
- 速率使用平滑 HTB/TBF 整形，优先于简单 DROP，避免重传反而增加流量。

### 2.5 动作状态机

```text
正常（observe）
  │ 达到日告警值
  ▼
只告警，不减速、不切换
  │ 达到日迁移/降速值，连续两次采样成立
  ▼
下载/视频子类降速；若备用余量已核实，可只迁移 US-MEDIA/DOWNLOAD
  │ 达到严重保护线（试运行建议=日迁移值约2倍）
  ▼
仅暂停 DOWNLOAD 非关键大文件；视频低速可用；普通国外浏览继续
  │ 人工窗口/次日出账/小流量复测
  ▼
解封或恢复限速，保留计量与审计
```

**禁止动作**：默认切 DIRECT、直接断国外、限制国内、断医院上传、清空全部 mihomo 连接、重启整机当回退。

### B2. GIA 服务器纯计量（只计数，不限流）

- 新表只加 INPUT/OUTPUT counter，不加 DROP/REJECT，不 reload 防火墙，不替换 qdisc。
- 已验证的站点公网 NAT IP 建命名计数器；共享 IP 只能建组账；CF 回源进 shared；未映射进 unknown。

### B3. 路由器代理端点计量（覆盖 BWG/机场）

- 不用 WAN 总流量代替国外流量；
- 保存每设备/每提供方/每日/每周期累计；
- 机场 provider 更新时同时保留新旧端点，待旧连接结束再移除；
- unknown 比例高时只告警，不执行自动封禁；
- 重启、WAN IP 变化、节点切换都重新对拍端点；
- 不写原始访问正文、不输出订阅 URL/密码/UUID。

### B4. 计量验收

- 管理端口没有被计入；
- 国内 DIRECT 不计入；
- 代理流量增长方向合理；
- 计数器重启/断点有记录；
- 不尝试让“客户端一条腿”直接等于 vnstat 网卡双向总账；
- 至少观察 24–48 小时后，才把数据用于阈值建议。

## 5. 阶段 C：限速引擎 v2 开发与 R2 单台试点

> **阶段 C 未完成前，禁止对任何设备声称“已按日流量限速”。**

### C1. 必须新增，不得复用旧字段冒充

建议新增版本化任务/策略 `proxy_ratelimit_v2`。以下是“某设备每日代理流量超过 3GiB 后，视频和下载分别限速”的**参数示例，不是现网已生效配置**：

```json
{
  "schema": 2,
  "policy_id": "pol-r2-example",
  "policy_version": 7,
  "device_id": "rtr-a9bcba",
  "enforcement": "observe",
  "scope": "download_video",
  "quota": {
    "period": "daily",
    "timezone": "Asia/Shanghai",
    "used_bytes_source": "router_meter",
    "warn_gib": 1.0,
    "action_gib": 3.0,
    "hard_gib": 6.0
  },
  "actions": {
    "video": {
      "mode": "shape",
      "down": {"value": 60, "unit": "kbps"},
      "up": {"value": 1000, "unit": "kbps"}
    },
    "download": {
      "mode": "shape",
      "down": {"value": 60, "unit": "kbps"},
      "up": {"value": 1000, "unit": "kbps"}
    },
    "web": {"mode": "unchanged"}
  },
  "exempt": false,
  "temporary_release": null
}
```

`enforcement` 只允许：

- `observe`：只计量/告警；
- `limited`：启用下载/视频速率限制；
- `paused`：暂停 DOWNLOAD 非关键大文件，其他保留；
- `exempt`：设备长期豁免，只计量不自动动作。

**如果后端尚无该任务类型，停止，不得改用旧 `set_ratelimit`。**

后端和 agent 必须做到：

- 结构化参数校验，禁止 eval；
- 多代理端点、多协议、上下行、动态机场端点；
- 所有代理端点汇入同一设备预算类，不叠加额度；
- 任一内核命令失败必须 task failed 并回退，不得写成功 policy；
- 节点切换、WAN IP 变化、重启后重新对拍并恢复；
- apply/status/release 都返回真实执行结果和命中计数；
- 不动旧 `vps_limit_kbps` 的单位与兼容语义。

### C1A. 可在线调整的限速参数（v2.1 新增，必须实现）

#### C1A.1 哪些参数必须按设备独立可改

每台设备都必须能单独修改，不得全舰队共用一份写死值：

- `quota.warn_gib`：日告警阈值；
- `quota.action_gib`：日开始降速/迁移阈值，例如 3GiB；
- `quota.hard_gib`：严重保护线；
- `actions.video.down/up`：视频上下行速率；
- `actions.download.down/up`：下载上下行速率；
- `actions.web.mode`：普通浏览默认 `unchanged`；
- `scope`：只视频、只下载、视频+下载；
- `enforcement`：observe/limited/paused/exempt；
- 临时解封范围、原因和到期时间。

设备可以有独立 override；修改某台设备不得顺带覆盖其他设备或全局默认值。

#### C1A.2 单位强制规范，禁止“60kb”直接入库

执行者输入 `60kb` 时**含义不明确，必须停止并确认**，不得自行猜测：

| 用户真实意图 | 合法参数 | 换算结果 |
|---|---|---|
| 60 KiB/s（约60KB每秒） | `{"value":60,"unit":"KiB/s"}` | 60×1024×8=491,520 bit/s=491.52 kbit/s |
| 60 kbit/s | `{"value":60,"unit":"kbps"}` | 60,000 bit/s=7.5 kB/s，约7.32KiB/s |

- 允许单位：`kbps`、`Mbps`、`KiB/s`、`MiB/s`；底层统一保存整数 `bits_per_second`。
- `kbps/Mbps` 按1000进制，`KiB/s/MiB/s` 按1024进制；展示时保留用户原值与规范值。
- `0` 不是合法“无限速”值；不限速必须通过 `observe`、`exempt` 或明确的 `mode:"unchanged"` 表达。
- 不允许负数、NaN、字符串拼接表达式或把节点名当 shell 片段。
- 视频与下载可以不同值；同一类多条连接共享该类上限，不能每条连接各拿一份。

#### C1A.3 在线修改流程

参数修改必须走 `status → preview → apply → verify`，不允许直接改数据库或 tc 命令后宣称成功：

1. **status**：读取当前生效策略版本、实际内核状态、当前日已用量和本方案对象清单。
2. **preview**：校验 device_id、schema、单位、阈值关系、速率范围、端点覆盖、并行锁；返回脱敏 old/new diff。
3. **并发保护**：提交必须带 `expected_policy_version` 和新的 Idempotency-Key；版本不符表示有人已改过，停止，不覆盖。
4. **apply**：只修改该设备、该作用域的 v2 策略和自有整形对象；不重启 mihomo、不重启隧道、不清 cache.db、不清流量计数。
5. **verify**：返回 task 终态、真实 tc/IFB 参数、命中计数、管理健康、国内与国外小样本结果。
6. **失败回退**：恢复修改前 exact policy_version 和自有对象，不能只把数值改成0。
7. **审计**：记录操作者、授权人、原因、old/new、时间、task_id、当前用量、验收结果。

#### C1A.4 修改阈值的特殊规则

- 修改阈值只影响之后的评估，**不清空当天已用量，不追溯改历史动作**。
- 若新阈值低于当前已用量，preview 必须显著提示“下一采样周期可能立即触发动作”，只有提交 `allow_immediate_action=true` 才允许继续；否则保持观察并让人工决定。
- 提高阈值不等于解封现有限速；当前已处于 limited 的设备需要单独 release 或人工恢复策略。
- 降低/提高速率只调整整形参数，不清空连接，不强制用户重连。
- 计量中断、unknown 比例高时，禁止因修改阈值而自动封禁，只允许 observe/告警。

#### C1A.5 参数修改示例（仅示例，禁止直接生产执行）

需求：R2 当日国外代理上下行合计超过 3GiB 后，视频和下载下行都限制到 **60 kbit/s**（用户已确认的初始值），普通国外浏览不变。

```text
status(rtr-a9bcba)
preview(
  device_id=rtr-a9bcba,
  expected_policy_version=<status返回的当前版本>,
  quota.action_gib=3.0,
  actions.video.down={value:60,unit:"kbps"},
  actions.download.down={value:60,unit:"kbps"},
  actions.web.mode="unchanged"
)
# 审核 old/new diff、当前已用量、是否立即触发、端点覆盖和单位换算
apply(... 新Idempotency-Key ...)
verify(...)
```

如果用户说的“60kb”实际是 60kbit/s，则必须重新 preview 为 `{"value":60,"unit":"kbps"}`，不得沿用上面的 60KiB/s 示例。

#### C1A.6 修改参数与解封的关系

- 解封不是把速率改成0，而是按第7节切换 `observe/exempt` 并移除对应自有动作对象。
- 解封期间仍可以调整未来策略草稿，但不得自动生效。
- 恢复限速时必须使用明确的人工 apply，重新校验当前已用量、阈值和版本，不能自动拿解封前旧值强行恢复。

### C2. tc 实现约束

- 根据实际默认路由识别 WAN，不假定 eth0；
- SN 的 noqueue、GL 的 mq、GIA 的 fq 不得统一覆盖；
- 有现存 SQM/HTB/自定义过滤器即停止，另做集成；
- 上传：仅代理元组分类进自有 HTB/TBF 类；
- 下载：仅代理来源元组 redirect 到自有 IFB，在 IFB 上整形；
- 其他流量不重定向、不进受限类；
- 自有 handle/IFB 先查归属，非本方案创建则拒绝覆盖；
- apply = preflight → 备份 → 临时自动回退 → 内核规则 → 命中/吞吐验收 → 提交；
- 回退只删除本方案对象，恢复原 qdisc/filter，能在原 SSH 会话执行且另开会话实登；
- 不关闭业务 offload 来“让规则看起来生效”；有绕过分流时停止并报告。

### C3. R2 试点顺序

1. R2 先运行 `observe` 48 小时，只计量/告警。
2. 引擎 apply 但不启用业务阈值，验证分类、状态、回退。
3. 启用下载/视频子类速率，普通国外浏览不进入该子类。
4. 完成 §C4 全部测试。
5. R2 稳定 48 小时后，才讨论日配额自动动作。

### C4. R2 验收矩阵（每项保留实际计数与结果）

| 测试 | 通过标准 |
|---|---|
| BWG-HY2 UDP34567 | 命中同一代理类，达到共享上限 |
| BWG-VLESS TCP443 | 同样命中，不因 TCP/UDP 变化绕过 |
| GIA TCP443/UDP34568 | 仅在批准的 GIA 测试窗口验证；当前额度窗口不允许则明确标“未验”，不得写通过 |
| CF TCP2053/EDGE 实际端口 | 命中，预算归当前源站 |
| 机场非443端口 | 命中，证明没有写死443 |
| 两条同时代理连接 | 合计不超上限，不各拿一份 |
| 国内直连下载 | 不进代理受限类，速度无显著人为下降 |
| 广州 SSH/心跳/排障口 | 不命中，管理不断，两个心跳推进，另开会话可实登 |
| LOL 国内 UDP | 不命中，现场训练模式可操作（无现场则标待验） |
| 内核故意不支持 | apply 返回 failed 并回退，不能 task ok |
| WAN IP变化/重启/节点换IP | 策略按设计恢复，计量 discontinuity 正确 |
| 解封与再启用 | 只撤自有对象，DNS例外/无线/管理不变 |
| 在线调参 | 修改 action_gib 与 video/download 各自速率后，返回正确规范单位、命中参数和 old/new 审计；日用量不清零 |
| 非法单位/版本冲突 | `60kb`、rate=0、expected_policy_version过期均被拒绝，不落盘 |
| 新阈值低于当前用量 | 无 allow_immediate_action 时拒绝自动动作；有明确授权时才按提示执行 |
| 普通国外浏览 | 不进入下载/视频子类限速，仍可访问 |

测速只用批准的 2–4MiB 小数据集，记录窗口、并发、重传，分清 kbit/s、Mbit/s、KiB/s，不用大文件刷额度。

## 7. 解封机制（必须与限速同时交付）

### 7.1 解封原则

1. **解封不删除计量、不清空已用日/月配额、不修改历史日志。**
2. 解封只作用于本方案创建的限速/暂停对象，不删除别人的 tc/nft/防火墙对象。
3. 解封后保留状态为 `observe` 或 `exempt`，不得偷偷恢复 `limited`。
4. 任何解封都记录：设备、范围、原因、授权人、执行者、时间、原策略、恢复条件、验收结果。
5. 医院/管理/国内业务异常时，优先解封并停止自动动作，不等待额度判断。

### 7.2 四种解封范围

| 类型 | 适用场景 | 动作 |
|---|---|---|
| 单类解封 | 只需恢复视频或下载 | 只解除 US-MEDIA 或 DOWNLOAD 的限速/暂停，其他保持 |
| 单台临时解封 | 站点临时有大文件/视频业务 | 该设备转 `observe`，保留计量和告警；可设到期时间 |
| 单台长期豁免 | 经负责人确认的特殊设备 | 该设备转 `exempt`，不自动限速/迁移，仍保留计量和人工告警 |
| 紧急解封 | 国内/管理/游戏受影响、规则异常、误伤 | 立即撤除该设备全部本方案限速对象，转 `observe`，停止自动动作，人工复核 |

### 7.3 临时解封规则

- 默认建议 60 分钟，最长不超过用户明确授权的时长；
- `temporary_release` 记录 `scope/reason/started_at/expires_at/approved_by`；
- **到期不得盲目自动恢复限速**：到期前先检查站点业务、当前阈值和人工锁；无明确恢复授权则保持 observe 并提醒人工；
- 临时解封期间仍累计流量，不能把解封时间内的用量从账上删除；
- 自动迁移在临时解封期间暂停，避免刚解封又被切走。

### 7.4 解封执行接口（v2 实现后才允许使用）

应提供等价的 status/apply/release 能力：

```text
status(device_id)
release(device_id, scope=video|download|all, mode=temporary|exempt|emergency,
        reason, approved_by, expires_at?)
apply(device_id, original_policy_id)   # 仅人工明确恢复时
```

**若该接口尚未实现，执行 AI 不得臆造命令，也不得用旧 set_ratelimit kbps=0 冒充完整解封。** 紧急情况下只能按已验证的“本方案对象清单”撤销，并保留管理通道。

### 7.5 解封验收（每台必做）

- 自有下载/视频限速类、IFB 规则或 DOWNLOAD 暂停对象已按范围移除；
- 其他 tc/nft/防火墙对象未变；
- 计量仍在采样，未清零；
- 国内网站、LOL 国内 UDP、广州 SSH、心跳、排障口正常；
- P0 游戏 DNS 例外、无线、mihomo 配置、tunnel.conf、self-heal 未变；
- 普通国外浏览恢复；视频/下载按解封范围实测；
- 设备状态已写成 observe/exempt，不会在下次心跳被旧策略自动改回 limited；
- 记录解封前后状态、时间和恢复条件。

### 7.6 解封失败处理

- 解封命令失败：保持当前 SSH 会话，不重重启，不批量操作其他设备；
- 只读列出本方案对象，按备份逐项恢复；
- 如果无法证明哪些对象属于本方案，停止并交人工，不清理整个 qdisc/防火墙；
- 管理通道若异常，优先使用已核验备用控制入口，禁止盲杀 132xx 会话。

## 8. 告警、审计与恢复

- 告警 webhook 未配置时，平台 alerts/审计必须可见，并明确“本地告警已生成/外部推送未送达”，不能假装已通知。
- 月预算 70% 预警、90%停止新增 GIA 非关键业务并迁移到已核实有余量的备用；未核实供应商计费口径前不启用自动硬动作。
- 切出口不清空已用 GIA 预算。
- 恢复 GIA 需要供应商重置证据、小流量健康验证和人工窗口，不仅凭日期自动 PUT AUTO。
- 每日自动迁移最多 2 次；每设备锁防止多会话/多脚本同时动作。

## 10. 全局停止条件

任一发生，立即停止当前设备与当前批次：

- 心跳 >90 秒、排障口无法重登；
- 国内网站、国内游戏、医院业务或管理通道异常；
- 任务 failed/rolled_back/expired；
- 配置哈希不符、primary 不唯一、preview 不符合预期；
- 限速命中计数不符合、协议覆盖不全、实际吞吐不支持；
- 解封后仍被旧策略自动改回；
- 计量中断却被当成 0 流量；
- 发现并行会话正在改同一后端/设备；
- 需要重启整机才能“恢复”。
