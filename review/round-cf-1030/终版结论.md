# 终版结论（round-cf-1030）— R4 通道抗封锁评审

> GLM 起草 + Codex/Grok 独立审查 + 证据裁决。**Kimi 缺席（429 周额度）**。产物：方案.md / 审查_zcode.md / codex.md / grok.raw / 分歧表.md（本目录）。

## 用户三问的最终回答

### Q1：R4 当前通道可以吗？

**可以上网，但比初审判断的脆弱。**

- 主用 GIA REALITY 实测健康（165ms），日常可用。
- 三条通道（REALITY/HY2/CF）**全部落在同一台 66云服务器**——是"三种接入方式"不是"三份冗余"，服务器停机/欠费/封号则三条同死。
- 当天该通道已因一次手工改配置全断 2 小时 17 分（12:49–15:06），说明**配置脆弱性与 IP 封锁同等致命**。
- **新发现（比 IP 封锁更迫近的问题）**：R4 现网 US-MEDIA 组为空（9090 实查 ["COMPATIBLE"]），而 YouTube/Netflix 规则全部指向 US-MEDIA——**坊子用户现在就看不了 YouTube，与被封无关、与 CF 节点无关**，是平台模板渲染空组问题（10-29/10-30 报告已两次标记待修）。
- CF 节点：节点级验证可达 YouTube（339/366ms 成功案例），但质量不稳（部分测试超时），且因 US-MEDIA 空组，**真实视频流量到不了它**。

### Q2：可以防止封号吗？

**不能保证。分四类说明（初审只答了其一，已修正）：**

| 封的对象 | 现状 |
|---|---|
| GFW 封 IP | 防不了封本身；CF 链可绕开"大陆直连被封"这一种（前提：服务器本身还活着、CF 回源段健康）。协议伪装（REALITY/WS-in-TLS）只提高识别成本，不免疫——BWG 同款 REALITY 仍被封是实证 |
| 66云服务商封号 | 无自动预案；方向=CF A 记录改指新源站+重放部署+迁移 GIA 管理中继，**未演练**，不能承诺分钟级 |
| Cloudflare 账号/域名被针对 | 换域名是条件性手段（需同步改设备 SNI/Host+等边缘证书），不是"几块钱即解"；CF 免费版 CDN 条款对视频类流量保留限制权，长期重负载有账号风险 |
| 网站账号（Google 等） | 出口 IP 不因 CF 改变（仍是 66云），按 IP 信誉的拦截不会因套 CF 消失；R1/R3/R5 经 GIA 已可开 YouTube 首页（10-29 实证），说明"数据中心 IP 一律被墙"不成立 |

### Q3：66云 IP 被封了有解决方案吗？

**有一种"大概率活着"的路径（CF），但它是假设未演练，且不覆盖全部封法：**

- **只有大陆方向封这个 IP、机器与服务仍在**时：CF 链路理论存活（CF 回源不跨 GFW，今日源站段实测健康）。设备侧 NODE-PICK 自动切换到 CF——但切换语义受 mihomo fallback 行为限制：CF 探测恰好失败时会摆动；全部成员死则回落 DIRECT（=国外站不可用，不是低质量出海）。**需一次真实受控演练才能给出切换时间承诺。**
- 机器/账号/带宽层死亡（封号、停机、欠费）：CF 同死（源站即它）。恢复=换源站+改 A 记录+重放部署+迁移管理中继（GIA 上的 s-relay 断则全舰队心跳断——今日事故实证）。
- **当前两个前置缺陷使该预案名存实亡**：① CF 节点仅在 R4 且是手工配置，平台下次发布即删除（对兜底能力有害，非"无害"）；② US-MEDIA 空组使视频类流量根本走不到 CF。

## 评审产生的修正清单（GLM 初审被推翻/降级的断言）

CF 是异入口非异出口；"YouTube 首次可达"错误（10-29 已有三台可达）；"管理面不受影响"过度（仅设备 SSH 口独立）；"≤2 分钟自动降级"无保证；"3-5 成成功率"非实测；"换 IP 无效"过度归因；"GFW 不敢封 CF"论证过强；"5-10 分钟恢复"未演练。详见分歧表.md。

## 建议行动（按优先级，均需用户授权后执行）

1. **修 US-MEDIA 空组**（平台模板 filter/成员渲染问题）——这直接决定坊子现在能不能看 YouTube，与防封无关、收益立竿见影；
2. **平台模板支持 vless+ws 节点**，把 CF 节点转为平台正式节点（消除"发布即删"的预案失效）；
3. **做一次受控封禁演练**（临时把 NODE-PICK 首位指到假 IP 或拔 GIA 探测），实测自动切换时间与 CF 接管表现；
4. GIA 2053 端口限源为 CF IP 段（消除公网可探测的新暴露面）；
5. CF 链增加第二条优选 IP/节点做路径备选（Anycast 下非独立双保险，仅增路径选择）；
6. 中长期：第二台境外源站热备（BWG/DMIT 复用或新购）+ 管理中继去 GIA 化，消除 66云单点对管理面的挟持。
